# 금융전략 직원의 전문성 구축

## 이번 구현에 들어간 것

`financial_strategist`는 첫 네 직원 중 하나다. 초기 모델은 Codex 구독에서 사용할 수 있는
`gpt-6-astra`로 설정했다. 역할 설정은 [roles.json](../src/quant_company/roles.json)에 있으며,
서버의 `/var/lib/quant-company/config/roles.json`을 통해 버전별로 운영할 수 있다.

| 요소 | 첫 구현 | 현재 한계 |
|---|---|---|
| 직무 | 금융 개념·경제적 설명·반례·자료 요구 정리 | 직무 설명 자체는 전문성 증거가 아니다 |
| 도구 계약 | 계산·등록 지식 검색·공식 자료 후보 검색과 HTML 원문 읽기 | 일반 인터넷·뉴스 검색, 가격 단말·유료 자료·전체 데이터 레이크는 미연결 |
| 논의 | 국내 연구·데이터 직원에게 직접 위임 | 비활성 직무에 자동 위임하지 않는다 |
| 수치 규약 | 통화·기간·단위·명목금액·계산 가정 명시 | 실제 답안 품질은 별도 시험 필요 |
| 출처 규약 | 제공·조회된 source ID만 사용, 시점·범위 확인 | URL만 존재하면 검증됐다고 보지 않는다 |
| 개선 자료 | [9개 가상 개발 사례](../evals/financial-cases.json) | 공개 개발 사례이며 독립 시험 결과는 없음 |

분야는 거시·통화정책, 금리·채권, 주식·회계·가치평가, 파생상품, 포트폴리오 위험,
시장 미시구조, 가상자산 구조를 포괄한다. 분야별 실제 자료와 도구를 연결하고 새 사례에서
오류를 측정하며 전문성을 확장한다. 초기 모델이 모든 분야에 정확하다고 가정하지 않는다.

## 근거가 기억이 되는 과정

1. 공식 자료의 본문·제목·발행자·조회 시점과 지원하는 문장을 확인한다.
2. 제도·상품 규격·금리는 적용 시장과 효력 발생일을, 역사 연구 자료는 실제 이용 가능
   시점을 확인한다. 빠진 항목은 `unknown`으로 남긴다.
3. 출처가 직접 뒷받침하는 사실, 계산한 값, 해석, 가설을 분리해 기록한다.
4. 검토된 주장만 근거와 함께 공유 기억으로 승격한다. 동료가 반복한 말이나 BOT의
   자기평가만으로 승격하지 않는다. 출처 변경·정정·유효기간 종료 시 새 버전으로 연결한다.

현재 [공식 자료 목록](../evals/source-catalog.json)은 검색의 시작점이다. 목록을 만들면서
금융 지식을 대량 적재하거나 검증 완료로 등록하지 않았다. FRED·SEC·CME 등의 공식 본문과
개별 금융 주장은 실제 요청 범위에서 읽고 확인해야 한다.

실행 도구의 첫 [공식 문서 읽기 경로](official-sources.md)는 별도의 소규모 카탈로그를 사용한다.
후보 검색과 원문 확인을 구별하고, 원문을 읽었을 때만 출처 ID를 만든다. 발행 시각 미상은
조회 시각으로 대체하지 않으며, 미국 상품 설명과 국내 거래 제도의 적용 범위를 구별한다.

- [FRED 공식 API 자료](https://fred.stlouisfed.org/docs/api/fred/)
- [SEC EDGAR API 자료](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)
- [CME의 틱 단위 설명](https://www.cmegroup.com/education/courses/introduction-to-futures/tick-movements-understanding-how-they-work)

## 평가와 개선

[평가 절차](../evals/README.md)는 계산 정확도, 단위, 시점, 출처 지원 여부, 불확실성 표현을
각각 확인한다. 가상 사례의 정답 검사와 실제 모델 응답 평가는 별도 기록이다. 현 단계에는
실제 모델 시험 성적·금융 자격 판정·전략 성과 수치가 없다.

실제 업무에서 생긴 오류는 사례와 근거를 보존하고, 프롬프트·자료·도구 중 원인이 있는
부분을 수정한다. 수정한 버전을 별도 사례로 평가한 뒤 운영 버전을 바꾼다. 프로세스가
자동으로 자신의 권한이나 활성 직원 목록을 확대하지 않는다.
