# 외부 검색과 원문 분석

`web_search`는 ChatGPT 구독의 Codex 검색으로 후보를 찾고, `web_read`는 공개 HTTPS 원문을
읽어 프로젝트 출처로 저장한다. `knowledge_search`는 이미 저장된 출처만 검색하며,
`finance_search`는 별도의 선정 공식자료 목록만 검색한다.

활성 직원 4명에게 두 웹 도구를 연결했다. 최신 뉴스·변경 가능한 사실·명시적인 인터넷 조사에서는
검색 후보를 확인한 다음 관련 원문을 읽고, 원문 링크와 날짜를 포함해 사실과 해석을 구분한다.
검색이 실행됐다는 모델의 말만으로 성공 처리하지 않는다. 별도 검색 요청의 실제 native 검색
이벤트가 있어야 후보를 반환하며, 후보·스니펫은 출처 ID를 받지 않는다.

- `web_search({query, limit?})`: 후보 최대 8건. 턴의 도구 수 제한과 회사 구독 호출 예산을 적용한다.
- `web_read({url})`: 로그인 없는 공개 HTTPS HTML/text 원문을 읽는다. URL·수집 시각·제공된
  발행 메타데이터·SHA-256·원본 바이트를 보존하고, 프로젝트 출처 ID와 본문을 반환한다.
- `read_source({source_id, offset?})`: 본문이 길면 `next_offset`에서 계속 읽는다.

발행 메타데이터가 없으면 `published_at=null`이다. 본문에 적힌 발표일은 본문 근거로 설명할 수
있지만 HTTP 변경 시각·수집 시각을 발표 시각으로 바꾸지 않는다. 원문 수집은 해당 글의 모든
주장이 참이라는 인증이 아니다. 중요한 사실은 관련 1차 자료로 대조한다.

공개 IP만 허용하고 DNS 해석 결과에 직접 연결하면서 원래 호스트의 TLS 인증서를 검증한다.
리디렉션마다 같은 검사를 반복한다. 최대 1 MiB 원문, 최대 3회 리디렉션, 본문 수집 시간 제한을
적용한다. PDF·로그인·유료벽·자바스크립트로만 표시되는 본문은 현재 지원하지 않으며, 읽기
실패를 출처나 최신 사실로 대신하지 않는다. 추출 본문의 제한은 100,000자이며 생략 여부를 표시한다.

검색 호출과 원문 영수증은 재시작 후 재사용한다. 같은 턴의 중복 요청도 중복 예약하지 않는다.
중단·조건 변경이 들어오면 진행 중인 검색도 취소하고 이전 결과의 출처 등록과 게시를 막는다.
일반 직원의 모델 실행은 계속 도구 제안 방식이며 임의 shell·MCP·앱 권한을 얻지 않는다.

`COMPANY_WEB_ENABLED=false`로 서비스 웹 도구를 끌 수 있다. Compose의 공통 환경에 전달된다.
배포 시 새 런타임 이미지와 활성 역할 파일을 함께 반영해야 하며, 과거의 저장된 모델 요청 내용은
재시도 식별자 보존을 위해 고치지 않는다. 기존 `finance_search`·`finance_read`는 유지한다.

실제 구독·인터넷 검사는 별도 로컬 PostgreSQL에 다음 명령으로 실행할 수 있다. 구독을 소비하며
Slack 발송·배포·연구 실행은 하지 않는다. 결과와 원문은 출력 JSON 및 해당 실행의 DB 영수증으로
구분한다(DB는 검사 종료 후 제거되므로 출력 JSON이 인수 기록이다).

```bash
uv run --frozen python scripts/qualify_web_research.py --live
```

검증 범위와 운영 반영 여부는 [인수 기록](project/WEB-ENGINEERING-VALIDATION.md)을 따른다.
