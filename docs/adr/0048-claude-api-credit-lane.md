# 구독을 먼저 쓰되 정해 둔 작업과 장애 대비는 API 크레딧 레인으로 보낸다

## 배경

- 소유자 질문(2026-10-23):
  > "Anthropic 에서 20X max 구독자에게는 매월 $200 무료 API 크레딧을 주는 것으로 알고 있어서 이 무료 크레딧을 어떻게 잘
  > 활용 할 수 있을까 해서리,,,"
- 제안(평소엔 구독, 크레딧은 정해 둔 작은 작업과 장애 대비에 쓰고 월 $190에서 멈춤)에 대한 소유자 답: "응 나는 다 준비되었어."
  크레딧 받기, Console 조직 연결, API 키 만들기, Console 지출 한도 설정은 소유자 쪽에서 끝났다.
- 크레딧은 Console의 프로모션 크레딧으로 들어오고 결제 주기가 끝나면 사라진다. Claude Code 구독 로그인 사용에는 쓰이지 않는다.
  지금 방식(모든 호출이 `claude -p` 구독 로그인)이면 한 푼도 쓰이지 않는다.
- 최근 7일 공개 단가 환산은 약 $165(월 약 $640)다. 본편 대본·각색 검토·화면 검수가 대부분이다.
- 설계: [docs/superpowers/specs/2026-10-23-claude-api-credit-lane-design.md](../superpowers/specs/2026-10-23-claude-api-credit-lane-design.md)

## 결정

- **경로를 계약으로 가른다.** claude-runtime이 요청마다 고른다.
  - API 우선(소유자가 승인한 목록, 월 약 $100): `video_shorts_v1`, `newsletter_v1`, `video_performance_v1`, `video_weekly_v1`,
    `video_answer_v1`, `agent_decision`, `video_screen_fix_v1`. 아무것도 실행되지 않은 채 거절되면 구독으로 간다.
  - 구독 우선: 본편 대본·계획·각색 검토·화면 검수. CLI가 로그인 실패나 한도 거절로 아무것도 실행하지 않았을 때만 API가 대신한다.
  - 본편은 멈추지 않는다는 원칙에 맞춰 상한을 나눠 두지 않는다. 대신 대체가 시작되면 알려서 빨리 다시 로그인하게 한다.
- **조용한 유료 전환이 아니다.** AGENTS.md는 유료 API 자격으로 조용히 바꾸지 말라고 한다. 이번 전환은 소유자가 명시적으로 정했고,
  늘 드러난다. 상한, 켜고 끄는 스위치, 영수증의 `billing_mode`, 상태 파일, `ops status` 한 줄, 대체 시작 알림이 그 장치다.
- **유료 표면의 가드레일.**
  - 서비스 상한: 최근 31일 이동 창 합계가 `CLAUDE_API_CAP_USD`(운영 190)를 넘게 되는 예약은 거절한다. 기본값 0은 꺼짐이다.
    Console 지출 한도($200, 자동 충전 끔)가 마지막 방어선이다.
  - 킬 스위치: `CLAUDE_API_ENABLED=false`(기본값)면 모든 요청이 구독 경로로 간다.
  - 호출 전에 최악 비용을 예약하고 끝나면 정산한다. 모델이 단가표(출처 URL을 코드에 남김)에 없으면 API로 보내지 않는다.
  - 자동 재시도와 재실행이 없다. AGENTS.md대로 불확실한 유료 호출을 자동으로 다시 하지 않는다.
    - 200 뒤의 끊김·오류 이벤트·시간 초과는 `uncertain`이고, 529를 뺀 5xx(500·502·503·504 등)도 실행됐을 수 있어 예약액을 쓴 것으로 치며
      그 요청 ID는 다시 API로 가지 않는다. 구독이 불확실하게 끝난 요청도 API로 넘기지 않는다.
    - 호출하는 쪽이 새 ID로 다시 부를 수 있으므로 런타임이 제동을 건다. API 쪽 `uncertain`·`timeout`이면 30분 쉰다.
      소유자나 서비스가 일부러 한 취소는 쉬게 하지 않는다(다시 부르는 일이 아니고 31일 상한이 막는다).
    - 429는 `retry-after`(없으면 60초), 529와 연결 실패는 60초, 401·403은 재시작까지, 지출 한도 429는 다음 달 1일 00:00 UTC까지 쉰다.
    - 한 요청 ID는 한 번에 한 경로에서만 묻는다. 다른 경로가 실행 중이면 `pending`이다.
  - 키는 Docker secret `claude_api_key`로 claude-runtime에만 붙이고 요청 때 파일에서 읽어 헤더에만 쓴다. 환경변수로 두지 않으며
    CLI 환경 화이트리스트와 `FORBIDDEN_AUTH` 검사는 그대로다. 로그·Slack·영수증·오류 문구에 남기지 않는다.
  - 프롬프트 캐시는 쓰지 않는다. 캐시 읽기가 저장의 6%였고 저장 단가가 입력보다 25% 비싸다.
- **엄격 JSON 출력을 쓰지 않는다. `StructuredOutput` 도구로 받는다.** API의 `output_config.format`은 `minLength`/`maxLength`,
  숫자 범위, `minItems` 2 이상 같은 제약을 400으로 거절하고 `additionalProperties: false`를 요구한다. 우리 계약 스키마는 이런 제약을
  쓴다. CLI의 `--json-schema`도 `StructuredOutput`이라는 도구 하나로 결과를 받으므로(`parse_result`가 그 밖의 도구를 거부하는 이유)
  API도 같은 방식이다. `tool_choice`는 `auto`다(생각이 켜진 모델은 강제 선택을 받지 않는다). 결과는 계약 pydantic 모델로 검증하고,
  다른 도구·텍스트만 온 응답·`max_tokens`/`refusal` 종료·다른 모델은 `invalid_output`이다.
- **새 라이브러리와 렌더 이미지 변경이 없다.** `httpx`로 부르고 `contracts.py`·`pyproject.toml`은 그대로라 렌더 이미지를 다시 만들지 않는다.
- **메일은 API로 도는 동안 영상에 양보하지 않는다.** 취소하면 낸 돈을 버리고 같은 메일을 한 번 더 내게 된다. 런타임이 `kept`를 돌려주고
  메일은 양보 처리를 하지 않는다. 그사이 끝나 `completed`가 와도 양보하지 않고, 영상이 끝난 뒤 같은 ID로 저장된 결과를 받는다. 대체 글로 바뀐 메일의 취소는 API 요청도 끊는다.
- **보이기.** 상태 파일 `claude/jobs/.api/status.json`을 `deploy/ops_probe.py`가 읽어 `ops status`에 한 줄을 보이고, watch가
  #ops-alerts에 장부 읽기 실패, 키·지출 한도·uncertain 멈춤, 상한 80%, 구독 대체 시작을 알린다.

## 결과와 한계

- 켜는 순서: 소유자가 키 파일을 넣고(병합 전) → PR 병합과 자동 릴리스 → 운영 담당이 `runtime.env`에 `CLAUDE_API_ENABLED=true`,
  `CLAUDE_API_CAP_USD=190`을 넣고 claude-runtime을 다시 만든다. 그 전에는 레인이 꺼져 있어 동작이 지금과 같다.
- 시뮬레이션(`httpx.MockTransport`, 가짜 CLI) 테스트로 확인했다. 실제 API 호출은 켠 뒤 첫 영수증(`billing_mode: "api_credit"`, 비용, 모델)과
  Console 크레딧 감소로 따로 확인해야 하며, 그 전에는 배포·실호출 검증으로 적지 않는다.
- 429·5xx의 청구 여부는 공식 문서에 없다. 529(과부하)를 뺀 5xx는 모두 보수적으로 지출로 친다. 크레딧 잔액을 API로 읽는 방법은 확인하지 못했다.
  서비스 장부는 31일 이동 창이라 갱신일을 몰라도 한 주기에 상한을 넘지 않지만 Console의 실제 청구와 어긋날 수 있다.
- 구독 로그인이 길게 끊기면 본편 대체가 하루 약 $25씩 상한을 쓸 수 있다(위 결정).
