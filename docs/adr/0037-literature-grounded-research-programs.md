# ADR 0037 — Literature-grounded research programs

Status: implementation authorized by the user's “Implement the plan.” on 2026-09-28.
Production activation and a concrete scientific program remain review decisions.

## Authority and compatibility

An authenticated owner approves an immutable `ResearchProgram` with exact executable
envelopes and finite cumulative trial, compute and mission allowances. An envelope
freezes a `MissionSpec`: data hashes, development/sealed windows, code paths, evaluator,
objective, costs, risk and per-task search policy. Employees specialize the question,
title and evidence references. The program store reconstructs and revalidates this
derivation before execution. No model proposal grants approval.

Program child missions retain the owner's ingress event and an explicit program/task
record. Direct mission approvals remain unique; program approval can authorize multiple
children. Legacy version 1 mission serialization omits all new optional fields. Existing
P11 and ETF assignment identities, receipts, and in-flight jobs retain their contracts.

## Evidence and collaboration

Quant feed originals enter an owner/project-scoped library after independent critique,
independently of Slack delivery. Original pages, locations, retrieval evidence, document
version and editorial review remain immutable. Corrections/retractions mark old versions
for reconsideration; new tasks cannot cite them as current evidence. Historical research
is preserved. Every task source needs a quote found at its original location and complete
contiguous read receipts from the proposing employee's current provider attempt.

The researcher proposes a task; the data employee independently checks PIT, coverage,
execution and original reproduction conditions; the director accepts, revises or waits.
Exact reproduction and domestic transfer have different labels. The resulting mission
uses existing proposal/challenge/build/qualify/execute/interpret/audit stages. Every
challenge must receive a director disposition. Tests remain obligations for an independent
meaning review, with actual audited artifact paths or an explicit unresolved finding.

Causal validity is checked with existing pinned qlab artifacts first. A separate
financial strategist context then reviews selection effects, costs and alternative
explanations. Inconclusive and negative findings are publishable; missing causal validity
is not. No return or research interpretation enters ordinary conversation before these
gates. Reported predecessors become sources for the next task. `incumbent_trial_id` is
the best *measured feasible* development candidate, not a confirmation or adoption verdict.

## Execution and evaluation

All inference uses existing employee turns. PostgreSQL holds records and resource
reservations; the existing Temporal research tick schedules durable stages. Worker time
is reserved before queueing, atomically with the job. Verified outcomes settle the ledger;
technical failures consume elapsed time but not a scientific trial. Uncertain jobs keep
their reservation. Actual elapsed time includes execution overhead and can exceed the
reserved sandbox time; no new job starts after the resulting allowance is exhausted.

Version 2 uses the `kr-research-python-v2` transport with separately pinned ETF/equity
profiles. The protected worker reference adapter uses frozen daily snapshots, prior-session
information, adjusted open price returns, an explicit long-only unlevered cost model and
strict handling of missing/blocked execution. It refuses missing delisting settlement
and trading halt paths, rather than estimating them. This limits executable datasets:
the data assessment must establish applicability before a scientific run.

The first scientific evaluator measures cross-sectional predictive correlation and
aggregates dated observations into calendar-month means. A frozen 95% normal interval
with at least 30 months supports descriptive claim/reproduction checks. Reproduction
requires a predeclared target and tolerance. It is neither a general statistical test
registry nor multiplicity-adjusted confirmation. Other estimands require another protected
evaluator and program approval. The strategy evaluator retains cost-adjusted CAGR and
risk constraints. Raw artifact values are independently recomputed by the consumer.

Candidate code lives in approved quant-lab paths and may implement features, models or
portfolios with the provisioned offline runtime. Evaluator code, inputs, runtime, credentials
and network are inaccessible for modification. The service never trains or backtests.

## Acceptance

Use actual disposable PostgreSQL and Temporal, real Git bundle preparation, actual pinned
qlab verification and clearly labelled synthetic worker artifacts. Require tests for
approval provenance, original reads, unresolved objections, failed data prerequisites,
atomic budgets, restart/replay, code/input/metric tampering and legacy digests. A staged
3070 sandbox qualification precedes production activation; an approved scientific program
then requires actual ETF and stock trials and authenticated Slack/report receipts.
