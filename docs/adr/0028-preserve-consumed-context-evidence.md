# ADR-0028: 긴 대화에서도 읽은 출처의 인용 정보를 보존한다

- 날짜: 2026-09-18
- 상태: 구현·로컬 검증, 운영 반영 전

## 문제

P10 보고에서 총괄은 같은 출처를 네 번 조회한 후 다섯 번째 턴에 보고를 마쳤다.
실제 두 번째 요청에는 성공한 `read_source` 영수증이 있었지만 그 출처의 ID가
`approved_sources`에서 빠져 있었다. 시스템 상태 약 53,674자와 최근 메시지가
68,000자 예산을 채우자 최신순 출처 목록의 첫 항목을 삭제한 것이 원인이다.
모델은 승인 출처 목록에서만 ID를 복사하라는 지시와 충돌한다고 판단했다.

## 결정

- 서비스가 저장한 실제 `read_source` 영수증의 출처를 목록 조회에서 우선한다.
  최신 50개 밖으로 밀린 출처도 최근 대화의 영수증에 있으면 조회 대상에 포함한다.
- 해당 출처가 현재도 승인·가용·동일 프로젝트 또는 공용인지 DB 조건으로 다시 확인한다.
  과거 영수증이나 사용자 발언만으로 승인·권한을 복원하지 않는다.
- 컨텍스트 안의 읽은 출처, 현재 시스템 출처, 지시에 명시한 출처의 ID를 보존한다.
  최신순 출처·메모리·산출물은 오래된 항목부터 줄인다. 메시지는 기존 시간순을 유지한다.
- 그래도 예산이 부족하면 전체 시스템 정보를 먼저 조회 가능한 출처 참조와
  저장소 상태·실행 코드의 요약으로 표시한다. 그래도 부족할 때만 긴 메시지를 발췌한다.
  여러 페이지를 방금 읽은 영수증이 배경 정보 때문에 먼저 잘리지 않도록 한다.
  생략을 부재로 해석하지 않는다.
  필수 정보까지 예산을 초과하면 명시적 오류로 종료한다.

DB의 원문, 이전에 동결한 요청, 응답, 영수증은 바꾸지 않는다. 새 요청을 구성할 때만
적용하며 별도 큐·에이전트·실행 횟수 제한·자동 배포 경로는 추가하지 않는다.

## 검증과 한계

실제 임시 PostgreSQL에서 성공한 출처 조회→큰 컨텍스트→인용된 최종 산출물 저장을
검사했다. 최신 출처와 최신 50개 밖의 출처를 모두 다루며 승인 취소·미래 시점·다른
프로젝트로 이동한 출처는 제외한다. 큰 시스템 원문도 DB에는 전체 내용이 보존된다.
기존 구현에서는 출처 누락과 90,000자 모델 요청 초과가 각각 재현됐다.
두 페이지를 읽는 경우의 영수증 본문 잘림도 재현하고 시스템 요약을 먼저 하도록 수정했다.

모델 출력·큰 시스템 상태는 테스트 fixture다. 운영 P10 보고의 실제 완료 영수증은
결함이 있던 `e869eb5`에서 나온 증거이며, 수정 배포나 개선된 모델 행동의 증거로 쓰지 않는다.
운영 반영에는 기존 사용자 정책에 따른 검토가 필요하다.
