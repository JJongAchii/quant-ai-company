# Claude API 크레딧이 있으면 API를 먼저 쓰고, 한도는 크레딧 잔액이다

## 배경

- ADR 0048은 API 우선 작업(Shorts·메일·성과 분석·화면 수정 등)의 한도를 서비스 쪽 상한으로 두었다. 최근 31일 이동 창
  합계가 $190(`CLAUDE_API_CAP_USD`)를 넘는 예약은 거절한다.
- 2026-11-18 15:56 31일 사용액이 $188.77에 닿았다. 그 뒤 11-23까지 API는 한 번도 쓰이지 않았다. 모든 작업이 구독으로 돌았고,
  구독 한도 거절은 11-20 10:08 뉴스 선별 1건이었다.
- 크레딧은 프로모션으로 매달 $200씩 들어온다. 11-23에는 이미 다시 들어와 있었다. 그런데 이동 창에서는 오래된 지출이 빠져야
  자리가 생긴다. 11-26에 $4.65, 11-29에 $27.23, 12-01에 $48.25였다. 그래서 받은 크레딧을 주기 안에 다 쓰지 못한다.
- 소유자(2026-11-23):
  > "다시 api 크레딧이 충전되어서 있는상태인데, 이거 프로모션으로 매달 200$ 씩 충전해줄텐데 다시 충전되면 다시 api 부터
  > 사용되도록 할 수있나? api 크레딧 확인하면서 있을 경우 그걸 우선적으로 쓰도록"

  세 안(잔액에 맡김 / 충전일마다 상한 초기화 / 둘 다) 가운데 "잔액에 맡김"을 골랐다.
- 일반 API 키로는 잔액을 읽을 수 없다. 사용·비용 보고(`/v1/organizations/usage_report/messages`, `cost_report`)는 Admin
  자격이 필요하고, 잔액 항목도 없다. 잔액이 없을 때 Messages API는 실행 전에 거절한다. 문서상 402 `billing_error`이거나,
  메시지가 "Your credit balance is too low to access the Anthropic API"인 400 `invalid_request_error`이다. 거절이라 돈은
  나가지 않는다.

## 결정

- **서비스 상한을 없앤다.** `Budget.reserve`는 장부를 읽을 수 있으면 언제나 예약한다. `CLAUDE_API_CAP_USD`는 읽지 않고
  compose에서도 뺐다. 레인을 켜고 끄는 것은 `CLAUDE_API_ENABLED`뿐이다. 장부는 그대로 두고 31일 사용액 표시와 정산에 쓴다.
- **잔액 부족은 1시간 쉰다.** 402이거나 메시지에 "credit balance"가 있는 400이면 `ApiNotExecuted("credit")`이다. 레인은
  `credit` 쉼으로 1시간(`CREDIT_RECHECK`) 멈추고, 그 작업은 지금처럼 구독으로 간다.
  - 쉼은 장부에 남아 다시 시작해도 지켜진다. 1시간 뒤 다음 API 우선 작업이 다시 묻고, 크레딧이 들어와 있으면 그대로 API로 돈다.
  - 오류 본문에서는 이 예/아니오만 읽고 메시지 자체는 어디에도 남기지 않는다. 읽을 수 없거나 JSON이 아닌 본문(너무 깊은
    중첩 포함)은 상태 코드만으로 판단한다.
  - 다른 400은 지금처럼 `rejected`다(쉬지 않고 구독으로).
  - 쉼 순서에서 `credit`은 `uncertain` 뒤다. 두 호출이 동시에 하나는 잔액 부족, 하나는 불확실로 끝나면 경보가 필요한 불확실 쪽이 보인다.
- **마지막 방어선은 Console이다.** 지출 한도 $200·자동 충전 꺼짐은 ADR 0048에서 소유자가 맞춰 두었다. 자동 충전이 꺼져 있으면
  크레딧이 떨어진 뒤의 요청은 위 거절로 끝난다. 지출 한도의 429는 지금처럼 다음 달 1일 00:00 UTC까지 쉰다.
- **알림.** 상한 80% 경보(`claude_api:cap80`)를 없앴다. 크레딧 없음은 #ops-alerts에 올리지 않는다. 달마다 있는 일이고, 그동안
  구독으로 돌며, 1시간마다 쉼이 풀렸다 다시 걸려 경보가 깜빡이기 때문이다. `ops status` 줄로 보인다:
  `🤖 Claude API: 31일 사용 $X · 쉼(크레딧 없음 · 1시간마다 다시 확인)`. 최근 거절 이유로는 `크레딧 부족`이다.
- 본편이 구독을 먼저 쓰는 규칙과 API 우선 목록은 그대로다. 본편은 구독 로그인·한도 실패 때만 API로 간다.

## 결과와 한계

- 운영 `runtime.env`에는 `CLAUDE_API_ENABLED=true`가 이미 있다. 바꿀 값이 없어 자동 릴리스로 나간다. 남아 있는
  `CLAUDE_API_CAP_USD=190`은 컨테이너로 넘어가지 않으며, 지울지는 운영자가 정한다.
- 배포 뒤 첫 API 우선 작업부터 API로 간다. 11-23의 크레딧으로 받는지는 그 영수증(`billing_mode: "api_credit"`)과
  Console 크레딧 감소로 확인한다.
- 장부의 31일 합계가 $190을 넘을 수 있다. 크레딧이 주기마다 들어오므로 그것만으로는 문제가 아니다. 실제 청구는 Console이 기준이다.
- 상한이 없어 Console 월 지출 한도 $200(달력 월)에 닿을 수 있다. 크레딧 주기와 달력 월이 어긋나면 크레딧이 남아 있어도 그 달
  말에 지출 한도 429가 올 수 있다. 그러면 지금처럼 다음 달 1일 00:00 UTC까지 쉬고 #ops-alerts에 critical(`Console 지출 한도`)로
  알린다. 실제 잔액 소진이 400·402가 아니라 이 429로 오는지는 첫 실제 거절 영수증의 `reason`으로 확인한다.
- 배포 직후 열려 있던 `claude_api:cap80` 경보(31일 $188.77)가 사라지며 #ops-alerts에 '해소' 글이 한 번 올라간다.
- 잔액 부족 거절의 메시지 문구는 Anthropic이 바꿀 수 있다. 문구가 달라져도 그 400은 `rejected`로 구독에 간다. 이때는 쉬지
  않고 작업마다 한 번씩 API에 물어볼 뿐이고 돈은 나가지 않는다. 402는 문구와 상관없이 잡는다.
- 시험은 시뮬레이션(`httpx.MockTransport`, 가짜 CLI)이다. 실제 잔액 부족 응답은 이번 달 크레딧이 떨어질 때 영수증의
  `reason: "credit"`으로 처음 확인한다.
