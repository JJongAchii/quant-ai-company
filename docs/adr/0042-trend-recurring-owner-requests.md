# 정기 세 슬롯과 소유자 요청 검색 트렌드

2026-10-07 사용자는 정기 발송을 한국 시간 08:00·14:00·20:00로 선택하고,
Slack에서 실시간 검색어를 요청하면 그때도 발송되도록 요구했다.

정기 입력은 각 슬롯 30분 전에 동결하고 슬롯별 독립 ID로 확정한다. 기존 08시 ID와
이미 전달한 본문은 유지한다. 여러 슬롯에서는 최신 성공 RSS 한 건의 후보를 사용한다.
검증된 비스포츠 검색 급상승을 우선하며 기존 승인 주요 이슈로 회당 10개를 목표로 보충한다.
전체 플랫폼 실시간 검색량 또는 전체 검색 순위로 표시하지 않는다.

전용 채널의 소유자가 정확한 `실시간 검색어`·`검색 트렌드` 명령이나 Trend Scout 멘션을
보내면 결정론적 수신기가 DB 요청을 커밋한다. 같은 메시지의 일반 이벤트·멘션·재전달은
같은 ID다. 새 요청은 RSS 수집을 당기고, 편집이 확인되면 원 메시지 스레드로 응답한다.
검증된 최근 10분 편집은 자료 수집 시각을 보존해 재사용한다.

기존 서버의 Slack SDK 인증 Socket Mode 연결을 사용한다. 공개 HTTP 수신기의
HMAC·timestamp 검증은 유지한다. 두 경로는 동일 workspace/app/owner/channel과 봇
제외 정책을 적용한다. Trend Scout는 비활성 직원·빈 모델/도구/위임 권한을 유지하며,
명령을 모델에 해석시키거나 일반 회사 프로젝트로 전달하지 않는다.

KST 하루 모델 요청 12개 중 정기 세 슬롯의 최대 두 번 편집에 필요한 6개를 확보한다.
수시 요청은 나머지 최대 6개이며 회사 공통 호출 예산도 적용한다. NAVER HTTP 요청은
하루 100회 이내다. 날짜·키워드·시간 단위가 같은 추이 원 응답은 정규화 지수를
조합하지 않고 통째로 재사용하며 원 응답을 가리키는 영수증을 남긴다.

기존 Temporal 아침 publisher 코드를 변경해 역사 재생을 깨뜨리지 않는다. 새
`company-trend-feed-publication-v2`가 정기·요청 DB 상태를 검사한다. 기존 수집/편집
workflow 기록과 불명 모델·Slack 효과 영수증은 유지하며 자동 대체 호출·재발송하지 않는다.

설치 기본값은 기존 08시·요청 비활성·하루 모델 2개다. 운영 설정, 사용법과 검증 경계는
[운영 설명](../trend-feed.md)에 기록한다. 실제 배포는 현재 부모 이미지의 변경 대상만
덧붙이고 다른 운영 기능·환경·컨테이너를 보존한 영수증으로 확인한다.
