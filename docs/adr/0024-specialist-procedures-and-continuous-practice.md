# ADR-0024: 직원별 절차·수치 도구·영속적인 직무 평가와 개선

상태: 구현. 사용자 승인: 2026-09-17 대화의 “그래 진행해줘. 진짜 전문적이게 … 주기적으로 직원들이
새로운문제들을 풀거나 평가하면서 발전되도록 … 제대로 진행해줘”. 운영/실제 모델 인수는 별도 증거에 기록한다.

## 문제

직무 프롬프트와 도구 권한은 있었지만 호스트의 Quant 스킬은 격리 실행기에 전달되지 않았다.
금융 시험 fixture는 모델을 호출하지 않았고, 업무 실패를 직원의 다음 업무와 연결한 학습 이력이 없었다.
직원의 답변 수·CI 통과·역할명으로 전문가 수준이라고 주장할 수 없다.

## 결정

1. 기존 직무 10개와 별도 개선 담당에 전용 절차 11개를 패키징한다. 해당 직원의 절차만 요청에 넣고
   본문 SHA-256을 runtime context에 명시한다. 호스트 스킬·shell·MCP·네이티브 메모리는 계속 격리한다.
   이 절차는 기존 연구 규약의 필요한 원칙을 옮긴 것이며 연구 워커/감사 실행을 자동 연결하지 않는다.
2. 제한된 금융 도구(채권 가격/듀레이션/볼록성/충격, 유럽형 옵션/Greeks, FX 환산, 선형 시나리오)와
   제공 행의 데이터 품질 검사를 typed tool로 연결한다. 단위·가정·버전·입력 digest를 반환한다.
   공개 원문 참고 문헌은 절차에 명시하되 원문을 방금 읽었다고 인증하지 않는다.
3. 기존 PostgreSQL과 Temporal worker에서 별도 직원 교육 루프를 운영한다. 새 서버/유료 API는 필요 없다.
   하루 2개 과제, 과제당 최대 3개 요청을 기본으로 한다. KST 03시 이후 여유 시간에 실행한다.
   일반 업무가 있으면 다음 교육 호출을 연기한다. 이미 실행 중인 호출은 선점하지 않아 최대 모델 timeout만큼
   사용자 업무가 기다릴 수 있다. 이는 회사 공통 업무의 일일 한도를 복구하는 변경이 아니다.
4. 11개 직무 × 2개 유형에서 새 seed·수치·순서·사례 ID로 문제를 만든다. 문제/정답/루브릭을 호출 전
   고정하고 키는 제공자에게 보내지 않는다. 기존 configured model/role/pack snapshot과 실제 요청·응답·
   usage를 저장한다. 코드가 객관적 수치, 오류 누락, 정상 사례 오탐을 채점한다. 서술 품질은 자동 인증하지 않는다.
5. 실패한 조건을 출처가 있는 연습 피드백으로 해당 직원의 다음 업무에 전달하고 기존 개선 담당 관찰에 넣는다.
   공개된 실패는 연습 자료가 되며 다시 미지 평가라고 세지 않는다. 같은 유형의 이후 통과가 있으면 이전
   피드백은 현재 주의 목록에서 빠지되 기록은 보존한다. 한 번의 후속 통과로 일반화된 개선을 보증하지 않는다.
6. 개선 담당은 실제 코드·절차 수정, 검증, PR을 제안한다. 채점기·문제 생성·예약·권한은 수정하지 못한다.
   절차 변경은 기존 prompt_replay의 실패/정상 생산 업무 쌍을 사용할 수 있다. 합성 시험은 생산 turn 증거를
   대신하지 않는다. 근거가 부족하면 추가 증거/명확한 검토 항목을 남긴다. 운영 반영은 기존 사람 검토 정책을 따른다.
7. operator는 문제가 잘못됐다고 판단한 평가에 disputed와 사유를 남길 수 있다. 기존 답·점수는 수정하지 않고,
   disputed 평가는 직원 피드백과 신규 개선 접수에서 제외한다. 이미 접수된 PR은 사람이 해당 이의를 함께 검토한다.
8. Slack 총괄의 staff_status와 operator API/CLI로 실제 일정·기록·직원별 적용 버전을 조회한다.
   평가 과제는 업무 프로젝트/Slack/outbox/공유 금융 기억을 생성하지 않는다.

## 전문성의 의미와 남은 범위

새 수치가 들어간 알려진 문제 유형은 미지 분야 평가가 아니다. 이 첫 문제은행은 기초/중간 수준의
객관적 직무 오류를 탐지한다. 거시 인과 추론, 회계 심층 분석, 체결 시뮬레이션, 독창적 전략,
장기 실제 성과, 전문가 대비 우월성을 인증하지 않는다. 회사 고유 파인튜닝도 수행하지 않는다.

개선은 절차·도구·검색 가능한 검토 기억·실패 피드백의 변경을 뜻한다. 정기 문제 풀이만으로 모델 가중치가
학습되거나 역량이 반드시 상승하지 않는다. 모델·pack·유형별 이력과 새 문제에서의 성과로 확인한다.
다음 확대는 실제 연구 실패 사례와 전문가가 작성한 봉인 문제를 별도 검토해 추가하는 것이다.

일반 금융 지식의 후보 기억 제안→사람 검토→공유 경로는 기존 memories를 사용한다. 합성 정답이나
검증되지 않은 인터넷 주장을 자동으로 사실 기억에 넣지 않는다. 역할 활성화·연구 실행·거래 권한도 바꾸지 않는다.

## 검증

독립 수치 참조/유한차분/put-call parity, 잘못된 단위·비유한 값·시간대·결측/중복·빈 입력 검사;
PostgreSQL의 재시작/요청 재사용/동시 예약/예산/권한/피드백 격리/판정 이의;
Temporal의 중단 뒤 재시도 및 history replay; 실제 구독 모델은 별도 opt-in 인수.
