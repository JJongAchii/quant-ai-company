# ADR-0019: 자연어 업무 제어와 후속 입력 대기

2026-09-17 · Accepted for implementation. 사용자 승인: 앞서 제시한 3개 PR 계획에 대한
“그럼 다음 진행해줘”. 별도 유료 서비스·연구 실행·자동 운영 승격의 승인은 포함하지 않는다.

## 결정

- 같은 Slack 스레드의 총괄 후속 입력은 영속 `routing` 업무가 된다. 첫 요청과 명시적인
  `수정:` 경로는 유지한다. 라우팅은 기존 구독·직렬 실행·사용량 기록을 사용한다.
- 명확한 중단·재개·상태 명령은 모델을 부르지 않는다. 질문·인용·부정문을 명령으로 추측하지 않는다.
- 라우팅 모델은 대화의 의미만 `task_control` 제안으로 낸다. 서버가 현재 소유자·스레드·지시
  버전·입력 순서를 검사하고 실행한다. 일반 직원·문서·동료 메시지는 이 권한을 갖지 않는다.
- 뜻이 결정될 때까지 같은 프로젝트의 이전 모델 결과 반영과 아직 발신하지 않은 답변을 보류한다.
  읽기 질문은 기존 업무를 보존하고, 변경은 기존 요구사항에 최신 지시를 덧붙여 새 버전으로 실행한다.
  중단은 해당 스레드의 기존 실행을 무효화한다. 다른 스레드는 영향을 받지 않는다.
- 모호한 대상은 질문하고 업무를 대기시킨다. 중단·확인 대기 상태에서도 후속 질문과 상태 조회가 가능하다.
- 빠르게 연속된 후속 입력은 접수 순서로 판별한다. 아직 요청이 예약되지 않은 다음 라우팅만 새
  버전을 따라가며, 이미 예약한 모델 입력·응답은 덮어쓰지 않는다.
- Slack이 이미 접수한 발신은 되돌릴 수 없다. 발신 결과가 불명확하면 기존 uncertain 정책을 유지한다.

## 검증

실제 PostgreSQL에서 중복 입력, 연속 변경, 실행 중 변경, 읽기 질문, 중단·재개, 모호한 대상,
구독 대기 중 즉시 제어, 재시작, 다른 스레드 격리, 오래된 모델 응답·outbox 차단을 검사한다.
기본 CI와 실제 구독·Slack 인수는 별도 기록한다.
