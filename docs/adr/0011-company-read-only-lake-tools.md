# ADR-0011: 기존 S3 레이크의 제한된 조회 연결

- 날짜: 2026-09-16
- 상태: 사용자 승인된 데이터 연결 구현
- 승인: `docs/work/quant-ai-company/DATA-CONNECTION-APPROVAL.json`

## 경로와 권한

EC2가 발행하는 기존 `s3://insight-invest-datalake/qdata/clean/`을 회사 서비스가 소비한다.
원본 수집·발행·raw·다른 앱 산출물은 변경하지 않는다. 전용 IAM 사용자는 이 prefix의
목록·GetObject와 버킷 지역 조회만 가진다. 자격 증명은 worker에만 마운트하며 모델 컨테이너에
전달하지 않는다. 운영자가 설정한 루트는 모델이 바꿀 수 없다.

## 데이터 API와 실행 제한

소비자는 `qdata.api`만 사용한다. 기존 `coverage()`는 10개 테이블을 전수 읽으므로
38개·12.8GiB인 미러의 대화형 조회에는 쓰지 않는다. qdata의 신규 읽기 전용 API를 통해
`lake_catalog`, `lake_describe`, `lake_sample`을 데이터 직원에게 제공한다.

일반 코드·SQL 실행은 허용하지 않는다. 요청당 한 도구, 서비스 프로세스당 한 조회,
별도 단기 프로세스와 18초 제한을 둔다. 하위 프로세스에 DB·Slack·Temporal·모델 비밀을
상속하지 않는다. qdata는 footer 2MiB·읽기 8MiB·표본 20행/8열·선택 row group 비압축 8MiB를 제한한다.
실패·통계 미존재를 전체 데이터 읽기로 우회하지 않는다. 2GB 서버에서 실제 메모리를 검증한다.

## 증거와 재현

파일 수정일, 데이터 날짜 범위, 조회 시각, 객체 ETag·VersionId를 구별한다. 조회 중 객체가
바뀌면 결과를 채택하지 않는다. 전역 날짜 범위는 종목별 연속성·공시 가용성을 뜻하지 않는다.
표본은 첫 물리 행이며 최신 날짜나 대표 표본이 아니다.

성공한 실제 조회만 프로젝트 범위의 출처 레코드로 저장하고 source ID를 반환한다. 승인된
읽기 경로의 관측 기록이라는 뜻이며 전략 성과나 투자 주장의 검증을 뜻하지 않는다.
실패는 도구 영수증에 남기고 출처를 만들지 않는다. qdata 소스는 별도 커밋·archive digest로
고정해 Docker additional build context로 공급한다. 운영 이미지와 조회 영수증에 qdata 커밋을 기록한다.

## Slack 실사용에서 확인한 출처 ID 복사 오류

실제 사용자 요청에서 데이터 직원이 64자리 hash ID 일부를 누락해 산출물 검증이 중단됐다.
총괄은 원본 영수증으로 답변했지만, 담당자의 완료까지 검증한 것은 아니므로 첫 시도는 별도 보존한다.
신규 출처는 프로젝트와 영수증에서 계산한 hash의 24자리 접두어를 ID로 사용한다. 전체 영수증과
객체 식별자는 그대로 보존하고, ID 충돌 시 내용·프로젝트·승인 상태를 확인해 다르면 중단한다.
기존 ID를 재작성하거나 잘린 ID를 근사 매칭하지 않는다. 역할 지시에는 ID의 정확한 복사를 명시한다.
이는 복사 오류 가능성을 줄이는 변경이며, 앞으로의 모든 모델 응답 성공을 보장하지 않는다.
