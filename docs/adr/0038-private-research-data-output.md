# ADR 0038: Private research data output

## Context

The actual conditional program `c3ba5268d71c87bd2c6226160bc720498137bd291396a054970a1f1e7ebcf2db`
received its own owner approval and produced a source-backed task. The data employee's first four
attempts ended with `invalid_output (decision_contract:invalid_shape)`. These receipts establish
an outer proposal format failure; they do not identify the rejected field or establish a data finding.
A serialization example in the fourth attempt did not resolve the failure. The stage was held
with its requests, receipts, program authority and cumulative budget preserved.

## Decision

New `program_data` turns use `research_stage_v1`, a native structured response containing `action`,
`read_path`, `read_offset` and `artifact_json`. The runtime constructs the existing `AgentDecision`
for one scoped read or one private artifact. Completion requires a serialized JSON object.
Extra fields, native execution, mixed actions and malformed completion remain rejected.

The company still checks contiguous file coverage, approved source IDs, independent `DataAssessment`,
canonical scope and packet identities. The frozen evaluator and packet identity remain in the
data employee's prompt after long report reads. Three provider or data artifact format failures
hold the stage without a retry timer. Failure counts survive technical attempts; scientific budgets
and findings are not reset.

Existing frozen requests and receipts retain their original output contract and input digest.
The research proposal, owner approval, task selection and audit output contracts remain unchanged.

## Activation

This changes the request contract between the company, account gateway and primary Codex runtime.
All request validators must support the candidate before a new data turn is dispatched. Qualify
the exact source, actual imported code, compatible 3070 release and current authority first.
Then explicitly reconcile the held stage and let the employee make its own decision.
Passing simulated provider tests does not establish a successful deployed employee review.
