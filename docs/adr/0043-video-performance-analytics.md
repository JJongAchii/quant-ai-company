# 영상 성과 분석과 소유자가 채택한 교훈

2026-10-13 소유자는 Studio에서 보기만 하던 노출·클릭률·유입 검색어·시청 지속 같은 지표를 분석해, 잘된 이유와
안 된 이유를 알고 다음 영상 제작에 반영하기를 요청했다. 소유자는 네 가지를 골랐다.
- 분석 결과 중 승인한 교훈만 제작에 반영한다.
- 지표는 API로 자동 수집한다.
- 업로드 3일 뒤 영상별 카드와 월요일 심층 리뷰를 받는다.
- 별도 성과 Slack 채널을 쓴다.

영상은 소유자가 직접 올리므로 서버는 공개 업로드 목록을 읽고 연결한다. 제목 끝
`| M월 D일 아침|마감 · 오늘의 증시story`로 회차를 찾고, 없으면 제작 제목이 정확히 같은 작업에 연결하며, 운영자가
`video-analytics link`로 직접 연결할 수도 있다. 이 연결은 `video_publications`에 둔다. API 업로드 상태기계의
영수증인 `video_jobs.youtube_id`와는 섞지 않는다.

썸네일 노출수와 CTR은 Analytics API에 없다. YouTube Reporting API의 `channel_reach_basic_a1`과
`channel_reach_combined_a1`(유입 경로별)에만 있다. 작업(job)은 보고서 종류마다 한 번 만들고 영수증을 남긴다.
이 기능의 유일한 외부 쓰기다. 일 단위 보고서는 영수증과 함께 반영한다. 같은 종류와 날짜에 더 새 보고서가 오면
그날 값을 교체하고, 더하지 않는다. 문서는 CTR을 클릭/노출이라고만 하고 단위를 밝히지 않는다. 그래서 1보다
큰 값이 있는 보고서는 백분율로 읽고, 첫 실연결에서 Studio 값과 대조한다. 조회, 시청 시간, 이탈 곡선, 유입
경로, 검색어는 Analytics API로 읽는다. 날짜는 모두 태평양 시간이다.

영상마다 고정 구간 D+3, D+7, D+28을 측정한다. 그래야 영상끼리 같은 일수로 비교된다. 일별 뉴스 영상은 그날
이슈 크기에 크게 좌우되므로 같은 회차 종류의 직전 28일 중앙값과 비교하고, 5편 미만이면 "기준 부족"이라고
쓴다. 분석은 가설, 근거 수치, 확신도로만 낸다. 이탈 곡선은 렌더 manifest의 장면 시각(`scenes`, 이전 회차는
챕터)에 겹쳐 가장 가파른 장면을 찾는다.

진단은 기존 Claude 구독 실행기의 새 계약 두 개로 한다. `video_performance_v1`은 영상별이고 썸네일을 첨부하며
`VIDEO_REASONING_EFFORT`를 쓴다. `video_weekly_v1`은 주간이고 `VIDEO_REVIEW_EFFORT`를 쓴다. 요청 ID는 고정이고,
회사 일일 호출 한도에 들어가며, busy와 quota는 환불 후 같은 ID로 다시 요청한다. 실행 lane을 영상 제작과
나누므로, 제작 중인 회차가 있으면 분석을 요청하지 않는다. 분석이 실패해도 카드는 수치만으로 나간다.

주간 리뷰는 교훈을 최대 세 개 제안한다. 범위는 제목, 썸네일, 오프닝, 구성, 길이, 키워드로 한정하며 원문
줄, 숫자, 표기 규칙, 소유자 제목 규칙은 교훈 대상이 아니다. 교훈은 성과 채널의 버튼으로 브리핑 소유자만
채택, 거절, 은퇴시킬 수 있고, 활성 교훈은 최대 `VIDEO_ANALYTICS_MAX_LESSONS`(기본 8)개다. 채택된 교훈은 새
영상 작업을 만들 때 `policy.lessons`로 고정된다. 이미 만든 작업의 요청은 바뀌지 않는다. 대본 작성
프롬프트에서는 교훈을 데이터로 넣고 고정 규칙이 우선한다고 명시한다. 검토 프롬프트에는 넣지 않는다. 주간
리뷰는 교훈 적용 전후 회차를 같은 회차 종류끼리 비교해 유지, 은퇴, 판단 이르음을 낸다.

수집은 video worker 프로세스에서 별도 Temporal 큐(`-video-analytics`, 30분 간격)로 돌아간다. 이 프로세스에만
YouTube 토큰이 있고, 긴 렌더링이 수집을 막지 않는다. 기본값은 꺼짐(`VIDEO_ANALYTICS_ENABLED=false`)이다. 운영
절차와 검증 경계는 [영상 운영 설명](../daily-video.md#성과-분석)에 기록한다.
