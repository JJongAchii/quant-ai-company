# ADR-0016: Slack 승인 후 개선 PR 적용

상태: 구현. 사용자 지시: “응 완성해줘” (2026-09-17). 기존 “수정·테스트·PR 자동,
운영 반영은 검토 후” 정책의 승인 이후 실행 경로를 연결한다. 자동 승인은 추가하지 않는다.

## 동작

전용 워크스페이스의 허용 사용자이자 해당 프로젝트 소유자가, 개선 PR 알림을 받은 스레드에
`반영해`, `반영해줘`, `적용해줘`, `승인` 또는 `PR #3 반영해`라고 적으면 Slack ingress가
모델 호출 전에 처리한다. 부정문·질문·인용은 승인으로 해석하지 않는다. 대상이 여러 개면
PR 번호를 요청한다. 원문·Slack event key·사용자·프로젝트·PR case·head를 DB에 함께 남긴다.
별도 승인 접두어나 GitHub 로그인이 필요하지 않다. 알림이 전송되지 않은 PR, 다른 스레드,
다른 소유자, BOT 메시지는 승인할 수 없다.
Slack 승인 시각보다 늦게 게시된 PR 알림은 후보에서 제외한다. 지연 수신·과거 승인 복구가
사용자가 승인할 때 보지 못한 새 PR을 선택해서는 안 된다.

maintenance tick은 승인 처리를 우선한다. PR head·파일 내용·허용 범위·CI·현재 base를 재확인한다.
코드 base가 바뀌면 재검사가 필요하다. 문서 변경은 원래 수정 대상 파일이 그대로일 때만 다른
운영 커밋 위에 병합할 수 있다. draft를 ready로 바꾸고 정확한 head로 병합한다.
병합 intent를 먼저 저장하며 응답 유실/재시작 시 조회로 대사한다. 불확실한 병합을 반복하지 않는다.
GitHub의 병합과 DB는 분산 트랜잭션이 아니며, base 이동 경쟁은 병합 부모 확인으로 탐지해 배포를 막는다.

문서·설계 PR은 병합 후 완료한다. 실행 코드·역할 지침 변경은 `deploy_pending`으로 넘긴다.
host의 systemd timer(60초)가 DB의 승인된 release만 가져온다. 설치된 release의 고정 실행기로
GitHub merge commit archive를 받아 보호 파일·경로·역할 권한 불변을 다시 검사한다. 후보 코드가
Dockerfile·의존성·배포·인증·승인 처리 코드를 바꿀 수 없다. 봇에 Docker socket이나 SSH 키는 주지 않는다.

호스트는 이미지 빌드 → ingress 정지/업무 drain → S3 백업 → 이미지 교체 → 모든 서비스와
DB 컨테이너 동일성 확인을 수행한다. 실패·중단 시 이전 image/env/역할로 복구하며 DB를 과거
백업으로 덮지 않는다. 운영 모델·권한 override는 보존하고 승인된 역할 지침만 바꾼다.
backup과 같은 파일 lock을 사용한다. root 전용 release journal은 재시작 시 중복 적용을 막는다.
복구에 실패하면 성공이라고 보고하지 않으며 journal과 systemd 실패 상태를 운영자가 확인한다.

## 운영 경계

GitHub App 권한은 기존 저장소 하나의 contents/PR write, actions read를 유지한다.
이 권한 자체가 main 쓰기를 기술적으로 금지하는 것은 아니다. 승인·허용 범위 검사는 broker가 한다.
새 유료 자원, API, 계정 요금제 변경은 없다. 승인·병합·배포는 LLM 호출 예산을 소비하지 않는다.
개선 관찰 10분/진행 5분 주기는 유지하고 승인도 다음 진행 주기에서 처리한다.

검증은 PostgreSQL의 실제 Slack ingress/승인/중복 처리, GitHub 통신 fixture의 변경 커밋·유실 응답,
host 파일 교체·복구·재시작 검사를 포함한다. 실제 운영 인수 영수증은 workspace evidence에 별도 남긴다.
과거 이미 수신된 “반영해”는 원 Slack event key·원문·소유자를 확인해 운영자가 같은 handler로
복구할 수 있으며, 새 사용자 메시지가 온 것처럼 표현하지 않는다.
