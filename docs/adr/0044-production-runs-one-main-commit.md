# 운영은 main 커밋 하나로 돈다

## 배경

2026-10-14 운영 서버 전체를 읽기 전용으로 대조했다(`docs/project/SERVER-MAIN-DRIFT-20261014.md`).

- **코드:** 컨테이너 17개는 각자 다른 기준 커밋(9/23~10/14)에 파일을 덧씌운 이미지로 돌고 있었다. 어느 커밋과도 일치하지 않았다. 같은 소스 경로로 Git에 한 번도 커밋되지 않은 파일 버전이 53개였다. 원격 브랜치에만 있는 버전도 12개였다(연구 메모 상한, Maintainer 수정, 영상 수정).
- **설정:** 서비스마다 서로 다른 릴리스 디렉터리의 compose 파일에 호스트에만 있는 overlay를 최대 16개씩 덧붙였다. main의 compose와 `runtime.env`만으로 렌더하면 영상 제작(`VIDEO_ENABLED`)과 미국 장마감 브리핑이 꺼진다. `video-image-runtime`은 main에 정의조차 없었다.
- **운영 위험:** Slack 허용 채널이 서비스마다 달라 브리핑 스레드 답글이 버려지고 있었다. 같은 Temporal 큐(브리핑 데이터, 계정, 데이터 감시)를 버전이 다른 코드가 나눠 처리했다. 여러 서비스가 동시에 기동하면 시작 DDL이 실행 중 조회와 교착했다(09:27 dispatch).
- **과거 사고:** 9/28 DM 무응답, 영상 사진 미작동, 렌더 이미지 불일치가 모두 이 방식에서 나왔다. main의 CI 테스트 약 2,700건은 운영 코드를 보증하지 못했다.

## 결정

1. **릴리스는 main 커밋 하나다.** 모든 서비스 이미지는 그 커밋으로 빌드하고 `org.opencontainers.image.revision`으로 식별한다. 파일 덧씌우기 이미지와 호스트 전용 compose overlay는 더 쓰지 않는다.
2. **설정은 릴리스의 `deploy/release.json`이 정한다.** 이 파일이 나열한 compose 파일, 호스트의 `runtime.env`(값만, 비밀값은 파일), 릴리스 변수로 렌더한다. 호스트에만 있던 값은 `runtime.env`로 옮기고 구조는 main으로 옮긴다(#145).
3. **연구 작업은 연구 워커에 등록된 회사 릴리스(`RESEARCH_RELEASE_COMMIT`)에 묶는다.** 컨테이너가 실행하는 코드 커밋과는 분리한다. 연구 계산은 연구 워커가 등록된 커밋으로 하고, 회사 서비스는 그 커밋을 작업에 기록만 한다. worker 이미지 고정(`PINNED_COMPANY_WORKER_IMAGE`)은 릴리스의 autonomous 이미지를 가리킨다.
4. **배포는 `deploy/release.py`로만 한다.** 순서는 prepare(커밋을 가리키는 `git archive`) → build → plan → migrate → apply → verify → activate다.
   - apply는 서비스를 하나씩 바꾼다.
   - 바꾸기 전에 그 서비스가 끊을 작업이 없을 때까지 기다린다: 모델 호출, 턴, Slack 전송, 영상 작업, 브리핑 집필.
   - 바꾼 뒤에는 릴리스 이미지, 계획한 config-hash, 릴리스와 같은 패키지 파일인지 확인한다. 아니면 그 서비스를 옛 컨테이너에 기록된 compose 파일로 되돌린다. 결과는 `/var/lib/quant-company/release-journal`에 남는다.
   - 호스트 잠금은 백업, Maintainer 릴리스와 같이 쓴다.
5. **스키마 DDL은 내용이 바뀐 때만 실행한다(`schema_digests`).** 실행할 때는 잠금 대기 상한을 두고 재시도한다. 릴리스마다 migrate를 한 번 실행하고, 서비스 시작은 DDL을 건너뛴다.
6. **`release.py verify`가 운영과 main의 차이를 보여 준다.** 대상은 모든 서비스의 커밋, 렌더 설정, 패키지 파일이다. 다음 단계로 이 대조를 매일 Slack에 알리고, CI를 통과한 main 커밋을 조용한 시간에 자동 적용한다(ADR 0045).

## 결과

- **변경 경로:** 운영 변경은 main PR로만 들어온다. 긴급 수리도 main hotfix 커밋으로 릴리스한다.
- **전환 기간:** 전환이 끝날 때까지 다른 세션은 운영 서버를 직접 바꾸지 않는다(2026-10-14 배포 동결).
- **영상 렌더:** 영상 렌더 이미지(Fargate 작업 정의, CloudFormation)는 같은 커밋으로 빌드해야 한다. 이 단계는 당분간 소유자가 승인해서 실행한다. video-worker는 렌더 이미지와 같은 커밋일 때만 전환한다.
- **보이는 차이:** 한 서비스만 바꾼 상태처럼 일부 서비스가 이전 커밋에 남아 있으면 verify에 그대로 보인다. activate는 모든 서비스가 같은 커밋일 때만 한다.
