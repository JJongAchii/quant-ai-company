# ADR 0038: 한국 검색 트렌드 아침 브리핑

상태: 승인된 구현. 실제 운영 활성화와 외부 검증은 별도 기록한다.

사용자는 한국의 종합 검색 관심 주제를 전용 Slack 채널에서 매일 아침 최대 8개와 짧은 배경으로
받고, 기존 구독 모델을 하루 1~2회 사용하는 설계의 구현을 승인했다.

Google Trends KR RSS를 10분 간격으로 관측하고 07:30 KST에 지난 24시간 후보를 동결한다.
관측된 Google 규모 표시의 최댓값으로 정렬하며 표시값을 합산하지 않는다.
네이버 검색어 트렌드는 후보 추이 확인에, 뉴스 검색은 관련 원문 발견에 사용한다.
플랫폼 간 검색량이나 네이버 응답별 상대 지수를 하나의 순위로 합치지 않는다.
외부 API는 현재 NAVER API HUB 계약을 사용하며 키는 수집 프로세스에만 연결한다.

기존 허용 언론 원문을 바탕으로 Reporter 모델·effort를 상속한 구조화 제안을 검증한다.
한 번 편집, 완료된 제안의 검증 실패에 한 번 수정만 허용한다. 불명 호출은 대체하지 않는다.
뉴스 모델 큐와 구독 실행 잠금을 공유하고 회사 호출 한도에도 예약한다.
발송 전용 Trend Scout는 모델 직원으로 활성화하지 않으며 이벤트를 받지 않는다.

수집·편집과 08시 확정 workflow를 분리한다. 확정 시 편집이 준비되지 않으면 숫자·링크 본문을
사용한다. 날짜·지역·채널 ID로 PostgreSQL 본문/outbox를 한 번 커밋하고 Slack 전송은 기존
영수증 경로를 따른다. 09시 만료, 정책 재검증, 불명 결과의 자동 재시도 금지를 적용한다.
Temporal이 타이머·실행·재시도를 소유하며 인메모리 예약 큐는 만들지 않는다.

결과적으로 Google RSS와 기존 허용 원문에 없는 주제는 포괄하지 못할 수 있고, 새 유행의
네이버 일별 통계와 배경 설명도 지연될 수 있다. 이를 확인 불가·관측 이력 부족·수집 공백으로
표시한다. 정상 편집이 늦어도 매일 아침 브리핑을 확정할 수 있다.
