# 저녁 브리핑 이메일 설계

- 날짜: 2026-10-19
- 요청: 소유자(Achii)
- 상태: 설계. 소유자는 시안(v5)과 결정을 대화에서 승인했고, 이 문서는 그 결정을 기록한다.

## 1. 왜 만드는가

Slack `daily-brief`로 오는 리포트는 소유자 혼자 보는 형식이다. 소유자는 이것을 **바깥 사람에게도 정기적으로 보낼 수 있는 이메일**로 만들고 싶어 한다. 처음에는 소유자 본인만 받고, 나중에 아는 사람들을 Slack 지시로 추가한다. 소유자의 말로는 "외부로 보내는 거다보니 가독성을 좋게 해서 보내자"는 취지다. Slack 리포트 형식은 바꾸지 않는다.

## 2. 목표 / 비목표 / 실패 기준

목표
- KRX 거래일마다 **저녁(마감) 브리핑 한 번만** 이메일로 보낸다. 소유자: "저녁브리핑때 한번만 하자".
- 받는 사람이 휴대폰에서 2~3분 안에 오늘 시장과 알아 둘 이슈를 이해할 수 있게 쓴다.
- 소유자가 Slack에서 수신자를 추가·삭제·조회할 수 있다.
- 받는 사람은 스스로 수신을 거부할 수 있다.

비목표
- 아침 브리핑 메일은 보내지 않는다.
- 웹 구독 페이지나 공개 가입 양식은 만들지 않는다. 수신자는 소유자가 추가한다.
- Slack 리포트 형식은 바꾸지 않는다.
- 영상 업로드 주소를 자동으로 넣지 않는다. 영상은 소유자가 직접 올리므로 발송 시점에 주소가 없다.

실패로 보는 경우
- 리포트에 없는 숫자나 사실이 메일에 들어가는 것
- 같은 메일이 같은 사람에게 두 번 가는 것. 불확실한 발송은 자동으로 다시 보내지 않는다.
- 수신 거부한 사람에게 계속 가는 것
- 수신자 주소가 로그·Slack·다른 서비스로 새는 것. 로그에는 가린 주소만 남긴다.
- 메일 기능 장애가 브리핑이나 영상을 막는 것

## 3. 결정된 내용

### 3.1 형식: 시안 v5 (소유자 승인)
소유자가 고른 방향은 "요약형 B, 더 상세하게"다. 이어 다음 피드백을 줬다.
- 6~7점 평가 뒤 "그 방향으로 다시 만들어줘"
- "AI 표시 필요없어 넣지마"
- "진지하게 말해주면 좋겠는데"
- "근거 줄은 제외해줘"

1. **제목**: 그날 가장 두드러진 사실을 숫자로 쓴다. 예: `코스피, 3.2% 급락 출발 후 1.8% 상승 마감 | 10/19 마감 브리핑`. 미리보기 줄에는 수급 등 핵심을 한 문장으로 쓴다.
2. **머리글**: 뭐든story 로고·이름, "MM/DD 장 마감 · 오늘의 증시story", 큰 제목, 2문장 요약.
3. **오늘의 시장**(맨 앞)
   - 소제목 한 줄
   - 출발→마감 그림: 코스피 시가·종가와 등락률. 데이터가 없으면 지수·등락만 보여 준다.
   - 지수 흐름 문단
   - 투자자별 매매: 기관·외국인·개인의 장 마감 순매수를 색(상승 빨강, 하락 파랑)으로 보여 준다.
   - 업종·종목 문단
   - 용어 풀이 상자(예: 순매수, 순환매)
4. **주요 이슈** 2~3개. 각각 다음으로 구성한다.
   - 사실을 담은 소제목. 비유는 쓰지 않는다.
   - 무슨 일인지 한 문단. 어려운 용어는 괄호로 풀이한다.
   - "시사점" 상자: 한국 시장·투자자에게 어떤 의미인지. 반론이 있으면 함께 쓴다.
   - "▶ 확인할 일정/지표/사항": 가능하면 날짜와 연결한다.
5. **기업 소식** 0~1개, 한 문단.
6. **주요 일정**: 날짜(요일)별 한 줄. 이슈와 관련된 날에는 짧은 메모를 붙인다.
7. **영상으로 보기** 버튼: 채널 페이지 https://www.youtube.com/@anything-story 로 연결한다.
8. **끝부분**
   - 소개: "뭐든story는 매 거래일 장 마감 후 국내 증시의 주요 내용을 정리해 보내 드립니다."
   - 수신 이유: "…수신에 동의하신 분께 발송됩니다."
   - 면책: "투자 권유가 아닌 정보 제공용 자료이며, 투자 판단과 책임은 본인에게 있습니다."
   - 수신 거부 링크
9. **넣지 않는 것**
   - AI 작성 표시
   - 근거 기사 목록 줄이나 출처 링크 줄
   - 본문 각주 번호
10. **문체**: "~습니다"체로 쓴다. 구어체("~했어요")와 비유("지갑은 닫혀", "불씨")는 쓰지 않는다. 쉬운 말과 용어 풀이는 유지한다.

시안 HTML(참고용): 이 문서와 같은 PR의 `docs/superpowers/specs/assets/2026-10-19-evening-brief-email-v5.html`.

### 3.2 내용의 출처와 검증
- 메일 글은 그날 **커밋된 PM 에디션**(`brief_editions` 행의 `proposal`, `market_data`, `rendered`)만을 근거로 쓴다.
- 리포트 문장을 잘라 붙여서는 위 형식(훅 제목, 시장 이야기 먼저, 쉬운 말)을 만들 수 없다. 그래서 **메일용 글을 쓰는 모델 단계**를 둔다.
- 쓴 글은 보내기 전에 결정적으로 검사한다.
  - 메일의 모든 숫자는 에디션 텍스트에 있어야 한다. 반올림 표기(3.17%→3.2%)는 허용 규칙을 둔다.
  - 매수·매도 권유 표현, AI·모델·도구 언급, 금지 표현이 없어야 한다.
  - 구조(필수 블록, 이슈 수)가 맞아야 한다.
- 검사를 통과하지 못하면 재작성을 요청한다. 정해진 시각까지 실패하면 대체본을 보낸다. 대체본은 리포트 문장에서 결정적으로 뽑은 같은 레이아웃이다: 30초 요약, 숫자, 이슈 소제목과 사실 첫 문장, 확인할 것.
  - 메일은 하루를 건너뛰지 않는다. 이것은 빌더 판단이며, 소유자의 "영상은 보류하지 않는다" 원칙과 같은 방향이다.
- 에디션이 공지형·축소형이라 `proposal`이 없거나 이슈가 0개면 그날은 보내지 않고, 소유자에게 Slack으로 한 줄 알린다.

### 3.3 발송 시점
- PM 에디션이 커밋되면(지금은 16:10 기준 자료, 17:25 마감, 준비되면 조기 발송) 메일 작성을 시작한다. 준비되는 대로 보내되 **19:00 KST 전**에 보낸다.
- 작성 모델이 늦거나 실패하면 18:30에 대체본으로 전환한다.
- KRX 휴장일에는 PM 에디션이 없으므로 보내지 않는다.

### 3.4 발신 주소
- 소유자가 고른 방법은 **뭐든story 전용 Gmail 계정을 새로 만들어 앱 비밀번호로 SMTP 발송**하는 것이다(①).
- 발신자 이름은 "뭐든story", 주소는 소유자가 만든 Gmail이다.
- 서버 확인(2026-10-19 22:3x, 읽기 전용): dispatch 컨테이너에서 smtp.gmail.com:587에 연결되고 220 응답을 받는다. imap.gmail.com:993도 열려 있다.
- 앱 비밀번호는 Docker secret 파일로 넣는다. 그 메일을 보내는 컨테이너에만 마운트하고, 채팅·Git·로그에 남기지 않는다.
  - 소유자가 Mac 터미널에서 한 줄로 넣을 수 있게, 화면에 비밀번호를 보이지 않고 입력받아 0600 파일로 저장하는 스크립트를 제공한다. `deploy/claude-login.sh`와 같은 방식이다.

### 3.5 수신자 관리 (Slack)
- 소유자만 쓸 수 있는 **결정적 명령**으로 처리한다. 모델 도구로 만들면 codex-runtime 계약 이미지를 함께 바꿔야 하므로 피한다(ToolRequest 추가 금지).
- 명령은 소유자가 지시하는 채널에서 받는다.
  - `이메일 추가 <주소>`: 형식을 검사한 뒤 추가한다. 이미 있으면 다시 켠다.
  - `이메일 삭제 <주소>`: 수신을 끈다. 기록은 남긴다.
  - `이메일 목록`: 가린 주소와 상태를 보여 준다.
  - `이메일 시험 발송`: 가장 최근 PM 에디션으로 만든 메일을 **소유자 수신자에게만** 보낸다.
- 처음에는 수신자가 0명이다. 소유자가 자기 주소를 `이메일 추가`로 넣는다.

### 3.6 수신 거부
- 웹 주소(도메인)가 없으므로 메일 하단 링크와 `List-Unsubscribe` 헤더는 `mailto:`(발신 주소, 제목 "수신거부")로 둔다.
- 메일을 보내는 서비스가 같은 Gmail 계정을 IMAP으로 주기적으로 읽는다. 등록된 수신자가 보낸 "수신거부" 메일을 찾으면 수신을 끄고, 소유자에게 Slack으로 가린 주소와 함께 한 줄 알린다.

### 3.7 켜고 끄기
- 기본값은 꺼짐이다(`NEWSLETTER_ENABLED=false`). secret과 수신자가 준비되고 시험 발송을 확인한 뒤 소유자가 켠다.

## 4. 제약

- 운영 규칙(AGENTS.md, CLAUDE.md)
  - 모든 외부 효과는 영수증을 남기고 정확히 한 번 발송을 주장하지 않는다.
  - SMTP에는 멱등 키가 없다. 그래서 수신자별 발송 행을 먼저 기록하고 고정 Message-ID를 쓴다. 보내는 중 끊긴 발송은 `uncertain`으로 남기고 자동 재발송하지 않는다.
- 운영 변경은 PR 병합과 `release.py`로만 한다. secret 파일 경로, runtime.env 값, compose 변경은 릴리스가 못 하는 부분이므로 릴리스 운영자에게 정확한 값으로 전달한다.
- 새 설정은 `compose.yaml`의 해당 서비스 env에 명시해야 실제로 들어간다(x-db-env 또는 video-worker 목록).
- dispatch는 모델 토큰이 없는 발송 전용 프로세스다(`docs/deployment.md`). 모델 호출을 dispatch에 넣지 않는다.
- 렌더 입력(`video.remote`가 import하는 모듈과 `design/`)을 건드리지 않아야 렌더 이미지 없이 배포된다. `release.render_changes`가 []여야 한다.
- 수신자 주소는 개인정보다. DB에만 두고, 로그·Slack·테스트 출력에는 가린 형태만 쓴다.

## 5. 빌더에게 맡기는 것

- 메일 글을 쓰는 모델 호출의 위치와 계약 이름.
  - 조사 결과, Claude 호출 경로(claude-runtime, 같은 커밋에서 이미지가 빌드됨)를 쓰는 프로세스(video-worker)에 두면 codex-runtime 고정 이미지와 엮이지 않는다.
  - 새 output contract는 `ProviderRequest`의 Literal과 검증 분기, `claude_runner.output_schema`에 추가된다.
- 저장 테이블 설계: 수신자, 에디션별 메일 본문, 수신자별 발송 영수증, 명령 기록.
- PM 커밋 뒤 작업을 만드는 방법. 영상의 `enqueue_isolated`처럼 savepoint를 쓰고, 에디션마다 고정 ID를 둔다.
- HTML 메일 템플릿 구현.
  - 메일 클라이언트 호환을 위해 인라인 스타일과 테이블 레이아웃을 쓰고, 웹폰트는 쓰지 않는다.
  - 텍스트 대체본(multipart/alternative)을 함께 보낸다.
  - 로고는 첨부 이미지(cid)로 넣는다.
- 숫자 검사 규칙의 세부(반올림 허용 범위, 단위 표기)
- IMAP 확인 주기
- 출발→마감 그림에 쓸 시가 데이터의 출처. 에디션 텍스트에 시가가 없으면 그림 대신 지수·등락만 보여 준다.

## 6. 확인 방법

- 실제 PostgreSQL 테스트
  - 수신자 명령(추가/삭제/목록/시험), 소유자 이외 사용자 거부, 주소 가림
  - 발송 영수증. 중복 발송이 없고, 끊긴 발송은 uncertain으로 남아 재발송하지 않는다.
  - 수신 거부 처리
  - 기능이 꺼져 있으면 아무 일도 하지 않는다.
- 숫자 검사: 리포트에 없는 숫자를 넣은 글은 거절하고, 반올림 표기는 허용한다.
- 렌더: 10/19 PM 에디션으로 HTML을 만들어 브라우저 스크린샷으로 시안 v5와 비교한다.
- 실제 SMTP는 소유자의 계정이 준비된 뒤 `이메일 시험 발송`으로 소유자 주소에만 확인한다. 그 전까지의 테스트는 가짜 SMTP 서버로 한다(실제 배포로 표시하지 않는다).
