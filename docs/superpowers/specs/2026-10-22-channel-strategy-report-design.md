# 채널 전략 리포트 설계 (2026-10-22)

## 왜 바꾸나
사장님(10/22):
> "영상 하나하나 별로 분석해서 그 대안을 제시한다기보다 지금까지의 영상들의 성과들을 분석해서 앞으로 우리가 생성할 영상들에 어떤
> 개선을 하면 좋겠다는 이런 제안이 오는게 더 효과적이지 않을까 … 어떤 분석결과들을 통해 이런것들이 효과가 있었고 시청자들은 어떤
> 걸 선호했다던가, 어떤 검색으로 유입되고 … 우리도 이런 전략을 취하면 되겠다 이런 분석들이 나와야 좀더 이 채널이 의미가 있지 않을까?"

10/22 기준 상태:
- 영상별 카드 13개가 올라왔다. 내용은 기준 대비 수치, 가설, Studio에 붙여 넣을 수정안이다.
- 영상들을 묶어 보는 주간 리뷰는 10/19 단 한 번 돌았고 실패했다. `invalid_output`: `patterns` 한 항목이 300자를 넘었다. 다시 시도하는 장치가 없다.
- 채택된 교훈은 0개다.
- 채널이 작다(구독 18명, 영상당 노출 수백 회). 그래서 영상 하나의 수치는 거의 우연이고, 영상별 수정안의 효과도 작다.

## 목표
1. **채널 전략 리포트**를 주 2회(월·목 09:00 KST) analytics 채널에 올린다. 지금까지의 영상(본편과 Shorts)을 묶어 분석하고, 다음 영상의 제작 방식을 바꿀 전략을 제안한다.
2. **영상별 카드는 튀는 영상만** 올린다. 나머지 영상의 스냅샷은 리포트 재료로만 쓴다.
3. **벤치마크는 주 1회**(월요일 리포트에 포함)다.
   - 분야를 가리지 않고, 최근 급성장했거나 구독자에 비해 조회수가 크게 나온 영상을 서비스가 골라 온다.
   - 모델이 우리 채널(증시 브리핑 본편과 Shorts)에 옮길 수 있는 패턴을 뽑는다.
   - 사장님 답: "분석대상은 꼭 증시 경제 채널이 아니어도 되."
4. 리포트의 전략 항목은 지금 있는 교훈 버튼(채택·거절)으로 채택한다. 채택한 교훈은 다음 회차부터 제작 지시에 들어간다. Shorts 관련 전략도 Shorts 대본 지시에 들어가야 한다.
5. 모델 출력이 형식에 맞지 않아도 리포트가 통째로 날아가지 않는다.

## 리포트 내용 (Slack 본문, 한국어)
1. **한 줄 결론**과 이번 기간 숫자: 조회, 구독 증감, 노출, 클릭률, 30초 유지, 평균 시청 비율. 본편과 Shorts를 따로 보고, 지난 기간과 비교한다.
2. **효과가 있었던 것과 없었던 것**
   - 영상을 묶어 비교한다.
     - 제목 유형(질문형·사실형, 숫자·종목명 유무)
     - 썸네일 문구 길이
     - 아침·마감
     - 길이
     - 첫 장면(cold open) 방식
     - 연출 규칙(`policy.craft`)이나 활성 교훈 적용 전후
   - 항목마다 비교한 편수(n)와 확신 정도(낮음·보통·높음)를 붙인다.
   - 편수가 적으면 "아직 판단 이름"이라고 쓴다.
3. **시청자가 좋아한 것**: 이탈이 적었던 장면 유형과 주제(scene_drops), 좋아요·댓글이 많았던 영상과 그 공통점
4. **유입 경로와 검색어**
   - 탐색·추천·검색·Shorts 피드·채널 페이지·외부 비중의 추이
   - 영상 전체의 검색어를 모은 상위 목록
   - 키워드 전략: 제목·태그·설명에 어떤 말을 넣을지
5. **Shorts → 본편**: Shorts 조회, 구독 증감, 본편 조회와의 관계(같은 날 본편과 짝지어 비교)
6. **다음 전략 3가지와 실험 1개**
   - 전략: 바로 쓸 수 있는 제작 지시 한 문장, 범위(scope), 근거 영상, 움직일 지표
   - 실험: 무엇을 바꿔 무엇과 비교할지, 몇 편 동안, 어떤 지표로 판단할지
   - 활성 교훈마다 유지·은퇴·판단 이름 평가(지금 주간 리뷰와 같다)
7. **벤치마크**(월요일만): 고른 영상 3~5개마다 왜 잘됐는지(제목·썸네일·첫 장면·주제·댓글 반응), 그리고 우리 채널에 옮길 점 1~3개

리포트 아래에 전략 3가지마다 교훈 버튼(채택·거절)을 단다. 활성 교훈에는 은퇴 버튼을 단다.

## 정해진 것 (사장님 결정)
- 주기: 월·목 09:00 KST
- 영상별 카드: 튀는 영상만
- 벤치마크: 주 1회(월), 분야 무관

## 내가 정한 것 (사장님이 다르게 원하면 바꾼다)
- 지금 주간 리뷰(`kind='weekly'`, 월 09:00)를 이 리포트로 바꾼다. 같은 테이블·버튼·답글 흐름을 쓴다. 날짜가 월요일과 목요일이 된다.
  - 분석 대상: 리포트 시점까지 d3 이상 스냅샷이 있는 모든 업로드
  - 강조 범위: 직전 리포트 이후 새로 들어온 영상
  - 데이터는 YouTube 보고서 특성상 2~3일 늦다. 리포트에 "데이터 기준일"을 적는다.
- **튀는 영상**: d3 스냅샷이 같은 판(아침·마감·Shorts) 기준 중앙값 대비 다음 중 하나에 해당하는 영상
  - 조회 2배 이상 또는 절반 이하
  - 클릭률 1.5배 이상 또는 2/3 이하
  - 30초 유지 1.3배 이상 또는 0.77배 이하
  - 기준이 부족하면(같은 판 3편 미만) 카드를 올리지 않는다.
  - 튀지 않는 영상은 모델 진단도 하지 않는다(모델 사용량 절약). 7일 업데이트 글도 튀는 영상에만 단다.
- **교훈 범위에 `shorts`를 추가**한다.
  - `shorts` 교훈은 Shorts 대본 지시에만 넣고, 본편 지시에서는 뺀다.
  - Shorts 컷이 쓰는 교훈은 본편 회차가 만들어질 때 고정된 `policy.lessons`에서 고른다. 렌더 이미지 입력인 episode.py·contracts.py는 건드리지 않는다.
- **벤치마크 후보 수집**(서비스가 함, 모델은 고르지 않음)
  - YouTube Data API를 쓴다.
    - `videos.list chart=mostPopular regionCode=KR`: 카테고리 전체와 22·27·28 등 몇 개, 각 50개
    - `channels.list`: 구독자 수, 채널 개설일
  - 점수: 조회수/구독자 비율과 채널 나이. 개설 1년 이내이거나 비율이 높은 영상을 앞에 둔다.
  - 상위 5개를 고르고, 영상마다 제목·설명 앞부분·길이·게시일·조회·좋아요·댓글 수·인기 댓글 5개·썸네일 이미지를 모델에 준다.
  - 쿼터: 리포트 1회에 약 20단위 이하. `search.list`(100단위)는 쓰지 않는다.
  - 우리 채널의 공개 데이터 권한만 쓴다. 쓰기 권한은 쓰지 않는다.
- **출력이 형식에 맞지 않을 때**
  - 같은 리포트를 한 번 더 요청한다. 검증 오류를 피드백으로 붙이고, 새 요청 ID는 `-r2`다.
  - 그래도 실패하면 지금처럼 실패 글을 올리되, 오류 코드와 다음 리포트 날짜를 적는다.
  - 항목별 글자 수 한도는 넉넉히(500자) 두고, 모델에게 한도를 알려 준다.
- 리포트 길이: Slack 본문 4,000자 이내. 넘치면 벤치마크와 세부 근거는 스레드 첫 답글로 보낸다.
- 정직성: 지금 FUNNEL/HONESTY 규칙을 유지한다. 작은 표본임을 밝히고, 상관관계를 인과로 말하지 않는다.

## 하지 않는 것
- 영상 Studio 메타데이터를 자동으로 바꾸지 않는다(지금처럼 사람이 붙여 넣는다).
- 다른 채널 영상 내려받기, 자막 수집, 화면 캡처는 하지 않는다. 공개 메타데이터와 썸네일 이미지만 쓴다.
- 렌더 이미지 입력(episode.py, contracts.py, motion.py, design/)은 건드리지 않는다.

## 확인 방법
- 단위 테스트
  - 튀는 영상 판정
  - 리포트 컨텍스트 구성(본편과 Shorts 분리, 기간 비교, 검색어 모으기, 유입 비중)
  - 벤치마크 점수와 선택
  - 출력 실패 시 `-r2` 재요청과 실패 글
  - `shorts` 교훈의 본편 제외와 Shorts 포함
  - 월·목 일정과 따라잡기
- 운영 확인: 배포 후 다음 월·목 09시 리포트가 analytics 채널에 올라오는지 본다. 목요일이 첫 리포트다.
