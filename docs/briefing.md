# Analyst — daily-brief

첫 메시지를 읽고 오늘 시장의 방향, 흐름을 만든 핵심 사건, 다음에 확인할 사항을 파악하는 전용 Slack 봇이다.
핵심 요약 뒤 시장 전체 흐름과 주요 이슈를 설명한다. 본문 산문은 대략 1,800~3,500자를 지향하며
기사 수에 맞춰 분량을 조절한다. 링크를 포함한 전송 상한은 30,000자이며 실제 Slack 블록 제한도 검사한다. 상세 근거는 같은 스레드에
최대 네 건(각 3,500자)이다. 분량 때문에 중요한 이슈를 본문 밖으로 자동으로 밀어내지 않는다.
[Slack의 권장 분량과 전송 제한](https://docs.slack.dev/reference/methods/chat.postMessage/)을 구분하며,
긴 글 자체를 좋은 브리핑으로 평가하지 않는다.
Reporter는 속보를, Analyst는 정기 종합과 후속 질문을 맡는다. 금융전략 직원은 전략 개발
팀장 역할을 유지하며 사용자가 요청할 때만 연결한다.

사용자에게 보이는 이름은 **Analyst(애널리스트)**다. 기존 `market_brief` 역할 ID와 자격 증명 키,
발간 ID·스레드·예약은 유지한다. 별도 봇이나 새 발송 경로를 중복 생성하지 않는다.
이전에 앱을 설치했다면 기존 앱의 표시 이름을 Analyst, bot display name을 analyst로 갱신한다.
manifest 파일이나 코드를 바꾼 것만으로 실제 Slack 앱의 이름이 변경되지는 않는다.

아침은 새 미국 거래 결과가 있거나 당일 한국장이 열리거나 월요일이면 발간한다. 일요일 정기
발간은 없다. 오후는 한국 거래일에만 발간한다. 휴장을 보합으로 표시하거나 금요일 종가를 월요일의
새 결과로 복사하지 않는다. 미국 동부 시간과 한국 시간을 구분하고 서머타임·조기폐장을 반영한다.
거래일 계산은 `exchange_calendars`의 XNYS/XKRX를 사용한다. 라이브러리가 임시휴장·특별 거래시간을
전부 아는 것은 아니므로 운영자는 공식 공지를 대조해 아래 날짜별 override를 등록해야 한다.

한국판은 장 마감 후 그날의 흐름을 파악할 수 있도록 17:45로 정했다. 16:10부터 자료를 수집하고
16:30에 입력을 고정한 뒤 선정·작성·검토를 진행한다. 독립된 마감 보도 두 곳의 핵심 종가가
일치해야 하며, 수집 자료가 늦게 게시되면 기준일이 표시된 과거 맥락으로만 사용한다.
과거 S3 조사에서 확인한 KRX 19:24 게시 시각은 하루의 관측이며 매일의 게시 보장은 아니다.
당일 종가를 확인할 수 없으면 결측을 표시한다. 미국 ETF 수집 데이터는 지수 자체가 아니며 지수 종가로 대체하지 않는다.
실제 지연은 초 단위로 기록한다. 기존 운영 인수의 최종 한계는 목표 시각에서 10분 이내이며,
이를 정시 도착으로 숨기지 않는다. 한계 이후 새 생성을 시작하지 않는다.

본문 순서는 **핵심 최대 세 줄 → 주요 숫자 → 시장 전체 흐름 → 주요 이슈 → 다음 확인할 것**이다.
주식의 업종·수급·상승 범위, 금리·환율·원자재, 경제지표·중앙은행, 정책·통상·국제 정세,
기업·산업 변화를 매회 검토한다. 확인된 중요한 변화가 많은 날은 서로 다른 이슈 네~여섯 개를
각각 제목과 짧은 문단으로 설명한다. 세 번째 이슈부터 부수 소식으로 낮추지 않는다.
같은 사건의 종목별·자금조달별 설명을 여러 이슈로 세지 않고, 별개의 경제적 변화와 확인 조건이
있을 때만 나눈다. 중요한 다른 분야가 빠지면 원문·문장 단위 검증이 맞아도 내용 범위 검토는
통과하지 않는다. 조용한 날에는 적게 쓰며 분야별 기사 수를 강제하거나 미확인 분야를
‘주요 변화 없음’으로 표현하지 않는다.
짧은 문장과 문단을 사용하고 출처는 작은 번호 링크로 표시한다. 다섯 가지 분석 소제목을 매 이슈에
반복하지 않는다. 중요도·변화·영향·반대 근거는 내부 편집 기준이며, 수치의 시각과 상세 비교는
스레드에 둔다. 이슈의 경제적 영향 뒤에는 다른 가능성·상쇄 조건을 짧게 연결해 본문만 읽어도 양쪽 설명을
볼 수 있게 한다. 원문이 전한 실제 상쇄 요인은 사실로도 설명한다. 요약은 결론, 시장 흐름은 시장 간
연결, 개별 이슈는 구체적 사건과 배경을 맡고 같은 설명을 반복하지 않는다. 시장 내부 항목은 새로운
업종·시장 폭·수급 정보가 있을 때만 쓴다. 자료 불일치는 독자 언어로 설명한다. 각 중요 이슈의
확인 조건은 이슈 본문 옆에 두고, 다음 확인 사항에도 공간을
확보하며 가까운 발표·행사 일정을 먼저 보여준다. 별도 관찰 항목이 없으면 핵심 이슈의 확인 조건을 사용한다. 첫 메시지에 그날을 이해하는 데
필요한 결론이 있어야 한다. 이슈가 많은 날은 최대 여섯 건까지 사건·배경·영향을 설명한다.
시장·정책·국제 정세·기업/업종·자산 간 흐름의 누락 여부를 별도로 평가한다.
[후속 실제 원문 평가](project/BRIEFING-HELDOUT-VALIDATION.md)에서는 한 기사 안의 정책 기준·제안·시행
시점처럼 서로 다른 중요 내용을 각각 확인한다. 본문의 다음 확인 사항은 선정·검증된 일정 전체와 시장 확인
조건 최대 세 건을 모두 보여준다. 관찰 항목에 담긴 이미 확인된 사실은 업종·수급 본문에 배치하고,
앞으로 확인할 조건과 구분한다. 작성자는 중요한 일정만
고르고 검토자가 중요도·가독성을 확인하며, 표시 순번만으로 핵심 일정을 스레드에 숨기지 않는다. 시각이 확인되지 않은 일정은
불확실성을 한 번만 표시하고 한국의 특정 시간대로 억지 배정하지 않는다.
[실제 모델 내용 평가 기준](project/BRIEFING-CONTENT-EVALUATION.md)을 사용하며 이전 합성 예시는 품질 증거가 아니다.
자료가 적으면 짧게 쓴다. 업종 집중도, 시장 폭, 수급은
출처가 있을 때만 다룬다. 중국·유럽·원자재·가상자산과 중요한 세계 사건도 중요도에 따라 포함한다.
컨센서스·이전값·수정값은 실제 근거가 있어야 하며, 사실과 인과 해석을 분리한다.

오후판은 오전의 원래 관찰 문장을 보존해 확인됨·엇갈림·판단 불가로 돌아본다. 오전 메시지의
전달이 불명확하면 전달된 관찰로 취급하지 않는다. 미리보기에서는 오전 미리보기를 사용할 수 있다.
스레드에서 질문하면 Analyst가 같은 발간본과 원문을 읽는다. 추가 조회 결과는 원래 자료
기준 시각과 구분한다. 잘못된 설명의 정정은 원문을 덮어쓰지 않고 스레드에 근거·확인 시각과 함께 남긴다.

금융전략 팀장을 직접 멘션하거나 브리핑 스레드에서 다음처럼 입력한다.

```text
금융전략 검토: 이번 변화가 기존 연구 가정에 미치는 영향을 분석해줘.
```

이 명시적 사용자 입력을 서비스가 기존 금융전략 업무 경로로 연결한다. Analyst 모델은
동료 위임 권한이 없으며 정기 발간이 전략 연구를 자동으로 시작하지 않는다.

## 실행·검증 경계

- 발송 95분 전에 수집을 시작하고 75분 전에 입력을 고정한다. 일반일의 입력 기준은 06:30/16:30 KST다.
  작성 뒤 첫 검토·한 차례 보완·최종 검토를 마칠 시간을 확보하며, 일반일 발송은 07:45/17:45를 유지한다.
  발간본에 실제 기준 시각을 표시한다. 정시 자격은 실제 수집·큐·전송을 포함해 별도로 검증한다.
- 기존 S3 레이크는 `qdata.api`로 읽는다. 한국 지수 종가와 전 거래일·5/20거래일 비교는 코드에서
  계산한다. 당일 한국 자료는 18시 이후 가용 조건과 실제 조회 완료 시각을 모두 지켜야 한다.
  당일 자료가 없으면 과거 값을 오늘 값으로 쓰지 않는다.
- `BRIEFING_US_CLOSE_ENABLED=true`(기본 꺼짐)이면 데이터 worker가 미국 새 거래가 있는 아침판에 대해 XNYS
  실제 마감 C 기준 C+5~C+35분 동안 2분 간격으로 Yahoo 공개 chart 값을 읽는다(지수 `^GSPC ^IXIC ^DJI ^SOX ^VIX`,
  ETF 9종, 설정 `briefing_us_close_stocks` 기본 NVDA·MU·AAPL·MSFT(compose 전달은 아직 없음), 연속 거래 `^TNX`·WTI·금·비트코인·이더리움).
  원천 시각이 마감 이후(VIX는 C+15분)이고 연속 두 조회 값이 같을 때만 확정한다. `^TNX`·선물·암호화폐는 마감
  뒤에도 거래되므로 시각이 붙은 미확정 시세로만 기록하고 종가로 고정하지 않는다. 모든 조회는
  `market_data.us_close`와 데이터 원문(`yahoo.chart:us_close`) 영수증에 보존하며 입력 고정 이후에는 조회하지 않는다.
  작성 입력에는 확정 지수(S&P 500·나스닥·다우·필라델피아 반도체·VIX)만 짧은 표(키·심볼·종가·전일 대비·전일 종가·
  원천 시각·제공자)로 넣고 원시 조회와 ETF·종목 확정 값은 영수증에만 둔다. 확정 지수 값은 기존 데이터셋 경로로
  고정 관측값 후보가 되며, 미국 마감 이후 발행된 기사 1건이 같은 종가를 보고할 때만 수집 데이터로 고정한다. 기사 값이 다르면 수집 데이터 우선 규칙을 쓰지 않고 해당 숫자를 빼며 두
  값을 기록한다. 확정 값이 없거나 일치 기사가 없으면 기존 두 매체 일치 규칙을 쓴다.
- 미국 ETF의 수정가격 비교, FRED·ECOS 관측은 각 날짜가 붙은 배경자료다. SPY를 S&P 500 지수로,
  QQQ를 나스닥 종합으로 표시하지 않는다. 거시 관측일을 발표 시각으로 간주하지 않는다.
- 읽기 전후 객체 식별자를 대조하고 계산에 쓴 행을 발간본에 보존한다. 자격 증명이 있는 기존
  전용 `briefing-data-worker`의 별도 단기 프로세스에서 수행한다. DB·Slack·모델 비밀은 읽기 프로세스에 전달하지 않는다.
  고정된 작은 테이블 4개만 사용하며 객체당 4MiB·10만 행·12열, 총 실행 45초 제한을 둔다.
  대형 개별주·수급 테이블을 전체 읽기로 우회하지 않는다. 해당 시장 폭·수급은 확인된 원문이 있을 때만 쓴다.
- 기존 등록 뉴스 원문을 재사용한다. 최신 국내 단신이 다른 출처를 밀어내지 않도록 관련 제목을
  출처별로 제한해 읽고, 주제·출처를 나누어 선택한다. 부족하면 등록된 국내외 매체·공식 피드 최대
  10곳에서 발견하고 주기당 원문 최대 12건을 추가 확인한다. 총 수집 시간은 210초로 제한한다.
- 경제 일정은 연준·BLS·BEA·한국은행의 공개 페이지를 읽는다. 접근 거절·추출 실패·시각 미확인은
  결측으로 남긴다. BLS 접근 거절은 기존 뉴스 수집과 같은 제약이며 우회하지 않는다.
- 수집 원문에서 후보 최대 96건을 보존하고, Analyst의 자료 선정 단계가 제목·앞부분·중간의 조건과
  반대 근거·마지막 실질 문단을 비교해
  최종 기사 최대 20건을 고른다. 필수 마감 기사, 알려진 ID, 마감 이전 수집 시각, 본문 합계
  최초 선정 36,000자 제한을 코드가 검사한다. 전체 42,000자 중 6,000자를 독립 검토 후 누락 원문을
  읽는 보완용으로 남긴다. 원문을 잘라 예산에 맞추지 않는다. 선택 이유는 작성자가 원문에서 확인할 질문이며 사실 근거가 아니다.
  영문 `KOSPI/KOSDAQ` 마감 기사도 국문 기사와 같은 제목 우선순위로 다룬다. 짧은 중복 마감
  요약보다 업종·수급·반대 근거를 더한 원문을 우선하고, 통신사 재전재 여부는 따로 확인한다.
  발견용 발췌는 원문 위치와 함께 제공하며 문맥 상한에 따라 기사당 520/440/360/280/240자로 조절한다.
  후보 ID를 버리거나 선택된 원문을 줄이는 용도로 사용하지 않는다. 작성·검토에는 완전한 본문을
  기사당 최대 12,000자까지 보존한다. 수집기가 이미 원문을 잘랐거나 실제 본문 길이가 공급분을
  넘거나 이 한도를 넘는 기사는 브리핑 근거에서 제외한다. 부분 원문을 완전한 기사로 인정하지 않는다.
  새 발간본은 원문 해시·출처·정확한 위치에 연결된 짧은 인용 참조를 모델에 제공하고, 모델이
  선택한 참조를 서비스가 정확한 원문으로 복원해 타입·숫자·의미 검증에 넘긴다. 없는 참조, 다른
  출처나 변경된 원문은 거부한다. 원래 모델 영수증을 고쳐 인용 오류를 숨기지 않는다.
  핵심 이슈의 고객·자금 조달 조건, 성장의 집중 위험, 실제 시행된 무역 조건과 금리의 다른
  설명을 자료 선정 때 함께 확인한다. 투자 발표가 상장이나 보증 등 선행 조건에 달려 있다면
  그 조건을 본문에 남긴다. 전문용어는 원문이 뒷받침하는 기능이나 쉬운 범주로 풀어 쓴다.
  입력은 한 번만 고정하며 마감 처리에서 자료를 다시 붙이지 않는다. 검토 입력의 반복 키와
  인용 참조는 복원 가능한 형식으로 줄이되, 선택된 원문 본문·발표 시각·독자에게 보이는 문장은 보존한다.
  수정은 지적된 예시뿐 아니라 보충 원문 전체의 실적 구성·증설 시점·상쇄 조건을 다시 분석한다.
  기존 문장의 길이·인용 한도에 들어가지 않는 중요한 근거는 같은 이슈 아래에 짧은 문단으로
  추가할 수 있다. 한 차례 내용 보완에서 최대 4개를 추가하되, 기존 문단을 포함해 이슈당 최대 2개,
  문단당 최대 500자(가급적 300자 이하)이며 각 문단은 자체 원문 근거와
  숫자 검증을 받는다. 최종 검토는 이 문단도 본문에 보이는 사실로 평가한다. 기존 가격·검증 문장과
  수정·모델 호출 횟수 제한, 독립 검토 12개 기준, 본문 크기 제한은 그대로 적용한다.
  일정 최대 4건을 추가한다. 후보에서 빠진 수와 모든 입력·선정 영수증을 보존한다. 전 세계 뉴스·일정의
  완전한 커버리지를 보장하지 않는다. 기사 읽기 권한은 기존 `news/sources.json` 등록을 따른다.
- 동일 매체의 여러 피드를 독립 출처로 세지 않고, 매체 다양성과 중복 원문 제외를 먼저 적용한다.
  동일 통신 기사를 옮긴 여러 매체도 독립 확인이 아니므로 별도 검토에서 확인한다.
  제목 분류는 한국은행 약칭과 은행 이름, 거시 고용과 개별 노사 요구를 구별하며, 단일 종목
  상장 첫날 기사나 ETF 구성 변경이 더 넓은 이슈를 밀어내지 않도록 한다. 선택 규칙의 버전도
  발간 정책에 포함해 변경 전 미리보기를 새 정책의 자격으로 재사용하지 않는다.
- 마감 보도·출처 다양성·주제 범위가 부족하면 발간당 검색 최대 1회를 기존 ChatGPT 구독으로 수행한다. 검색 결과는
  후보일 뿐이며 허용 매체 원문을 읽어야 근거가 된다. 새 유료 API·유료 시세 계약은 없다.
- 자료 선정·사실 확정·작성·독립 검토를 각각 요청한다. 현재 사용자 지정 배정은 `gpt-6-astra / xhigh`이며
  실제 배정 버전과 요청을 함께 저장한다. 원문은 명령이 아닌 데이터다.
  코드가 출처·인용문 포함·숫자·단위·시점·거래일을 검사하고, 별도 모델 검토가 의미·인과관계를
  검토한다. 같은 모델의 두 호출이며 사실의 완전한 독립 검증을 보장하지 않는다.
  기존 `news-brief-` 요청에는 전용 단일 실행 슬롯을 예약한다. 기존 뉴스·회사·Quant 슬롯,
  요청 ID·해시·영수증 경로와 인증 방식은 유지한다. 슬롯 변경 전의 불확실한 요청도 재실행하지 않는다.
  이 코드 경로의 실제 운영 자격은 새 이미지 설치와 정시 미리보기에서 별도로 확인한다.
- 새 회차는 입력 고정부터 발간 시각 이후 10분까지의 전체 85분을 공유한다. 단계별 고정 6분·16분
  타이머 대신 남은 후속 작업과 전송 여유 1분을 제외한 절대 종료 시각을 요청에 저장한다.
  앞 단계가 빨리 끝나면 다음 단계가 남은 시간을 이어 쓴다. 사실 정리 18분·작성 16분·검토 12분·
  보완 16분·최종 검토 12분은 후속 작업을 위한 예약량이며 각 호출의 고정 종료 제한이 아니다.
  예를 들어 정상 기준 시각에 시작한 선정은 후속 작업을 예약하고 약 10분을 쓸 수 있으며,
  선정이 3분에 끝나면 사실 정리는 약 25분을 쓸 수 있다. 정시 완료를 보장하는 수치는 아니다.
  대기나 재접속은 종료 시각을 늘리지 않는다. 런타임·HTTP·Temporal도 같은 종료 경계를 존중하며,
  기존 요청은 당시 제한과 해시를 유지한다. 첫 검토에서 문제가 확인되고 최종 검토까지 마칠 시간이

  처리하며 서로 다른 금액이나 뺄셈을 하나로 합치지 않는다. `-5.66%`와 `5.66% 하락했습니다`는
  명시된 하락 방향과 % 단위까지 대조한다. 공동 서술어가 붙은 하락률 나열도 검사하되,
  부호를 일괄 제거하거나 상승·단위 변경까지 허용하지 않는다. 날짜·단위·주장의 의미는 별도 원문 검토가 필요하며 숫자 일치만으로
  같은 사실이라고 확정하지 않는다.
  가상자산 24시간 변화는 한국 기준 관측일·정확한 시각을 사용하고 미국 증시 종가로 취급하지 않는다.
  중첩 JSON 인용문에 들어간 실제 줄바꿈은 내용 그대로 읽을 수 있지만 잘못된 구문·제어문자나
  계약 위반을 임의로 고치지 않는다. 연속된 공백·줄바꿈만 정규화해 고정된 기사 본문 또는 제목의
  연속 구간과 대조하며, 인용문 자체의 글자·문장부호 대조는 그대로 유지한다.
- 아침 미국 거래가 있으면 S&P 500·나스닥 종합 종가, 오후에는 코스피·코스닥 종가가 핵심이다.
  핵심 종가나 요약이 부족하면 `축약판`으로 표시한다. 빠진 값을 생성하거나 이전 날 값으로 채우지 않는다.
- PostgreSQL에 발간본·모델 요청·입력·검토·메시지를 저장한다. 날짜/판/채널/소유자별 ID가 고정된다.
  Temporal은 수집과 모델 작업의 타이머·재시도·복구를 담당한다.
- 수집은 `-brief-collection` queue, 작성·검토·검색은 기존 `-news-model` queue와 뉴스용 Codex 잠금을
  사용한다. 모델 슬롯은 늘리지 않는다. 준비 중에는 새 일반 뉴스 모델 작업을 미루되 이미 실행 중인
  요청을 중단하지 않는다. 일반 사용자·연구 업무의 기존 실행 자리는 유지한다.
- 회사 한도·구독 quota·전역 일시정지를 지킨다. 요청의 응답이 불명확하면 새 요청 ID로 재생성하지 않는다.
- 예정 시각 10분 후까지 검토가 끝나지 않으면 지연 안내를 축약판으로 확정한다. 검토하지 못한 초안을
  게시하거나 오후의 근거로 사용하지 않는다. 이후 늦게 온 모델 응답은 영수증만 보존한다.
- 한 시간 이상 지난 미발간 판은 `missed`로 남기고 연속 재발송하지 않는다. 오래된 미발송 메시지도 만료한다.
- 본문 Slack 성공 응답의 `ts`를 확보해야 상세 스레드를 생성한다. timeout·5xx·성공 응답의 `ts` 누락은
  `uncertain`이며 자동 재발송하지 않는다. 안정적인 ID는 상관관계 식별자이며 exactly-once 보장이 아니다.
- 사용자/채널 권한, 설정·출처 정책, 프로젝트 revision, 만료를 발송 직전 다시 확인한다.
  `@channel`·`@here`·자동 소유자 멘션을 넣지 않고 링크 미리보기를 끈다.

## 설정과 운영 준비

```dotenv
BRIEFING_ENABLED=true
BRIEFING_PUBLISH_ENABLED=false
BRIEFING_SEARCH_ENABLED=true
BRIEFING_CHANNEL_ID=C_ACTUAL_DAILY_BRIEF_CHANNEL
BRIEFING_OWNER_USER=U_ACTUAL_OWNER
```

채널 이름의 하이픈/밑줄로 추정하지 않고 실제 ID를 지정한다. 소유자·채널은 기존 허용 목록에도
추가한다. 서버 `roles.json`에는 패키지의 `market_brief` 역할만 병합하고 다른 직원의 설정을 보존한다.
모든 회사 프로세스에 같은 설정을 적용한다. `news-worker`가 브리핑 수집/작성도 실행하므로
Reporter를 끈 경우에도 `news-worker` 프로세스는 필요하다.
기존 `COMPANY_LAKE_URI`와 lake 읽기 자격 증명이 설정된 일반 `worker`가 `-brief-data` queue를
담당한다. 뉴스 worker나 모델 컨테이너에 lake 자격 증명을 추가하지 않는다.

[전용 앱 manifest](../slack-apps/market_brief.json)를 설치하고 Analyst를 해당 채널에 초대한다.
Socket Mode 앱 토큰에는 `connections:write`를 부여한다. 기존 비밀 저장소의 Slack 자격 증명 JSON에
`market_brief`의 `app_id`, `bot_user_id`, `bot_token`, `app_token`을 추가한다. HTTP Events를 쓰는 경우만
`signing_secret`이 필요하다. 토큰은 채팅·Git·Codex 컨테이너에 넣지 않는다.

특별 거래시간은 `BRIEFING_CALENDAR_OVERRIDES_FILE`에 JSON 파일의 절대 경로를 지정한다. 기본값은
없음이다. 등록 항목은 `market`(US/KR), `day`(YYYY-MM-DD), `closed`(boolean), `close_at`(시간대 포함
ISO 시각 또는 null), `source_url`(공식 공지 URL)이다. `closed=true`이면 `close_at=null`이고,
특별 개장일은 `closed=false`와 실제 종가 시각을 넣는다. 같은 날짜/시장 중복은 거절한다.
파일을 지정하면 모든 관련 서비스에 같은 읽기 전용 파일을 마운트한다. 승인된 배포 설정을 통해
변경하고 정규 브리핑 모델에게 캘린더 수정 권한을 주지 않는다.

기존 배포 절차로 마이그레이션과 프로세스를 갱신한다. 수집·역할 활성화와 게시 활성화를 분리하며,
운영자의 최신 발송 지시를 적용한다. 과거 미리보기는 발송 설정을 켜도 소급 게시하지 않는다.

## 명령과 데모

```bash
uv sync --frozen --extra lake
uv run quant-company slack-manifests --include-market-brief --output .local/briefing-apps
uv run quant-company briefing probe --output .local/briefing-source-probe.json
uv run quant-company migrate
uv run quant-company briefing collect
uv run --extra lake quant-company briefing data
uv run quant-company briefing review
uv run quant-company briefing preview
uv run quant-company briefing status
uv run --extra lake quant-company briefing data-probe --output .local/briefing-data-probe.json
uv run quant-company briefing qualify --output .local/briefing-qualification.json
```

`probe`는 공개 네트워크 연결 검사이며 DB·모델·Slack을 사용하지 않는다. `collect`는 일정상 준비
가능한 판의 자료를 수집한다. `review`는 준비된 검색/선정/작성/검토/보완/최종검토 단계 중 최대 한 번을 수행하며
실제 구독을 사용할 수 있다. 설정된 시간 창 밖에서는 대기한다. `preview`는 이미 저장된 최근
발간본을 읽을 뿐 모델 호출·게시를 수행하지 않는다. 상시 운전은 Temporal 워크플로가 담당한다.

`status`에서 `previewed`, 실제 outbox `pending/delivered/uncertain`, `missed`, 출처 오류와 핵심 지표
결측을 구분한다. 모델 장애는 `calls`의 고정 요청 ID로 조사한다. 결과 불명인 발송을 새로운 ID로
다시 만들지 말고 Slack과 outbox 영수증을 먼저 대조한다. 이번 버전에는 자동 재발행 명령이 없다.

실제 PostgreSQL·로컬 Temporal과 합성 시장 자료/모의 Slack을 사용하는 데모 검증:

```bash
TEST_DATABASE_URL=postgresql://DISPOSABLE_TEST_USER@localhost:5432/postgres \
  uv run pytest -q tests/test_briefing.py tests/test_briefing_temporal.py
uv run ruff check .
```

운영 품질은 최근 5거래일의 고정 입력 재현, 실제 발간, 핵심 종가·출처·검토·지연·축약 사유와
실제 전달 기록으로 점검한다. 10월 7일 사용자 지시에 따라 이 검증을 자동 게시와 병행한다.
미리보기/재현에는 자료 조회 시각을 보존해야 하며 오늘 조회한 문서를 과거에 수집한 것으로 바꾸지
않는다. 기간 관찰을 코드 테스트나 과거 날짜 fixture로 대신하지 않는다. 롤백은 `BRIEFING_PUBLISH_ENABLED=false`,
완전 중지는 추가로 `BRIEFING_ENABLED=false`를 모든 관련 프로세스에 적용한다. 이미 전송 중인
메시지는 취소를 보장하지 않는다. DB 백업에는 새 테이블도 포함된다.

`data`/`data-probe`는 lake extra와 기존 `COMPANY_LAKE_URI`·읽기 자격 증명이 있는 환경에서 실행한다.
`data-probe`는 다음 예정 판을 기준으로 실제 레이크를 읽고 숫자·날짜·지연을 검사한다. 모델·Slack·DB
게시를 수행하지 않는다. `qualify`는 최근 완료된 한국 5거래일의 아침/저녁 저장본을 읽어 원문·수치·
렌더링 재현, 핵심 지수의 수집/복수출처 여부와 실제 Codex 작성·검토 기록을 검사한다.
각 판에 예정·확정 시각과 지연 초, 핵심 지수 출처 수준, 결측·수집 오류와 빠진 입력 주제를 표시한다.
10분 넘게 늦거나 현재 편집·입력 선택 정책과 다른 판은 자격으로 인정하지 않는다.
보완을 사용한 판은 보완·최종검토의 실제 Codex 완료 영수증까지 필요하다. 합성 자료,
누락, 축약·충돌, 실제 모델 미확인은 통과로 세지 않는다. 이 명령은 발송 설정을 변경하지 않으며
Slack 실전송 인수와 사람의 내용 검토를 대체하지 않는다. 현재 포맷과 시장 전체 흐름·이슈 분석,
모든 원문을 다룬 검토 기록, 내용 범위·깊이·가독성의 통과도 필요하다.

실제 모델 출력의 재현은 `scripts/evaluate_briefing.py`로 한다. 이 스크립트는 회사 DB나 Slack에
연결하지 않는다. 요청/응답 파일과 원문 묶음을 고정해 검증 결과와 읽을 수 있는 Markdown을 만든다.

```bash
uv run python scripts/evaluate_briefing.py --bundle FROZEN_BUNDLE.json \
  --writer WRITE_RECEIPT.json --output EVIDENCE/draft
# draft/review-request.json을 기존 인증된 worker에서 한 번 실행해 REVIEW_RECEIPT.json을 얻는다.
# 기존 deploy/entrypoint.py를 거치며 --call은 공식 구독 런타임만 사용한다.
python scripts/evaluate_briefing.py --call EVIDENCE/draft/review-request.json --output REVIEW_RECEIPT.json
uv run python scripts/evaluate_briefing.py --bundle FROZEN_BUNDLE.json \
  --writer WRITE_RECEIPT.json --reviewer REVIEW_RECEIPT.json --output EVIDENCE/reviewed
# 확인된 실패의 보완 입력만 준비한다. 실행·정시 자격 부여는 하지 않는다.
uv run python scripts/evaluate_briefing.py --bundle FROZEN_BUNDLE.json \
  --writer WRITE_RECEIPT.json --reviewer REVIEW_RECEIPT.json \
  --prepare-revision --output EVIDENCE/repair-input
```

같은 파일명에 다른 결과를 덮어쓰지 않는다. 전송이 불명확하면 같은 요청 ID의 영수증을 확인하고,
새 ID로 다시 생성하지 않는다. 과거 자료 평가·정시 실제 발간·새로운 날의 검증은 별도로 기록한다.
