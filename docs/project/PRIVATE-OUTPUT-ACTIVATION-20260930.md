# 내부 연구 응답 교정 worker 적용 — 2026-09-30

소유자의 `승인할게` 응답으로 [PR #97](https://github.com/JJongAchii/quant-ai-company/pull/97)의
worker 적용이 승인됐다. PR은 연구 통합 브랜치에 병합됐고 승인된 코드
`0286ba3e7426ff6546b90e6926124ae65e71ba79`가 07:45:14 UTC(16:45 KST)부터 운영 중이다.
이미지와 설치 controller의 SHA-256, qdata pin을 [실제 전환 영수증](evidence/private-output-cutover-20260930.json)으로 확인했다.

`PINNED_COMPANY_WORKER_IMAGE`도 새 이미지로 갱신해 다음 앱 배포에서 사용할 pin을
보존했다. worker의 이전 이미지 표기는 `73fcfc3`였지만 내부 환경의 회사 pin은
`f2fa96f`였다. 새 worker는 이미지·환경·설치 코드가 모두 `0286ba3`다. 롤백에는 서버에
보존한 실제 이전 환경을 사용한다.

## 백업과 보존

진행 중 모델 응답을 배출한 뒤 기존 백업 도구로 DB·공개 설정·모델 완료 영수증·연구
파일·독립 qlab을 함께 백업했다. 별도 인증 파일은 포함하지 않았다. S3 백업 SHA-256은
`e252fc2f846e2f568f00d7241ef45d2d6c85702e4f95276c4732068e471513e7`다.
스냅샷 동안 기록을 쓰는 서비스가 잠시 정지됐다가 같은 컨테이너로 재시작됐다.

첫 적용은 마운트 보존 검사에서 secret 파일 참조를 일반 volume과 따로 계산해야 해
교체 전에 중단됐다. 별도 표현을 합쳐 실제 경로·쓰기 권한의 동일성을 확인한 다음
같은 백업을 검증해 재사용했다. 첫 임시 보류 단계의 출력 파싱 오류도 복구했고 최종
관측에서 `runtime_control.paused_until`과 `reason`은 모두 null이다. 실패를 이유로
모델 요청 ID를 바꾸거나 메시지를 재전송하지 않았다.

다른 컨테이너 ID와 역할·연구 profile·독립 qlab 설정 해시는 그대로였다. 별도 앱의
`5defb8c` release와 current 경로도 보존했다. 3070의 release, 입력과 평가기를 교체하거나
과학 job을 실행하지 않았다. [적용 후 상태](evidence/private-output-postcheck-20260930.json)

## 실제 연구 경로 확인

적용 후 데이터 task `14bf1d1f-16e7-5023-a281-0a045721d9ff`는 **1회차, 9 turn**으로
필수 패킷 파일과 인용 원문을 읽고 독립 평가를 완료했다. 이후 후보
`2733156b-0a7e-50dc-995c-93cf58bf114b`의 director 선정 단계가 시작됐다.
[읽기·응답 영수증](evidence/private-output-live-data-review-20260930.json)

이번 실제 응답들은 `say`가 비어 있어 새 교정 분기는 발동하지 않았다. 같은 시도에서
잘못된 안내 문장을 한 번 교정하고 완료 읽기·거절 응답을 보존하는 분기는 실제
PostgreSQL과 합성 모델의 회귀 검사로 검증했다. 관련 35개, 전체 1,342개 검사와 Ruff가
통과했고 46개는 실행 조건이 없어 skip했다. 이 수치를 실제 모델의 교정 성공률로
해석하지 않는다.

독립 데이터 판단은 `blocked`다. 고정 입력의 coverage는 확인됐으나 원본 객체·변환
계보와 역사적 공개/수집 시점 증명이 부족하다. 데이터 직원의 실제 호가·기업행사
지적은 이론적 평가의 주장 범위에 맞춰 director가 검토해야 한다. 승인 프로그램
digest와 예산은 유지됐으며 프로그램 미션은 0건이다. 심사 경로의 복구를 데이터
적격성 통과나 실험 개시로 보고하지 않는다.
