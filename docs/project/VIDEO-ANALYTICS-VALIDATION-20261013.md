# 영상 성과 분석 구현 검증 · 2026-10-13

소유자가 요청한 영상 성과 분석을 구현했다(설계: [ADR 0043](../adr/0043-video-performance-analytics.md), 운영:
[daily-video 성과 분석](../daily-video.md#성과-분석)). 공개 업로드를 제작 작업에 연결하고, 노출·CTR·조회·이탈·유입·
검색어를 고정 구간으로 측정한다. Claude 진단 카드와 월요일 리뷰를 성과 채널로 보내며, 소유자가 채택한 교훈만 새 영상
작업에 고정한다. 기본값은 `VIDEO_ANALYTICS_ENABLED=false`다. 2026-10-14에 운영 서버에 배포하고 실연결을 확인했으며,
2026-10-15 11:43 KST에 켰다([실연결](#실연결-2026-10-14), [켜기와 첫 카드](#켜기와-첫-카드-2026-10-15)).

## 검증한 동작 (새 테스트 74개)

- 제목 끝 회차 해석(아침·마감·연말·옛 접두어 거절), 같은 제목 대체 연결, 수동 link 유지
- 노출 보고서: CSV 열 검증, 백분율 표기 보고서 환산, 같은 날짜의 새 보고서는 교체, 오래되거나 반복된 보고서는 무시,
  유입 경로별 합산. 읽지 못하는 보고서 하나가 나머지를 막지 않음
- 태평양 시간 고정 구간 D+3·D+7·D+28, 구간의 모든 날짜에 노출 보고서 두 종류가 올 때까지 대기(최근 날짜부터 오는
  과거분, 따로 오는 유입 경로별 보고서), 4일 유예, 60일보다 오래된 업로드 제외
- 이탈 곡선 보간, 장면별 이탈 기울기와 가장 가파른 장면, 옛 회차의 챕터 대체, 렌더 manifest 장면 시각
- 기준선: 같은 회차 종류, 직전 28일, 5편 미만이면 기준 부족
- 분석 영수증: 고정 요청 ID, 회사 일일 호출 한도, busy 환불 후 같은 ID 재요청, 실행 중 재요청 때는 처음 고정한
  요청(프롬프트·썸네일·effort)을 그대로 다시 보냄, 계약 위반·실패 때는 수치만으로 카드 게시
- 제작 중인 회차가 있으면 분석 대기(영상 제작이 꺼져 있거나 6시간 넘게 멈춘 작업은 제외)
- 3일 카드 내용, 7일 갱신은 카드 수신 확인 뒤 스레드 답글, 과거 업로드는 카드 없이 측정
- 월요일 리뷰: 썸네일 첨부, 채널에 없는 영상을 근거로 든 제안과 없는 교훈 평가 제거, 버튼 렌더링, 재실행 없음
- 교훈 버튼: 소유자, 채널, 수신 확인된 리뷰 메시지 ts, 버튼 라벨, block에 묶임. 위조 7종과 미수신·다른 메시지 거절,
  재전달 멱등, 활성 상한, 은퇴
- 새 작업에 활성 교훈 고정, 꺼져 있으면 고정 안 함, 대본 작성 프롬프트 반영, 나중에 채택한 교훈은 기존 작업에
  반영 안 됨, 교훈이 없으면 프롬프트가 이전과 동일
- 설정 검증(전용 허용 채널, 소유자, YouTube 채널), Analyst interactivity, OAuth scope, 썸네일 호스트와 토큰
  미전송, 보고서 다운로드 호스트 제한, 꺼지면 outbox `stale`

## 실연결 (2026-10-14)

[기록](evidence/video-analytics-20261014/verification.json). Google Cloud 설정(API 2개, OAuth 앱 프로덕션 게시)을 마쳤다.
YouTube 재로그인(scope 3개, refresh token 있음)도 끝났다. 운영 서버의 17개 서비스가 main 5454e3d로 바뀌었고, 분석은
꺼진 채다. `sync --dry-run`으로 공개 업로드 9편과 Reporting 작업 2개를 확인했다.

10월 8일 마감 회차(10/8~10/10)는 조회 24, 시청 28분, 평균 2:11(46.6%), 좋아요 4, 댓글 2, 유입 6종으로
Studio 고급 모드와 모두 같았다. 성과 채널 `#video-performance`를 만들고 Analyst 봇을 초대했다.

dry-run에서 예전 제목 형식 3편이 회차로 읽히지 않았고, `[역사story]` 2편이 측정 대상에 들어 있었다. 둘 다 고쳤다
(예전 형식 해석, 다른 시리즈 제외, 테스트 3개 추가·1개 갱신).

첫 노출 보고서(`channel_reach_basic_a1`, 10월 12일치)는 16:59 KST에 왔다. 운영 파서로 읽은 7개 영상의 노출수와 CTR이
Studio 고급 모드의 같은 날짜 값과 영상 ID까지 모두 같았다(합계 122회, 3.3%). CTR 원본 값은 0~1 비율(0.2857 = 28.6%)이다.
과거분이 최근 날짜부터 와서, 스냅샷이 구간 마지막 날의 보고서만 보고 측정되면 앞 날짜의 노출이 빠진 채 고정되는 문제가
있었다. 유입 경로별 보고서는 합계 보고서보다 늦게 왔다(같은 시각 0건). 구간의 모든 날짜에 두 보고서가 모두 왔을 때
측정하도록 고쳤다(테스트 1개 추가, 1개 갱신, 1개 보강).

10월 15일 07:32 KST에 두 보고서의 과거분이 9/13~10/12까지 모두 왔다. 10월 8일 마감 회차의 3일 구간은 보고서 기준
140회, 클릭 5, CTR 3.6%로 Studio(138회, 3.6%)와 CTR이 같다. 날짜별로 보면 10/9(108회)와 10/10(9회)은 유입 경로까지 같고,
업로드 당일 10/8의 탐색 노출만 보고서 15회, Studio 13회로 다르다. 클릭은 모든 날짜·경로에서 같다. 파서는 CSV 값을 그대로
읽으므로, 카드에는 Reporting API 값이 나간다.

첫 tick은 11:48에 시작했다. 분석 큐를 받는 video-worker가 11:43에 다시 뜬 뒤였다. 업로드 11편을 기록했고, 이 가운데
시리즈 9편 중 6편이 작업에 연결됐다. 두 보고서 30일치를 반영했다. 3일 구간의 모든 날짜에 두 보고서가 있는 3편(10/7 마감,
10/8 아침, 10/8 마감)만 측정했다. 셋 다 Claude 진단을 거쳐 11:51~11:53에 `#video-performance`로 게시됐다. 10월 8일 마감
카드의 조회 24, 평균 2:11(46.5%), 노출 140, CTR 3.6%는 위 대조 값과 같다.

10/7~10/8의 예전 형식 3편은 작업 기록 이전에 만든 회차라 연결할 작업이 없다. 그래서 카드에 오프닝·장면 데이터가 없고,
진단이 그 빈칸을 `cold_open`, `scene_drops` 같은 내부 이름으로 언급했다. 연결된 회차(10/12 이후)는 이 데이터가 있다.
