# 직원별 지속 개선 경로 검증

2026-09-18. 구현·로컬 검증 완료, 운영 반영 및 외부 평가 모델 연결은 미실행.

직원별 현재 모델·절차·suite의 객관 평가 이력, 미평가 영역, 취약 유형과 다음 배정 이유를
`staff_status.development`에 연결했다. 같은 유형의 서로 다른 과제 3회 연속 통과 전까지 실패
피드백을 보존한다. 직원 순환·일일 2과제·업무 우선순위는 유지한다.

기존에는 합성 평가에서 실패한 직원의 절차 수정도 생산 업무의 실패/정상 요청 두 건이 있어야 했다.
이제 개선 BOT은 `staff_replay`로 해당 직원의 playbook 하나를 고치고 실제 기록된 실패와
서버가 미리 동결한 새 사례 두 건을 기존/수정 절차로 비교할 수 있다. 새 문제·정답은 수정자에게
공개하지 않는다. 코드 채점과 일반 CI를 통과한 수정만 검토용 PR으로 연결한다.

## 확인한 동작

- 실제 PostgreSQL에서 실패 기록 → 자동 개선 접수 → 새 문제 동결 → 절차 수정 → 도구를 사용하는
  기존/수정 풀이 → 객관 채점 → 검토 PR 경로를 검사했다. 모델/GitHub는 명시적 fixture다.
- 재시작과 모델 응답 저장 직후 중단에서 동일 응답을 재사용한다. 호출 예산 대기 시 추가 호출을 하지 않는다.
- 문제 이의, 권한/기준 변경, 새 문제·정답 변조, 판정 receipt 위조, 정상 경로 퇴행은 진행을 막는다.
- 기존 실패를 재현하지 못하면 `inconclusive`다. 새 사례를 두 버전 모두 맞힌 경우
  `transfer_advantage=false`를 남긴다. 수정안 통과가 일반적인 우월성 증거는 아니다.
- 한 번의 후속 통과, 다른 모델/절차의 통과, 중복 사례, disputed/blocked 기록을 섞어 약점을 해소하지 않는다.
- JSONB 왕복으로 키 순서가 바뀌어도 개선 담당의 중복 삽입된 절차를 일관되게 교체한다.
  평가 schema에 필드를 추가해도 기존 저장된 평가 계획의 digest는 그대로 검증한다.

## 아직 검증하지 않은 것

실제 직원의 장기 전문성 상승, 서술 품질, 외부 계열 모델의 평가 정확도, 이번 코드의 운영 배포.
22개 기존 문제 유형의 범위는 같다. 실제 업무의 새로운 문제와 독립 검토를 통해 이 범위를 확장해야 한다.
모델 가중치 학습, 새 유료 API, 직원 전원의 매일 평가로 전환하는 예산 변경은 수행하지 않았다.

외부 평가자의 후보·가격·동일 답안 비교 계획은
[독립 평가 모델 제안](STAFF-INDEPENDENT-REVIEW-PROPOSAL.md)에 별도로 정리했다.
