# Analyst 브리핑 구현·검증

2026-09-22. 사용자 요청에 따라 정기 브리핑과 후속 질문의 담당을 **Analyst(애널리스트)**로 전환했다.
첫 메시지만 읽어도 시장의 방향·핵심 원인·다음 확인 사항을 파악하도록 본문은 간결하게 유지한다.
운영 설정과 실제 Slack 앱은 아직 활성화하지 않았다.

## 담당과 분석 방식

- Slack manifest·역할 이름·본문 서명은 Analyst다. 내부 `market_brief` ID, 발간 기록, 스레드 연결,
  자격 증명 키와 07:30/20:00 KST 일정은 유지한다. 실제 설치된 앱의 표시 이름은 별도 운영 갱신이 필요하다.
- 핵심 이슈마다 사실·짧은 해석·다음 확인 조건에 더해 **경제적 전달 경로, 대안 설명, 영향의 시간 범위,
  인과 판단의 근거**가 필수다. 모두 원문 근거가 연결된 구조화된 분석 결론이며 숨겨진 사고과정을 요구하지 않는다.
- 전달 경로는 사건이 현금흐름·할인율·유동성·수요/공급 중 무엇을 통해 어떤 시장에 영향을 주는지 설명한다.
  보도의 설명, 자체 조건부 가설, 원인 미확정을 구분하고 다음 조건은 현재 판단을 약화시키거나 바꿀 수 있어야 한다.
- 분석 관점에는 예상 대비 차이/전기 대비 변화, 수정치와 기저효과, 명목/실질금리, 이익/밸류에이션,
  지수/시장 폭, 환산 효과/영업 노출을 포함한다. 근거가 없는 관점을 채우거나 목표가·확률을 생성하지 않는다.
- 본문에는 중요한 결론과 반대 근거를 자연스럽게 담는다. 상세 전달 경로·경쟁 설명·분석 시계는 스레드에 둔다.

실제 발송 코드로 만든 [합성 브리핑 예시](evidence/briefing-analyst-preview.md)는 본문 1,034자와 상세 한 건이다.
[고정 입력과 출력](evidence/briefing-analyst-preview.json)도 저장했다. 실제 시황이나 실제 모델 평가 결과는 아니다.

## 같은 절차, 명시적인 검토

[전문 절차](../../src/quant_company/staff/playbooks/market_brief.md)를 정기 작성·검토와 후속 대화에 전달한다.
정기 입력에는 절차 버전·digest와 과거 연습 피드백을 고정하며, 정책 digest에도 절차 버전을 반영한다.
모델이 근거를 설명하는 것과 근거가 실제로 맞는 것은 구분한다.

별도 검토는 숫자, 출처, 시점, 인과, 중요도/가독성, 반대 근거, 전달 경로, 대안 설명, 반증 조건의
아홉 항목을 모두 반환해야 한다. 누락된 검토는 통과하지 않는다. 분석 문장도 기존 인용문·숫자·ID 검사를
받고, 핵심 분석 문장이 탈락하면 이슈 전체를 제거한다. 검토자는 이에 의존한 요약 문장도 함께 거절해야 한다.
형식은 v3로 올렸다. 과거 v2 저장본은 보존하지만 새 분석 계약을 통과한 발간본으로 세지 않는다.

후속 질문에는 기존 공식자료 검색/읽기와 금융 계산 도구를 연결했다. 정기 작성·검토 중에는 고정 입력만
사용한다. 거래·모델 학습·자동 동료 위임·예약·설정 변경 권한은 추가하지 않았다. 금융전략 팀장 연결은
기존처럼 사용자 명시 요청을 따른다.

## 전문역량의 점검과 피드백

애널리스트를 기존 직원 평가 순환에 추가했다. 전체 일일 과제 수·호출 한도는 늘리지 않는다.
브리핑 준비 중에는 새로운 연습/설명 검토 모델 호출을 미룬다. 이미 실행 중인 호출을 취소하지 않는다.

| 사례 유형 | 수치 검사와 심어 둔 오류 |
|---|---|
| 거시 서프라이즈와 인과 | 컨센서스/수정 전월 비교, 수익률 bp 계산, 디스인플레이션/물가 하락 혼동, 동시 움직임을 유일 원인으로 단정, 명목/실질 혼동 |
| 실적·환율·시장 폭 | EPS 예상 대비 차이, 지수 등락, 상승 종목 비율, 전년 증가/예상 상회 혼동, 원화 방향, 수출주 무조건 수혜 단정 |

문제와 정답은 서버가 생성하고 정답키는 모델 프롬프트에 넣지 않는다. 수치·오류 누락·오탐은 코드가 채점하며
설명의 경제적 타당성은 별도 검토 대상이다. 과거 실패는 다음 발간 입력의 주의사항으로 전달하지만 시장 근거로
인용하지 않는다. 모델·절차·문제 유형별 이력과 아직 측정하지 못한 영역을 남긴다.

[공개 합성 사례와 미평가 프로필](evidence/briefing-analyst-practice.json)에는 정답키가 없으며 실제 모델 실행은
없었다. 이 자료로 전문성이 입증됐다고 주장하지 않는다. 실제 운영 이력은 총괄에게 문의하거나 다음 명령으로
확인한다.

```bash
quant-company staff status --employee market_brief
```

## 검증 범위와 남은 운영 확인

집중 검사 **85개 통과** 후 브리핑 우선순위 검사를 추가했고, 최종 전체 회귀는 **1,076개 통과·36개
건너뜀·실패 없음**이다. 린트·lock 검사와 wheel 빌드도 통과했다.

관련 통합 검사와 전체 회귀의 원본은 [집중 검사](evidence/briefing-analyst-targeted.xml),
[전체 검사](evidence/briefing-analyst-tests.xml), 최종 집계·파일 해시는
[검증 영수증](evidence/briefing-analyst-validation.json)에 기록한다.
실제 로컬 PostgreSQL과 Temporal을 사용하며, 모델·Slack은 테스트 응답이다. 분석 필수 항목, 부정확한
숫자·인용 거절, 가설의 사실 분류 거절, 이슈 단위 제거, 고정 절차의 작성/검토 전달, 피드백 경로,
정답키 비노출과 브리핑 우선순위를 검사한다.

새 모델 가중치 학습이나 전문가 자격 취득을 수행한 것은 아니다. 실제 구독 모델의 분석·사례 풀이,
독립적인 설명 검토, 실제 Slack 앱 갱신·전송, 운영 배포와 5거래일 실시간 관찰은 남아 있다.
현재 로컬 설정에는 회사 모델 runtime token과 전용 Slack 앱·채널/소유자 연결이 없고, 게시 설정은 꺼져 있다.
절차·테스트 통과만으로 실제 애널리스트 수준의 품질을 확정하지 않는다.

운영 절차는 [브리핑 안내](../briefing.md), 직무 평가 범위는 [직원 전문성 안내](../staff-development.md),
설계 결정은 [ADR 0036](../adr/0036-analyst-market-briefing.md)에 있다.
