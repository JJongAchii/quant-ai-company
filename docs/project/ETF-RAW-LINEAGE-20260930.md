# ETF 원시 본문과 연구 입력 계보 — 2026-09-30

승인된 835거래일의 원시 ETF 파일을 실제로 읽고 파일별 SHA256을 기록했다.
고정 qdata 변환 코드로 별도 정제 사본을 만든 결과, 승인 입력 8,350행의
시가·종가·거래대금·거래 가능 여부가 모두 일치했다. 조정가격은 종목별 기준을
맞춘 계열 형태가 일치한다. 준비 당시 정제 객체의 바이트와 과거 공개·수정
시점을 복구한 결과는 아니다.

원시 파일의 행은 해당 날짜의 전체 ETF다. 그 중 승인된 10종목의 행만 연구 입력과
대조했다. 종목 선정용 사본은 2022-12-29 이후 객체를 포함하지 않는다. 533개
유효 후보에서 기존 10종목을 다시 얻었으며, 새 종목이나 규칙을 채택하지 않았다.
원시자료의 숫자 값은 변경하지 않은 qdata builder가 읽고 정규화했다. 가격·메타
소비와 입력 대조는 고정 `qdata.api`를 통해 수행했다. 직접 원시 파일을 조사한
코드는 정제 전 중복을 숨기지 않도록 스키마·행 수·종목 키만 검사한다.

## 어떤 값이 연구 입력으로 변환되는가

| 원시 KRX 필드 | 고정 qdata 변환 | 회사 연구 입력 |
| --- | --- | --- |
| 파일명 거래일, `ISU_SRT_CD` | `date`, `ticker` | 거래일·종목 키 |
| `TDD_OPNPRC`, `TDD_CLSPRC` | 숫자 문자열·콤마·결측 표기를 정규화한 `open`, `close` | 시가·종가 |
| `ACC_TRDVAL` | 실제 거래대금 `value` | 유동성 선정·거래대금 |
| `FLUC_RT`와 종가 | 거래소 기준가격 등락률을 연결해 `adj_close`·`adj_factor` 생성 | 기준가격 조정 계열 |
| 이름, 거래량·가격·거래대금 | 레버리지·인버스 제외, 양수·유한값 검증 | 선정 자격·거래 가능 플래그 |
| 해당 원시 필드 없음 | 회사 생성기가 거래일 23:59 KST를 가정 | `available_at` |

이번 별도 정제 사본은 마지막 관측이 2025-12-30이다. 준비 당시 정제자료의 마지막
기준과 달라 `adj_close` 절대값 8,350개가 다르지만, 종목별 양의 상수배 관계와
기준을 맞춘 전체 계열의 일치를 확인했다. 이 8,350개 차이는 이전 **현재 S3
정제자료** 조회의 7,515개 차이와 별개다. 대조 기준은 가설·특징·라벨·신호에
사용하지 않았다. KRX 기준가격 조정 계열을 현금 분배금 재투자 총수익으로
표시하지 않는다.

별도로 생성한 입력 JSON 두 개는 감사 사본이다. 승인 입력 두 파일의 원래 해시는
유지됐으며 감사 사본을 실행 프로필이나 운영 입력으로 전환하지 않았다.

## 검증과 남은 공백

승인 범위 밖의 객체, 원본 변경, 잘린 다운로드, 정제 전 중복을 거절하는 로컬
검사 8건과 전체 Ruff가 통과했다. 이 검사는 가짜 S3 응답으로 실패 조건을 검사하며,
실제 AWS 다운로드·qdata 변환·운영 PostgreSQL 조회는 위 영수증으로 구별한다.
전략 성과·과학 시행·봉인 기간의 가격 행은 계산하거나 읽지 않았다.

첫 다운로드는 샌드박스 네트워크 연결 차단으로 835개 HEAD가 실패했으며 GET과
본문 읽기는 0건이었다. 이 실패와 당시 스크립트의 무조건적 본문 읽기 플래그 오류를
보존·명시하고, 성공 건수를 기록하도록 수정한 뒤 승인된 네트워크 접근으로
새 실행 디렉터리에서 완료했다.
[실패 원본](evidence/etf-raw-lineage-20260930/raw-body-download-network-rejection.json),
[정정 기록](evidence/etf-raw-lineage-20260930/network-rejection-note.json).

이번에 고정한 해시는 **현재 보관 중인 원시 파일**의 바이트를 증명한다. 모두
2026-07-29에 과거 날짜로 수집된 파일이며, 당시 거래일에 실제 공개된 버전이라는
증명은 아니다. 준비 당시 원시→정제 실행 명세·정제 객체의 절대 바이트도 미확보다.
다음 연구 실행 판단에는 역사적 공개·수정 이력 또는 그 공백을 처리하는 새로운
구체적 데이터 계약이 필요하다. 입력·계약을 바꾸게 되면 새 파일과 digest를 먼저
준비하고 서명된 소유자 승인을 받아야 한다. 현재 데이터 준비 승인은 내리지 않았다.
