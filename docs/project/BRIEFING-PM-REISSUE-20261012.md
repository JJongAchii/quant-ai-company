## 2. 수정 재시도 정책 (내일부터, briefing-final)

소유자 규칙: "재시도 시 잘못된 부분만 올바르게 잘 쓰면 되는거 아니야. 그럼 만료시각까지 쓰다가 그때까지의 글 기준으로
그냥 하는걸로 해."

- 작업 창: 예정 시각 + 10분 → 만료 시각 − 10분(예정 + 50분, `execution.final_at`). 모든 단계 마감, 재시도 여유 판단,
  마감 처리(flush)의 안전장치 발행 시각이 함께 옮겨졌다. 준비된 발간본은 지금처럼 바로 발행된다.
- 재시도: 단계당 최대 10회(실행기가 받는 `-r1`~`-r9`), 남은 시간이 있는 동안 계속한다. 불확실·시간 초과 응답도 새 시도
  번호로 다시 묻는다(그 영수증은 그대로 남기고 같은 요청은 다시 보내지 않는다).
- 수정 방식: 서버 검사에서 떨어진 초안은 다음 시도에 그 초안과 떨어진 규칙·세부 내용(예: 배치가 빠진 사실 ID와 원문
  인용)을 함께 보내 "고칠 부분만 고쳐 전체를 다시 내라"고 요청한다(`briefing/repair.py`). 초안만으로 고칠 수 없는 검사이거나
  입력 한도를 넘으면 예전처럼 전체 지시문 + 검사 이름으로 다시 묻는다.
- 발송기(dispatch)도 마감 처리(flush)를 돌리므로 news-worker와 dispatch에 같은 브리핑 파일 4개를 배포한다. 정책 다이제스트
  입력은 바꾸지 않았다(발송기의 메시지 검사와 호환).

## 3. 영상 렌더 실패 복구 (fargate7)

- 오후 영상(작업 `02a27a7c`, 안전장치 본문 기준)의 화면 검수 뒤 '화면 수정' 단계에서 모델이 그림 목록에 없는
  `bank-of-korea`를 장면 `bok`에 넣었다. 수정안은 그림 목록 검사를 거치지 않아 Fargate 3회와 서버 자체 렌더가 모두
  KeyError로 실패했다.
- 수정: 화면 수정안이 목록 밖 그림을 쓰는 장면은 원래대로 둔다(`apply_screen_fix(..., library, reverted)`). Claude 응답이
  불확실로 끝나도 한 번의 실패 시도로 보고 다음 시도로 넘어간다. 워커 `quant-company-video:7b37ac4-fargate7` 배포,
  멈춘 작업은 장면 `bok` 그림을 `rates-bonds`로 바꾸고 원격 렌더 상태를 비워 다시 렌더했다(복구 기록 테이블에 남김).
  재렌더는 Fargate Spot에서 정상 완료(20개 장면, 영상 2분 42초).
