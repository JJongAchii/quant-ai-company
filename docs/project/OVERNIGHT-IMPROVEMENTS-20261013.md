## 1. 브리핑 수정 단계가 건너뛰어진 문제 (news-worker·dispatch `briefing-final-1`, 23:39 배포)

- 원인(측정): 사실 목록이 확정된 회차의 '전체 재작성' 수정 요청에 원문별 메모가 두 번(약 4만 자) 들어가

  지적받은 부분만 고치는 문단 수정(editorial patch)으로 넘어가며, 이때 인용되지 않은 원문 행만 줄인다(검토가 가리킨
  원문 행은 유지). 오늘 2차본 실측 87,973자로 한도 안. 서버 검사에서 빠진 항목은 계속 빠진다.

- 00:54 `briefing-final-2`: 브리핑이 예정+50분까지 고치는 동안에도 뉴스가 모델을 기다리는 시간은 예전처럼

## 2. 영상: 이슈·해석 중심 (video-worker `fargate8` 23:39 → `fargate9` 00:08)

- 구조 검사에서 '처음 3장면 요약·5장면 안 시장판' 강제를 없앴다. 도입은 그날의 핵심 질문, 이슈 장면 4개 이상.
- 대본 지시: 무슨 일이 → 왜 중요한가 → 브리핑의 해석 → 다르게 볼 점 → 확인할 신호. 해석은 해석이라고 밝히고
  적극적으로 전달(매수·매도 권유·가격 예측만 금지). 시장판(등락률·수급)은 그날 뉴스일 때만.
- 독립 검토 기준도 같은 방향으로 바꿨다(시장판 요구 금지, 이슈 분석이 빈약하면 지적).
- 영상 제작 기준 문서 v1.1 (docs/DAILY_VIDEO_PRODUCTION_STANDARD.md §2).

## 3. 회차별 실제 사진 (fargate9)

- 대본의 그림 항목에 `PHOTO: <검색어> || SCENE: <대체 장면>`을 쓰면, 음성 전에 위키미디어 공용에서 자유 라이선스
  (CC0·퍼블릭 도메인·CC BY·CC BY-SA) 큰 사진을 찾아 16:9로 맞춘다(인물은 얼굴을 자르지 않고 흐린 배경으로 채움).
  후보는 Claude가 직접 보고(화면 검수 계약, 이미지 첨부) 맞는 것만 쓴다. 맞는 사진이 없으면 생성 그림, 그다음
  라이브러리 그림. 화면 칩 '자료사진 · 저작자 · 라이선스'와 설명란 '[자료사진 출처]'가 자동으로 붙는다.
- Fargate 렌더 이미지는 바꾸지 않았다(CloudFormation 갱신은 권한 검사에서 거부). 대신 워커가 업로드할 때
  회차 사진을 그 렌더의 라이브러리 사본에 '자료사진'으로 넣고 그림의 대체 자산으로 돌린다 — 기존 렌더 이미지가
  'AI 생성'이 아니라 자료사진으로 표시한다.
- 서버 실측: Commons API는 연락처 없는 파이썬 클라이언트를 로봇 정책으로 거부(403) → 채널 주소를 User-Agent에 넣었다.
  "Donald Trump official portrait"·"crude oil tanker"·"Samsung Electronics semiconductor" 검색과 내려받기·16:9 처리 확인.
- 예비용으로 검수한 실제 사진 28장(인물·기관·기업·에너지)을 라이브러리에 추가(31장, manifest 백업 보관).
- 통신사·언론사 기사 사진은 저작권 때문에 쓰지 않는다.
- 정정(10/13 아침): 대본 지시문이 등록 사진을 먼저 쓰게 되어 있어 첫 아침 영상은 회차별 검색 없이 예비 사진만 썼다.
  fargate10에서 회차별 PHOTO 요청을 먼저, 썸네일도 그 사진으로 바꿨다 —
  [BRIEFING-AM-REISSUE-20261013.md](BRIEFING-AM-REISSUE-20261013.md) §4.

## 4. qdata 정규장 확정치 (quant-data PR #49 — 병합 대기)
