## 확인한 동작

- 운영 서버: operator API → 실제 PostgreSQL·Temporal worker → 배포된 Codex → native 검색 →
  연준 공식 원문 3건 → 출처와 날짜를 포함한 한국어 분석까지 3개 직원 턴으로 완료했다.
  원문 바이트 해시를 대조하고 금리·시행일·정책 문구·날짜의 답변 근거를 수집 본문에서 확인했다.
  이 운영자 검증 프로젝트에는 Slack 채널이 없으며 테스트 메시지를 발송하지 않았다.
- 운영 상태: 기존 PostgreSQL 컨테이너를 유지했고 교체 전 백업을 S3에 저장했다. 서비스 7개,
  개선 BOT의 Temporal workflow, 배포·백업 타이머를 확인했다. 활성 직원 4명의 웹 도구가 켜져
  있으며 기존 모델·활성 역할과 호출 한도 설정을 보존했다.
- 직원: 실제 검색 이벤트 확인 → 공식 원문 3건 수집 → 프로젝트 출처 등록 → 원문 링크와
  발표일·수집 시각을 포함한 한국어 분석까지 3개 직원 턴으로 완료했다. 총괄의 실제 설정 모델
  `gpt-6-astra`와 ChatGPT 구독을 사용했다. 수집한 원문들의 발행 메타데이터가 없다는 점,
  본문 날짜와 수집 시각의 차이, 확인한 사실과 해석·미검증 항목이 답변에 구분되어 있다.
- 검색 실행기: CLI 0.154.0에서 `web_search="live"`만 켜면 실제 검색이 없었다. 검색 요청에
  한해 필요한 code-mode bridge를 함께 켜 실제 검색을 확인했다. 일반 모델 턴의 도구 권한은
  그대로 제한한다. 미실행 검색은 성공으로 저장하지 않는다.
- 개선 BOT: 코드 추가 조사 → 명시적인 새 기능·호출부·회귀 검사 작성 → 실제 pytest에서
  기존 기능 실패 → 해당 로그를 입력으로 두 번째 후보 수정 → 통과한 후보의 PR 경로를 검사했다.
  PostgreSQL과 pytest는 실제 실행이며, 이 검사에서 모델과 GitHub는 재현 가능한 fixture다.
  운영 BOT의 신규 코드 PR·배포를 실측했다는 주장이 아니다.
- 기준 보존: 원래 기능적 성공 기준은 후보 간 고정한다. 통과가 확인된 회귀 검사를 약하게
  바꾼 후보, 무단 파일·모델/권한 변경, 잘못된 CI head와 로그 리디렉션은 거절한다.
  검색의 중복 실행·일일 예약·프로젝트 변경 시 취소도 검사했다.
- 배포 결함: 자동 반영이 `roles.json`을 root 전용 `0600`으로 바꿔 UID 10001 서비스가 읽지
  못하는 문제를 파일 기반 정상 반영·rollback·중단 복구 세 경로에서 재현했다. 기존 소유자와
  권한을 보존하도록 수정했고, 운영 설정의 `0444`와 별도 복구 사본의 `0600`을 구별한다.

## 운영 범위

코드·Compose·활성 역할 설정을 함께 반영한다. `COMPANY_WEB_ENABLED`가 공통 컨테이너 환경에
전달되고, 활성 역할에 `web_search`·`web_read`가 있어야 한다. 기존 공식자료 도구는 유지한다.
provider와 설치된 반영 정책 변경은 소유자가 승인한 운영자 릴리스로 적용했다.
이번 인수는 서버의 실제 검색·분석 경로이며, 같은 요청의 Slack 재발송이나 개선 BOT이 새 코드
PR을 만들어 자동 배포하는 전체 과정을 새로 실측한 것은 아니다. 개선 BOT의 CI 재수정 경로는
실제 PostgreSQL·pytest와 모델/GitHub fixture로 검증했다. 새 코드 PR의 운영 반영에는 기존
사람 검토 절차가 적용된다.
현재 구현은 HTML/text이며 PDF·로그인·유료벽·자바스크립트 전용 본문은 지원하지 않는다.
