# Reporter: token efficiency and overnight delivery

User authorization: 2026-09-21, INTENT-v5 (71d4cd4616bb). Implementation/acceptance in progress.

The baseline is 331,430 input + output tokens in 56.92 minutes (eight Astra/high reviews and one search), not a daily average. Every review repeated six held originals alongside six new originals. Search alone consumed 93,448 tokens. Cached tokens are a subset of input; raw token totals and subscription credit weight are different measures.

The runtime will retain continuous free RSS/original collection. Luna/low screens up to 24 short leads every ten minutes by day and thirty minutes overnight. Uncertain importance stays eligible for the existing Astra/high editor; a screening result cannot authorize publication. The editor receives up to eight selected originals and explicitly related supporting originals (at most twelve originals total, with six supporting originals at most), bounded excerpts and the original 30-event history for duplicate detection. Independent discovery uses Luna/low, at most one requested native search per hourly call, and no overnight calls. Original/source/evidence/claim validation remains authoritative. Other staff models and Reporter replies are unchanged.

Automatic hot-news delivery uses Asia/Seoul, 06:00 inclusive to 24:00 exclusive. Both outbox claim and immediately-before-HTTP paths enforce this. RSS continues overnight. At 06:00 the editor begins draining overnight selections into verified publications. Once the frozen overnight input has been screened/reviewed, the collector assembles a durable daily collection and dispatch sends it. User work, verification and subscription availability can delay delivery past 06:00; this is not a promise of an instantaneous 06:00 message. An HTTP request started before midnight may finish after midnight.

No empty collection is sent. Normal nights produce one message; an unusually large collection continues in the same Slack thread to avoid a channel flood. Every item retains its individual event, original sources and review receipt; its outbox points to the actual aggregate Slack receipt. Questions in the collection thread can retrieve those sources. Follow-up events use the corresponding delivered thread. Unknown delivery outcomes stay unknown, with no individual resend fallback. Late originals arriving after the daily collection was frozen return to ordinary daytime processing. Expired or changed-policy publications remain in the audit trail and are not sent.

Validation must distinguish real PostgreSQL/Temporal with simulated Slack, real ChatGPT preview with zero Slack writes, and actual production automatic delivery. A natural midnight/06:00 observation cannot be claimed until it occurs. Measured savings on a matched article sample will be recorded separately and will not imply identical selection quality or a long-term quota guarantee.

## Qualification, 2026-09-21

[Real subscription preview](evidence/hot-news-efficiency-codex-preview.json) reused 24 actual new articles and six held originals from the first four expanded-feed reviews. Luna/low kept 13 and excluded 11; Astra/high completed three final reviews. In the initial 12-event preview, input + output fell from **116,734 to 77,389 tokens (33.7%)** in this sample. The final policy subsequently restored 30 historical events after a duplicate was observed; 33.7% is therefore **not a measured reduction for the final policy**. Cached input is not added again; reasoning-token metadata is not added separately. This is a preview comparison, not a production rate: the baseline included historical event context, while the disposable database had no prior events. Model selection and review context differ intentionally, and the historical-context difference prevents attributing all savings to the code change. No daily or subscription-quota percentage is promised.

Core monetary infrastructure, employment statistics, land regulation, maritime security and geopolitical candidates survived screening. A five-city grocery comparison pilot previously published was excluded as lower impact; insect-protein registration reached final review but was excluded there. Anonymous diplomatic and contested military claims remained held. The industrial-safety item was limited to expansion of inspections, excluding alleged violation counts and fatalities. This is a small, Korean-heavy sample, not a comprehensive news-recall evaluation.

The separate Luna search performed **one native search**, consumed **28,788 input + output tokens**, and added four registered-media URLs; two unregistered URLs were excluded. Its query/time differ from the previous 93,448-token search, so those numbers are not a matched search experiment. Search will also run half as often and only in daytime. No API credentials or extra subscription were used.

A [v1 preview failure](evidence/hot-news-efficiency-preview-repair.json) cost 22,677 tokens: the model correctly linked other supplied new articles, while the initial validator allowed held IDs only. The corrected contract permits only supplied primary/held references, forbids self-links, and retains original-evidence validation. The failed request was preserved; the new qualification was an explicit technical repair, not an automatic fresh-ID retry of an unknown inference. Successful preview writes to Slack: zero.

[Regression evidence](evidence/hot-news-efficiency-tests.json): 667 application/deployment/evaluation tests passed with real PostgreSQL and Temporal, two optional skips and one live exclusion. The final news regressions also cover copying subsequent event originals into the morning collection's question context. The workflow replays 409 pre-change production history events. Slack/model responses in these regressions are simulated. Natural midnight and 06:00 operation remain unobserved at this point.
