# Analyst `#daily-brief` 내용 자격 재검증 — 2026-09-28

Analyst 브리핑은 아직 **내용 자격이나 정시 발간 자격을 통과하지 않았다**. 올바른 Slack
워크스페이스의 기존 `#daily-brief`에는 Analyst 앱이 설치돼 있지만, 새 Lightsail 서버의
현재 릴리스에는 브리핑 역할이 없고 자동 게시도 꺼져 있다. 이 문서의 모든 본문은 당시
수집한 원문과 기존 구독 모델로 만든 **오프라인 평가**다. Slack에는 발송하지 않았다.

## 무엇을 통과해야 하나

첫 메시지만 읽어도 완료된 미국/한국장의 방향과 핵심 숫자, 어제와 달라진 사건, 그 사건이
가격·매출·원가·할인율 중 어디를 통해 어떤 시장에 영향을 주는지, 해석을 약화시키는
근거, 다음에 관측할 조건을 이해할 수 있어야 한다. 사건이 많은 날에는 이슈를 기계적으로
세 개로 자르지 않는다. 한 이슈를 여러 칸으로 반복하기보다 짧은 사실 문단과 자연스러운
해석·반대 근거를 이어 쓰고, 상세 인용과 보조 수치는 스레드에 둔다.

발간 판정에는 다음이 모두 필요하다.

1. 해당 마감 시각 전에 확보한 등록 원문과 시점이 확인된 수집 데이터만 입력한다. 과거
   판에 오늘의 레이크 상태나 검색 결과를 소급해서 넣지 않는다. 원문별로 반영한 고유 사실
   또는 제외 이유를 남긴다.
2. 작성 모델이 유효한 구조의 제안을 내야 한다. 각 수치·날짜·발언의 근거 인용, 계약월·
   거래소·정규장/장중 시점, 제안·합의·시행 상태를 코드가 검사한다. 오류가 있는 항목을
   잘라낸 뒤 내용이 비면 통과하지 않는다.
3. 검토 모델이 숫자, 출처, 시점, 인과, 중요도, 반대 근거, 전달 경로, 대안 설명, 반증
   조건, 원문 커버리지, 깊이, 가독성의 **12항목 전부**와 원문별 판정을 내야 한다. 빠진
   항목이나 중요한 사실의 누락은 `publish`가 아니다.
4. 모델 검토 뒤에도 응답을 보기 전에 적어 둔 원문 체크리스트로 본문을 별도로 대조한다.
   같은 모델의 자기 검토만으로 전문가 수준을 인증하지 않는다.
5. 통과한 내용이 실제 서버의 자료 수집·실행 시각·독립 지수 근거로 재현돼야 한다.
   최근 완료 한국 5거래일의 오전·오후 10개 판, 최대 10분 지연, 사람의 실제 내용 검토와
   전용 앱의 Slack 본문·스레드·수신 영수증을 확인한 뒤 게시를 켠다.

## 수리와 운영상의 한계

작성 지침은 중요 시한·금리의 이전 값과 새 값을 함께 밝히고, 같은 기사 속 별도 정책
담당자의 중요한 발언을 확인하며, 주장당 근거 1~4개를 지키도록 보강했다. 검토 스키마는
12개 항목을 전부 필수로 표시한다. 숫자 검증은 `$17.5m` 같은 달러 백만 단위, 방송 원문의
`one-thousand-358-point-two` 같은 소수, 두 종목이 공유하는 등락 동사를 좁게 처리한다.
실제 전날 장중 환율을 새날의 정형 관측으로 등록하는 오류는 계속 거절한다.

현재 코드에서 실제 PostgreSQL을 포함한 전체 회귀 **1,333개 통과·38개 건너뜀**, Ruff,
`uv lock --check`, `git diff --check`가 통과했다. 모델·Slack 모의 테스트와 위 실제 구독
응답은 구분한다. 실제 작성 한 건은 이번 사례에서 약 8~11분, 검토는 약 2분 걸렸다.
09/23 네 번의 성공한 호출은 643.730 + 110.634 + 542.742 + 149.940 =
**1,447.046초(약 24분 7초)**였다. 원문 수집·큐 대기·전송은 빠져 있다. 보완까지
필요한 날에는 07:10 입력 마감부터 07:30 목표 발간까지의 20분이 빠듯하므로
수집·대기·전송을 포함한 정시 관찰이 필요하다.

현재 서버 릴리스의 보호 파일 계약이 브리핑 포함 전체 릴리스를 거부한다는
[운영 인수 기록](ANALYST-PREVIEW-20260928.md)도 여전하다. 이 계약을 우회하거나
`BRIEFING_PUBLISH_ENABLED`를 켜지 않았다. 역사 사례에 독립 수집 지수 스냅샷이 없어
핵심 미국 지수는 단일 보도 근거인 경우가 있다. 과거 모델 시안이 통과하더라도
실제 5거래일·서버 배포·Slack 인수의 대체 증거가 되지 않는다.
