# 현재 사용 범위와 다음 완성 단위

기준: 2026-09-18. 운영 중인 첫 서비스의 확인 결과와 후속 구현 제안을 구별한다.

## 현재 사용 범위

- 활성 직원: 총괄·금융전략·국내연구·데이터. 글로벌·가상자산 등 나머지 직무는 정의만 있다.
- Slack 스레드별 요청, 동료 위임·회신·취합, 대화와 문서 저장, 업무 현황 조회.
- 메시지에 제공한 내용과 모델의 기존 지식을 바탕으로 설명·검토·연구 계획·문서 초안 작성.
- 제한된 산술 계산과 등록·승인된 출처 검색. 선정 공식자료의 후보 검색·실제 HTML 원문 읽기와
  출처·조회 시각 보존을 추가했다. 광범위한 금융 지식 저장소·전문성 시험은 미완료다.
- 데이터 담당의 S3 읽기 도구: 기존 수집 EC2가 발행한 데이터 목록·날짜 범위·스키마·소량 샘플.
  조회 결과는 실제 출처로 프로젝트에 저장한다. 원본 갱신·전체 커버리지 검사·연구 실행은 포함하지
  않는다. 실측 증거와 Slack 인수 상태는 `DATA-CONNECTION-VALIDATION.json`에 기록한다.
  실제 사용자 요청의 재조회·직원 산출물·최종 Slack 답변을 확인했다. 첫 시도의 출처 ID 누락은
  짧은 ID와 충돌 검사로 수리했으며, 일반적인 오류 자동 수리 기능을 구현한 것은 아니다.
- 실행 서비스가 새 요청에 직원별 모델·활성 여부·도구·한도를 전달한다. 이미 저장된 과거 요청은
  재시도 식별자를 보존하기 위해 바꾸지 않는다.
- 범용 웹 검색·원문 수집은 별도 구현 브랜치에서 실제 구독으로 검증했다. 운영 반영은
  `WEB-ENGINEERING-VALIDATION.md`를 따른다. 일반 직원의 저장소 수정, 3070 실행 제출, 백테스트·학습·거래는 미연결.
  서비스 수정은 아래 개선 담당의 제한된 PR 경로로 처리한다.
- AWS 단일 서버의 재부팅 복구·S3 복원을 검사했다. Slack·업무 실행·DB·Codex 인증은
  서버에 있어 맥북 종료와 무관하게 동작한다. 장시간 부하는 계속 관찰한다.

## GitHub와 개선 담당

- 정본은 비공개 `JJongAchii/quant-ai-company`다. `quant-workspace` PR #42는 이관 출처로 보존한다.
- 회사 서비스의 독립 CI를 연결했다. `quant-data`는 별도 저장소와 정확한 커밋으로 소비한다.
- 대화·오류 관찰→수정 제안→격리 CI→draft PR 경로와 GitHub App을 운영 중이다. 실제 문서 PR과
  Slack 승인 후 병합·완료 알림을 확인했다. 수정·테스트·PR은 자동, 운영 반영은 사람 검토 후다.
- 총괄의 보관 이력 조회·개선 진단 접수·진행 상태 도구를 연결했다. 진단은 현재 사람 요청에
  묶이며 같은 스레드로 상태를 알린다. 기존 호출 한도와 사용자·채널 접근 범위를 유지한다.
- GitHub 정리 때문에 회사의 맥북 독립 실행 상태가 바뀌지 않는다.

## 이번 후속 구현

- 같은 스레드의 후속 질문·조건 변경·중단·재개·확인 질문을 구분한다. 명확한 중단·재개·상태는
  모델 없이 처리하고, 지시 해석 중 이전 결과 게시를 보류한다.
- 공식자료 후보 검색과 실제 원문 읽기를 연결했다. KRX·FINRA·SEC Investor.gov·연준·BIS의
  허용 HTML URL을 읽고, 원문·조회 시각·관할·본문 해시를 저장한다. 선정 목록 검색이며 일반
  웹 검색 도구와는 별개다. PR #22·#24로 실제 범용 검색·원문 수집과 개선 BOT의 기능 구현·CI
  피드백 수리 경로를 운영에 반영했다. 서버에서 공식 원문 3건을 사용한 실제 분석을 확인했다.
  [웹 검색·개선 BOT 인수](WEB-ENGINEERING-VALIDATION.md)에 배포 커밋과 검증 범위를 기록한다.
- 실제 직원 협업과 중간 지시 변경의 운영 인수는 `CONVERSATION-FINANCE-VALIDATION.json`에 기록한다.
  CI·모의 HTTP·실제 원문·실제 구독·Slack 게시를 구분한다.

## 직원 전문성·지속 평가 — 2026-09-17 우선 구축

사용자의 최신 우선순위에 따라 첫 연구 실행 연결보다 직원 전문 절차·평가·개선을 먼저 구축했다.
전용 절차 11개, 금융/표본 품질 도구, 영속적인 정기 평가와 실패 피드백, 개선 BOT 접수 및
현황 조회가 구현됐다. 기본 일정은 KST 03시 이후 하루 2개 과제, 최대 3개 호출/과제다.
직무별 원래 모델과 활성 직원 4명은 유지하며 비활성 직무도 격리된 교육에 참여할 수 있다.

[실제 모델·운영 인수](STAFF-DEVELOPMENT-VALIDATION.md)와 [사용 방법](../staff-development.md)을 따른다.
합성 시험 통과는 종합 전문성 인증·실제 연구 수행·고빈도 실행 능력의 검증을 대체하지 않는다.
새 문제은행은 알려진 유형의 새로운 사례이며, 실제 업무와 전문가가 검토한 새 유형을 계속 추가해야 한다.

다음은 이 평가/개선 구조를 운영하면서 실제 연구의 데이터 확인·개발·독립검증 경로를 연결하는 것이다.
기존 KRX 데이터 계약과 연구 규약을 재사용하고, 신규 서버·모델 교체를 먼저 전제하지 않는다.

## 다음 순서

1. **운영 관찰**: 자연어 해석 오류·지시 변경·중단과 재개 사례를 모아 대화 제어를 개선한다.
   출처 링크가 실제 주장을 뒷받침하는지, 직원 간 요약에서 근거가 빠지지 않는지 확인한다.
2. **읽기 범위 확장**: 필요한 공식자료 카탈로그·PDF, 승인된 개인 연구 문서의
   검색·갱신 경로를 구체화한다. 지식 검색 기능과 실제 지식 축적·검증을 구별한다.
   기존 데이터 접근 계약과 문헌 규약을 사용하며 회사 자료 영역으로 범위를 넓히지 않는다.
3. **첫 연구 한 건 완주**: 구체적으로 승인된 연구를 데이터 확인 → 커밋된 코드 → 3070 실행 →
   결과 회수 → 해당 연구 단계의 검증 → 보고서까지 연결한다. 워커가 꺼져 있으면 대기 상태를
   보고한다. 5090·맥북으로 자동 전환하지 않는다. 연구 실행 범위는 별도 연구 승인을 따른다.
4. **전문성 검증과 확장**: 금융전략 직무 시험과 실제 연구 오류 기록을 바탕으로 지식·도구·모델
   배치를 개선한다. 첫 연구 경로가 동작한 뒤 글로벌·가상자산 담당을 활성화한다. 역할 이름이나
   프롬프트만으로 전문성·공개 시스템 대비 우월성을 주장하지 않는다.

다음 핵심 인수물은 **Slack에서 맡긴 실제 연구 1건의 재현 가능한 결과 보고서**다.
새로운 유료 데이터·API·서버 증설이 필요한 경우 구체적인 대상과 비용을 먼저 제시한다.

## 후속 로드맵 — 시장 브리핑·분석 BOT

2026-09-18 추가 요청에 따른 `hot-news`는 별도의 Reporter 앱으로 구현했다.
정기 발송 없이 약 10분 간격으로 수집하고, 원문 근거 검토 후 사건별로 게시하는 경로다.
2026-09-19 앱 설치·기존 서버 배포·실제 게시·스레드 답변·재시작 검사를 완료했다.
9월 21일 공식 발표만 수집하던 범위를 무료 언론 RSS 9개(BBC·CNBC·KBS World)와 공식 6개로
확장했다. 경제·금융, 거시, 세계 정세, 무역·에너지·공급망, 기업·산업·기술, 글로벌 주요 사건이
대상이다. 일반 보도는 매체 귀속을 표시하고, 추가 근거가 필요한 주장은 보류한다.
기존 구독 검색은 30분 간격으로 후보를 찾고 원문·날짜를 확인한다. 유료 API·새 구독은 없다.
[범위 복원 인수](HOT-NEWS-SCOPE-RESTORATION.md), [사용 방법·소스 목록](../news.md)을 따른다.
피드 조회, 새 기사, 편집 판단과 실제 Slack 전달을 구분하고, 매체·지역 편중과 누락률을
관찰한다. 정기 브리핑은 추후 `daily-brief`에서 진행한다.

2026-09-17 사용자 요청으로 추가했다. **기획 목록에만 등록하며, 구현·활성화는 추후 진행한다.**
위 연구 연결 순서를 바꾸거나 이번에 예약 발송·뉴스 구독을 시작하는 항목이 아니다.

| 기능 | 예정 동작 | 상태 |
|---|---|---|
| 아침 정기 시황 브리핑 | 매일 아침 Slack에서 국내·글로벌·가상자산의 전일 시장 흐름, 세계 경제 상황, 주요 뉴스를 요약한다. 주요 지수·금리·환율 등 변화와 그 배경, 당일 확인할 경제 일정도 정리한다. | 로드맵 등록, 미구현 |
| 요청형 시장 분석 | 총괄에게 시장 현황을 물으면 담당 BOT이 요청한 시장·자산·경제 주제를 조사하고, 핵심 변화·배경·시장 간 관계·주요 쟁점을 분석해 같은 Slack 스레드에 정리한다. | 로드맵 등록, 미구현 |

공통 요구사항은 출처 링크·자료 기준 시각, 관측 사실과 해석의 구분, 최신 자료가 없을 때의 명시다.
국내·해외의 전 거래일과 가상자산의 집계 구간을 구분해 서로 다른 시점의 수치를 섞지 않는다.
정기 브리핑과 요청형 분석은 같은 자료·근거를 재사용하되, 상세 직무·모델은 추후 설계한다.

구현 단계에서 아침 발송 시각(KST), 채널, 주말·휴장일 처리, 상세 시장 범위, 데이터·뉴스 제공처와
사용 권한·비용, 중복 발송 방지·누락 재처리 및 요약 품질 검증 기준을 정한다.
