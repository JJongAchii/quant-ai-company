# 검색 트렌드 스포츠 제외 적용

2026-10-06 사용자가 “누구 대 누구 처럼 스포츠 기사는 별로 보고싶지않은데”라고 요청했다.
경기 대진·결과·기록, 선수·구단·대표팀 소식과 이적 등 일반 스포츠를 제외하는 설정을
22:36 KST에 기존 운영의 `news-worker`와 `dispatch`에 적용했다.

전체 동결 후보를 먼저 분류하고, 스포츠를 제외한 순서대로 최대 8개를 고른다.
모든 후보가 스포츠면 그 사유를 안내한다. AI 분류가 마감까지 검증되지 않으면
미분류 항목을 생략하고 상태 안내만 보낸다. 편집 정책 버전 2를 발송 정책 digest에 포함해
이전 정책으로 만든 대기 본문을 발송하지 않는다.

실제 21:24 KST 자료와 저장된 구독 모델의 검증된 분류를 다시 사용했다.
14개 후보 중 한국 대 우즈베키스탄·삼성 대 KIA 등의 대진과 알카라스·최지만·김제덕 등의
선수 소식 10개가 제외됐다. 유해진·흑 상어·자녀·구축함 4개가 남았으며 출처·숫자·순서를 보존했다.
후순위 후보도 선택되는 것을 확인했다. [실제 자료 미리보기](evidence/trend-feed-sports-20261006/preview.txt)는
새 수집이나 새 모델 편집 결과가 아니라 기존 실제 자료의 필터 검증이다.

PostgreSQL·로컬 Temporal 회귀 36개와 Ruff를 통과했다. 회귀의 HTTP·모델·Slack은 모의다.
별도로 실제 운영 이미지의 입력·분류·원문 인용 검증과 필터 미리보기를 읽기 전용으로 실행했다.
새 모델·네이버·Slack 요청은 0개다. [종합 검증](evidence/trend-feed-sports-20261006/RESULT.json).

운영 중 다른 배포가 두 대상의 부모 이미지를 변경했다. 최신 실제 부모 이미지로 다시 자격검증했고,
검토한 편집기·저장소 두 파일의 변경 전 SHA가 같음을 확인했다. 최종 이미지는
`sha256:e036d78baa61b0072e8ed0c541ce5900452346e8c72a2d1723419d956d52832f`다.
220개 소스 중 `trend_feed/editor.py`와 `trend_feed/store.py`만 바뀌었고 부모 이미지 설정을 보존했다.
공유 compose 입력과 현재 실행 환경의 차이는 root 전용 설정 파일에서 실제 실행 환경을 보존해 처리했다.

첫 전환이 기존 읽기 전용 mount를 복구했지만, 엄격한 설정 동일성 검사가 이를 차이로 보고 중단했다.
새 워커의 설정에서 NAVER mount만 제거한 digest가 전환 전 digest와 정확히 일치했다.

검사는 파일 상태만 확인하고 키 값은 읽지 않았다. [연결 검사](evidence/trend-feed-sports-20261006/naver-mount.json).
