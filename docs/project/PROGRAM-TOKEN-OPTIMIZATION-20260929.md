이 수치는 단계별 중복 크기이며 호출별 토큰 절감량은 아니다. 한 제안 단계는 13번의

완료 응답은 과제 등록 검증에서 거부되어 새 시도를 시작했다. 실패한 원문 읽기가 비용을
키운 실제 경로다. [원시 집계](evidence/program-token-optimization-20260929.json)

## 변경

- 새 프로그램 단계의 `prior_tasks`에서 현재 `task`를 제거한다. 과거 과제에서는 원문
  인용문을 다시 복사하지 않고 출처 ID·위치, 과제 내용, 데이터 판단과 선정 사유를 보존한다.
  실제 원문은 기존 `evidence_sources` 파일과 읽기 영수증으로 검증한다.
- 제안 결과의 스키마·승인된 범위·현재 출처·정확한 인용문을 완료 처리 전에 검사한다.
  검증 오류는 같은 시도에 돌려주므로 이미 읽은 원문을 새 시도에서 다시 읽을 필요가 없다.
- 한 시도에서 제안 검증 오류가 세 번 발생하면 모델 요청을 더 만들지 않고 대기한다.
  원본 근거 또는 완료된 선행 연구가 바뀌어 단계 키가 달라질 때 새 단계를 시작한다.
  모델 응답, 원문 읽기, 오류와 보류 이벤트는 보존한다.

기존에 시작된 단계의 컨텍스트와 요청 ID는 바꾸지 않는다. 감사, 모델 선택, 공식 ChatGPT
인증, 연구 성과 판정과 전략 코드는 변경하지 않았다. 프로그램 단계의 시도 **안**에서 최근
원문 조각을 다시 싣는 전송 방식은 이번 변경 범위 밖이다.
