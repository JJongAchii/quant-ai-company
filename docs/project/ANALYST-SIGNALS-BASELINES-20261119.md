# Analyst 매매 신호 기준선 — 로컬·운영 레이크 (2026-11-19)

신호 성적표가 비교하는 기준선(항상 롱, 미국 따라가기)과 임시 신호 규칙(항상 롱)의 과거 적중률을 정리한다. 결정은
[ADR 0052](../adr/0052-analyst-daily-trading-signals.md), 설계는
[설계서](../superpowers/specs/2026-11-18-analyst-trading-signals-design.md)에 있다. 규칙은 결과를 보기 전에 정했고(2026-11-18),
조정하지 않았으며, 비용은 빼지 않았다. 아래는 과거 기록이고, 앞으로의 성적을 약속하지 않는다.

  `allow_exact_matches=False`).
- 수익률이 0이거나 포지션이 0인 날은 적중률에서 뺀다.
- 갭 반대(B1)는 그날 시가를 쓰므로 참고용이고 실행할 수 없다.
- 운영 실행에서는 점검을 겹치는 기간으로 좁히고 지수에 없는 날을 출력하게 했다(R20·R21, 규칙과 로컬 숫자는 그대로). 운영
  `krx_index`에 2026-09-04 행이 없어 그날의 KODEX 200 행 1개를 뺐고, 스크립트가 그 날짜를 출력한다.

오버나잇 항상 롱(KOSPI)은 구간을 나눠도 같았다: 로컬 2010–2017 59.4%, 2018– 59.4%, 2024– 60.7%, 운영 2016–2017 61.7%,
2018– 59.0%, 2024– 59.5%.

Yahoo 일봉과 공식 값 대조(로컬 출력 끝 두 줄): KODEX 200(`069500.KS`)은 2026-05-18~07-27의 48일 모두 시가·종가가 같았다.
KOSPI(`^KS11`)는 44일 종가가 모두 같았지만 2026-06-29 시가가 72.44bp 어긋났다. 그래서 KOSPI는 공식 레이크로, KODEX 200은
Yahoo 일봉으로 채점한다.

## 읽는 법

- 장중은 어느 기준선도 50% 근처이거나 그 아래다. 임시 신호(항상 롱)의 장중 과거 적중을 "약 50%"로 적는 근거다.
- 밤사이 정보는 대부분 시초가에 먼저 반영된다. 미국 방향은 갭을 75% 맞히지만 시가 이후는 47%만 맞힌다. 그래서 장중 신호는 "오늘
  오를까"가 아니라 "시가 이후 더 오를까"를 판단해야 한다.
- 오버나잇 항상 롱은 59~60%로 일정하다. 오버나잇 신호는 50%가 아니라 59%를 넘어야 의미가 있고, 임시 신호 문구도 "약 59%"다.
- 운영 레이크 결과는 로컬과 같은 결론이다. 신호 지시문과 임시 신호 문구의 숫자는 로컬 값 그대로 두었다.
- 진짜 적중률 55%를 우연과 구분하려면 약 600거래일, 60%라면 약 150거래일이 걸린다(단측 5%, 검정력 80%). 성적표가 p<0.05 전에는
  "아직 우연과 구분할 수 없음"이라고 쓰는 이유다.
- 운영 `krx_index`의 2026-09-04 같은 빈 날에는 KOSPI 채점이 "공식 자료 없음"으로 보류되고, 채점일 14일 뒤 "자료 없음 제외"가 된다.

## 실제 Codex 시험 시도 (2026-11-19, 실패 영수증)

[`analyst-signals-qualification-20261119.json`](evidence/analyst-signals-qualification-20261119.json)은 저장소 checkout에서
`scripts/qualify_signals.py --live --kind overnight --fetch-snapshot --synthetic-edition`을 한 번 돌린 영수증이다(코드
`3f111552`, 2026-11-19 23:27 KST, 11월 20일 오버나잇 칸). 일회용 로컬 PostgreSQL DB를 만들어 실제 신호 경로(아침판 같은 프로젝트,
`SignalStore` 예약·시세 고정·질문, `TurnExecutor`)를 탔고, 끝난 뒤 그 DB를 지웠다. Slack 전송기는 만들지 않았고 게시글도 없었다.
편집 본문은 시험용 합성 글이다. 시세는 Yahoo에서 실시간으로 읽었고, 11개 중 `KRW=X`는 응답의 심볼이 맞지 않아
(`chart_symbol_mismatch`) "빠짐"으로 처리됐다. 직후 같은 코드로 다시 읽었을 때는 11개 모두 정상이었다. **모델은 부르지 못했다.**
이 컴퓨터의 Codex CLI는 0.169.0이고 `CodexRunner`는 검증된 0.160.1(`src/quant_company/providers/codex_release.json`)만 실행하므로,
모델 호출 전에 `unavailable`로 거부했다(완료된 모델 턴 0, 제안 없음). 이 컴퓨터의 Codex 앱이 함께 쓰는 `~/.codex`에 다른 버전의
CLI를 돌리지 않으려고 다시 시도하지 않았다. 그래서 실제 모델 응답의 형식·지연 확인은 아직 없다. 운영자가 검증된 CLI로 같은 명령에
`--codex-bin <0.160.1 codex 경로>`를 붙여 한 번 돌리고 그 영수증을 `docs/project/evidence`에 남긴다.

## 실제 Codex 시험 (2026-11-20, 통과)

[`analyst-signals-qualification-20261120.json`](evidence/analyst-signals-qualification-20261120.json)은 같은 명령에
`--codex-bin`으로 검증된 Codex CLI 0.160.1을 붙여 한 번 돌린 영수증이다. 코드는 main `2a132c5`와 같은 트리이고, 2026-11-20
10:4x KST에 11월 20일 오버나잇 칸으로 돌렸다.
- CLI는 작업 컴퓨터의 임시 폴더에 설치했다. npm 무결성 해시가 `codex_release.json`의 값과 같다.
- 로그인은 이 컴퓨터의 Codex 앱이 쓰는 `~/.codex`가 아니라, ChatGPT 인증 파일만 복사한 별도 `CODEX_HOME`으로 했다. 실행 중 토큰이
  갱신되지 않게 했고, 시험 뒤 복사본을 지웠다. API 자격 증명은 쓰지 않았다.
- 모델 `gpt-6-astra`가 턴 세 번(10.3초·25.2초·20.9초, 합계 약 56초)에 답했다.
  - 첫 턴은 시세 스냅샷을 `read_source`로 읽었다.
  - 둘째 턴의 답은 근거 하나가 200자를 넘어 형식 오류였다.
  - 서비스가 도구 없이 다시 묻자 셋째 턴에서 통과했다(`format_failures` 1).
- 결과는 정시 커밋이었다. 오버나잇 숏, 확신도 52%, 근거 세 개(모두 스냅샷 인용), 틀렸다고 볼 조건이 들어 있다. 신호 글은 일회용 DB의
  보내지 않은 outbox 행으로만 남았다. Slack 전송기는 만들지 않았고, DB는 지웠다.
- 이 시험은 계약과 지연의 확인이다. 신호 방향이 맞는지에 대한 증거가 아니다.
- 근거 200자 초과로 다시 묻기를 한 번 썼다. 운영에서도 자주 나오면 지시문에서 길이 제한을 더 앞에 둔다.

## 확신도 계산 시험 (2026-11-24, 통과)

확신도를 Analyst가 고르지 않고, 반반 50에 오늘 근거별 점수를 더해 서비스가 계산하도록 바꾼 PR 브랜치에서 돌렸다
([ADR 0052](../adr/0052-analyst-daily-trading-signals.md)).
- 영수증은 [`analyst-signals-confidence-qualification-20261124.json`](evidence/analyst-signals-confidence-qualification-20261124.json)이다.
  - 코드는 main `2aacc0c` 위에 커밋 전 변경을 얹은 작업 트리였다. 영수증에는 `uncommitted_code: true`로 남았다.
  - CLI·로그인·일회용 DB·Slack 전송기 없음은 11-20 시험과 같다. 인증 복사본은 시험 뒤 지웠다.
- 운영 DB에서 읽기만 해 가져온 11-24 오버나잇 스냅샷(15:00 고정)으로 11-24 오버나잇 칸을 돌렸다.
  - 턴 한 번(37.5초), 형식 오류 없음, 정시 커밋이었다. 자리 표시만 있는 형식 틀을 따라 적지 않았다.
  - 근거 점수는 +3(미국 선물 강세), +1(원화 강세), −2(코스피가 이미 +7.39%라 종가 뒤 새 재료가 없음)였다.
  - 확신도는 52%(반반 50%에 오늘 근거 +2%p), 방향은 롱이다. 반대 근거를 음수로 적었다.
- 스냅샷 시각과 시험 시계는 맞다. 다만 실제 시각은 16:3x라 도구를 썼다면 15:00 뒤의 기사를 볼 수 있었다. 이번에는 도구를
  쓰지 않았다.
- 실행 노력은 역할 기본값 `high`였다. 운영 Analyst는 모델 배정 rev 6의 `gpt-6-astra` `xhigh`다.
- 같은 날 과거 적중률(오버나잇 롱 59)에서 출발하는 첫 안으로도 두 번 돌렸다. 두 번 다 근거 점수가 0이라 확신도가 59%(롱)에
  머물렀고, 소유자가 그 안을 거절해 영수증은 남기지 않았다.

## Claude Fable 5.2 신호 시험 (2026-11-24, 통과)

신호 턴을 Claude Fable 5.2로 돌리는 PR 브랜치에서 같은 스크립트를 `--claude-bin`으로 한 번 돌렸다.
- 영수증은 [`analyst-signals-fable-qualification-20261124.json`](evidence/analyst-signals-fable-qualification-20261124.json)이다.
- 실행기는 운영과 같은 `ClaudeRunner`다. 정확한 버전과 구독 로그인 사전 점검, 명령 인자, 결과 검증이 운영과 같다. Fable용 CLI는
  작업 컴퓨터의 Claude Code 2.1.328이다. 운영 이미지에 넣는 `claude-next`와 같은 버전이다.
- 로그인은 운영과 다르다. 운영은 격리된 로그인 디렉터리(`CLAUDE_CONFIG_DIR`)를 쓴다. 시험은 이 컴퓨터 CLI의 기본 구독 로그인(macOS
  키체인, `USER`로 찾음)을 썼다. 시험 실행 중에만 그렇게 바꿨다. API 자격 증명은 쓰지 않았다.
- 입력은 Codex 시험과 같은 11-24 운영 오버나잇 스냅샷(15:00 고정)이고, 지시문은 "오늘 근거로 계산하는 확신도" 버전이다.
  - 턴 한 번(32.3초), 형식 오류 없음, 정시 커밋이었다. 같은 입력의 Codex 시험은 37.5초였다.

    급등 직후라 밤사이 되돌림 위험)이었다. 확신도는 54%(반반 50%에 오늘 근거 +4%p), 방향은 롱이다.

  운영 Dockerfile의 고정 값(`1e08503d…`)과 같았다. 2.1.328은 `a982d380…`이다.
