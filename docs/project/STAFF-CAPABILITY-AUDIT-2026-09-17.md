# 직원별 전문성 점검

점검일: 2026-09-17. 사용자 우선순위: 첫 연구 연결에 앞서 각 직원의 능력·지식·스킬을 확인한다.

## 결론

현재 구현은 **직무·권한·협업 경로가 있는 초기 직원 조직**이다. 분야별 전문 지식과 실행 스킬을
충분히 갖추고, 독립적인 직무 평가로 실력을 입증한 조직까지 완성된 것은 아니다.

활성 직원 4명과 별도 개선 서비스가 있다. 나머지 6개 직무는 설정만 있고 비활성이다.
직무 설명, 모델 이름, 검색 성공, CI 통과, 업무 완료 상태만으로 전문성을 입증할 수 없다.
직원이 특정 문제를 못 푼다는 판정도 이번 점검으로 내리지 않는다. 미평가와 도구 미구현을 구별한다.

이번에는 소스·실행 설정·운영 DB의 집계·기존 검증 기록을 읽었다. 새 모델 시험, 연구·백테스트,
직원 활성화, 모델/권한 변경, 운영 배포는 실행하지 않았다.

## 2. 스킬은 어디까지 전달되는가

직원에게 전달되는 것은 해당 역할의 `mission`·`instructions`, 도구 목록, 제한된 업무 맥락이다.
회사 코드에는 직원별 SKILL 묶음을 등록·선택·버전 고정해 전달하는 경로가 없다.

Codex 실행기는 호스트 스킬 탐색을 끄고(`skip_host_skill_discovery=true`), 프로젝트 문서 읽기를
끄며(`project_doc_max_bytes=0`), 새 임시 작업 디렉터리에서 실행한다. 사용자 설정·MCP·하위
에이전트·Codex 내장 기억도 꺼져 있다. 이는 서비스 실행 경계를 제한하는 의도된 설정이다.

그러므로 이 작업공간에 있는 `krx-data-contract`, `backtest-hygiene`, `strategy-discovery`,
`experiment-log`, `strategy-report` 등의 전문 절차가 **서버 직원에게 자동 상속되지 않는다**.
현재 데이터 직원의 시점·단위 지침 같은 일부 원칙은 역할 프롬프트에 있지만, 해당 스킬 전체와
실행·검증 도구가 연결된 것은 아니다. 호스트 설정 전체를 풀어주는 대신, 필요한 절차와 도구를
직무별로 명시적으로 연결하는 구현이 필요하다.

## 3. 실제 축적된 지식과 기억

15:43 KST 운영 DB 집계:

| 항목 | 저장 건수 | 해석 |
|---|---:|---|
| 회사 운영 상태·이력 출처 | 22 | 금융 전문 지식 문서 수로 세지 않는다 |
| 데이터 레이크 조회 출처 | 11 | 메타데이터·표본 조회 기록이며 데이터 전수 검증과 다르다 |
| 공식 금융 원문 출처 | 2 | 업무에 묶여 저장된 원문 출처 등록 수 |
| 전사 공유 실제 출처 | 0 | 테스트용 가상 공유 출처 1건은 제외 |
| 직원 장기 기억 | **0** | 제안·검토 완료·공유 기억 모두 없음 |

이 수는 기반 LLM이 사전학습한 금융 지식의 양을 뜻하지 않는다. 회사가 별도로 축적하고 검토한
자료의 현황이다. `sources.approved`는 서비스가 사용할 수 있는 출처 등록 상태이며, 원문의
모든 주장이나 직원의 해석이 참으로 검증됐다는 인증이 아니다.

`knowledge_search`는 접근 가능한 출처 제목/본문의 문자열 검색이며 최대 5개를 반환한다.
직무별 전문 문헌 색인·개념 관계·반례·유효기간/정정 추적을 갖춘 검색 시스템은 아니다.
입력 맥락은 최근 메시지 35개, 출처 메타데이터 50개, 검토된 기억 15개, 산출물 요약 5개로 제한되며
전체 크기에 따라 더 줄어든다. 모든 경험을 항상 기억하는 직원으로 해석하면 안 된다.

기억 제안→운영자 검토→공유 경로는 코드에 있다. 그러나 실제 기억이 0건이므로 경험을 지식으로
정리하고 다음 업무에 재사용하는 과정의 운영 실증은 없다. 프로젝트 전용 출처는 그대로 공유
기억의 근거로 승격할 수 없다. 별도의 접근 범위·출처 검토가 필요하다.

회사 서비스에서 직원별 추가 학습/파인튜닝을 수행한 경로·기록도 확인되지 않았다. 대화가 DB에
남거나 프롬프트가 수정되는 것과 모델의 가중치가 학습되는 것은 구별한다.

## 4. 무엇이 검증됐고 무엇이 미평가인가

**실행 증거가 있는 범위:** 실제 모델의 직원 위임·회신, 공식 원문 읽기와 데이터 메타데이터 조회,
중간 지시 변경, Slack 게시와 총괄 태그, 일부 개선 문서 PR·승인 적용, 서버 백업·복구 경로.
PR #22의 별도 기록에는 실제 구독 모델의 웹 검색·원문 읽기 로컬 인수도 있다.

**전문성 시험은 미완료:** `evals/financial-cases.json`에는 공개 개발 예제 9개가 있다. 5개는
가상 산술, 4개는 시점·현재성·반복 주장·문서 지시 처리다. 테스트는 예제 정답과 형식을 확인하며
LLM을 호출하지 않는다. 실제 직원의 미지 문제 평가·모델 간 동일 조건 비교·독립 전문가 대비
시험 성적을 확인하지 못했다. CI 수백 개 통과를 금융 실력 점수로 읽으면 안 된다.

계산 도구는 제한된 사칙연산과 정수 거듭제곱이다. 채권 곡선/볼록성·옵션 Greeks·회계 연결 조정·
포트폴리오 위험·고빈도 체결의 전문 도구와 심화 평가가 이미 제공된 상태는 아니다.

기존 작업 완료 건수나 답변 수 역시 실력 점수로 변환하지 않았다. 운영 인수 기록 자체도
금융 전문가 시험·연구 성과 검증을 수행했다고 주장하지 않는다.

우선 기존 활성 직원과 첫 연구에 필요한 개발·검증 직무부터 결과 기준을 구체화한다. 각 직원에게
**책임지는 결과 → 필요한 지식 → 실행 절차 → 도구 → 별도 평가 문제 → 실제 업무 근거**를 묶는다.
평가에는 일반 모델과 같은 조건의 비교도 포함하고, 수정에 사용한 사례와 미지의 평가 사례를 나눈다.
기준·채점 근거를 먼저 정하고, 미실행 결과를 점수로 채우지 않는다.

특정 모델로 일괄 교체하거나 직책만 추가하는 결정을 이번 점검에서 내리지 않았다.
“누구보다 뛰어나다”는 전 분야 비교 기준이 없으므로 보증할 수 없다. 맡긴 업무에서 관찰 가능한
정확성·재현성·오류 발견 능력을 지속적으로 입증하는 것이 실제 구축 목표다.
