# Market Briefer 구현·인수 기록

이 문서는 첫 구현(v1)의 검증 기록이다. 수집 시장 데이터 통합, 저녁 20:00 일정, 읽기 쉬운 본문과
강화된 검토는 후속 [품질 개선 기록](MARKET-BRIEFER-QUALITY.md)이 현재 기준이다. 아래 검사와 해시는
당시 구현을 식별하는 역사 기록으로 보존한다.

기준: 2026-09-22. **구현 완료, 자동 게시 비활성, 운영 인수 전**이다.
사용자의 `Implement the plan.` 요청에 따라 독립 회사 worktree에 구현했다.
설계·설정·데모·복구는 [운영 안내](../briefing.md), 결정은 [ADR 0035](../adr/0035-market-briefer.md)에 있다.

## 구현 범위

- 전용 `market_brief` 역할과 Slack 앱 manifest. Reporter는 속보, 금융전략은 연구 팀장 역할을 유지한다.
- KST 07:30 아침판, 한국 정규장 마감 + 50분 오후판. 휴장·주말·서머타임·조기폐장과 공식 공지에
  따른 날짜별 거래시간 override를 반영한다. 월요일 전망과 토요일 주간 복기는 기존 아침판에 포함한다.
- 기존 등록 뉴스 원문 재사용, 제한된 공개 수집·선택적 구독 검색, 고정 입력, 작성·별도 검토,
  숫자·출처·단위·거래일 검사, 본문과 최대 두 개 상세 스레드.
- 오후판의 오전 관찰 문장 보존과 점검, 동일 스레드 후속 질문, 사용자가 명시한 금융전략 검토 연결.
  Briefer 모델의 동료 위임·예약 업무·지속 기억 제안은 허용하지 않는다.
- PostgreSQL 기록과 Temporal 타이머, 기존 뉴스 모델 슬롯 공유, 호출 한도·일시정지 준수.
  모델·Slack 응답이 불명확하면 영수증을 보존한다. 본문 전달 영수증 없이 상세 스레드를 만들지 않는다.
- 예정 시각 + 10분 검토 마감과 축약 안내, 1시간 초과 누락 처리, 과거 미리보기의 소급 게시 방지,
  발송 직전 권한·정책·revision·만료 재검사.

## 검증 증거와 범위

[테스트 원본](evidence/briefing-tests.xml)은 실제 로컬 PostgreSQL과 Temporal을 사용한 회귀 결과다.
전체 회귀 **1,045 통과·36 건너뜀·실패 없음**이다. 상태 조회의 본문 제외·수집 오류 표시를 마무리한 뒤
[관련 회귀 107개](evidence/briefing-final-regression.xml)도 통과했다. 린트, lock 검사와 wheel 빌드가
통과했고 wheel에 브리핑 코드·SQL·전용 절차가 포함됨을 확인했다.
집계·실행 환경·변경 파일 해시는 [검증 영수증](evidence/briefing-validation.json)에 기록한다.
시장 자료, 모델 응답과 Slack HTTP 응답은 합성/모의다. 실제 Codex·Slack·클라우드 배포를 검증한
것으로 해석하지 않는다. 명시적 opt-in이 필요한 실제 구독 검사와 선택적 연구 통합 검사는 건너뛴다.

```bash
uv run pytest -q tests deploy/test_deployment_contract.py evals/test_financial_fixtures.py \
  --junitxml=docs/project/evidence/briefing-tests.xml
uv run ruff check .
uv lock --check
```

브리핑 검사는 다음 실패 경계를 포함한다.

| 경계 | 확인 내용 |
|---|---|
| 수집 | 현 정책의 최신 원문 재사용, 마감 후 자료·미확인 발행일·무단 redirect·검색 snippet 제외 |
| 편집 | 인용문·숫자·시점·단위·전 거래일 검사, 검토 탈락 시 핵심 지표 결측과 축약 표시 |
| 동시성 | 같은 판의 호출 예약·확정 중복 방지, 수집과 검색 완료 경합 시 고정 검색 인자 보존 |
| 복구 | quota 뒤 같은 요청 재사용, 마감 후 응답 제외, 불명 모델 영수증 보존, 장기 중단 시 backlog 미발송 |
| Temporal | 실제 worker의 작성→검토, history replay, timer 생성 후 worker 재시작과 계속 실행 |
| Slack 모의 | 본문 영수증→상세, 질문·명시적 팀장 연결, timeout·5xx·ts 누락 시 재발송 금지 |
| 정책 | 기본 비활성, 한도·일시정지, 게시 직전 설정 변경 거절, 미리보기의 소급 게시 방지 |

[공개 소스 연결 검사](evidence/briefing-source-probe.json)는 실제 네트워크 응답이다.
CNBC 4개·연합뉴스 2개 피드 및 연준·BEA·한국은행 페이지에 접근했다. BLS 일정 페이지는
`http_status` 오류로 실패했다. 이 검사는 연결 여부만 확인하며 핵심 종가 확보율, 원문 의미,
발간 품질이나 실시간 5거래일 인수를 입증하지 않는다.

로컬 [설정 존재 여부 검사](evidence/briefing-environment-check.json)에서 회사 Codex runtime token,
전용 Slack 자격 증명 경로, 브리핑 채널/소유자가
설정되지 않았다. 자격 증명 파일을 복사하거나 다른 인증 경로로 우회하지 않았다.
새 비용·서버·모델 슬롯은 추가하지 않았다. `exchange-calendars`와 필요한 의존성을 lock에 추가했고,
기존 선택적 `qdata` 메타데이터는 유지했다. 실제 서버의 장시간 메모리·부하는 아직 확인 전이다.

## 운영 활성화에 남은 조건

1. 전용 앱 설치·채널 초대·허용 목록·서버 역할/비밀 설정을 연결한다.
2. 기존 서버에서 게시를 끈 채 실제 자료와 실제 구독 모델의 작성·검토를 확인한다. 핵심 종가,
   정확한 시간·거래일, 원문 인용, 일정 누락, 작성 지연과 축약 사유를 매 판 기록한다.
3. 실제 5거래일 미리보기와 그 기간 저장된 입력의 재현을 기록한다. 과거에 저장한 적 없는 자료를
   오늘 조회해 과거 수집으로 표시하거나 합성 날짜 테스트를 실시간 관찰로 계산하지 않는다.
4. 실제 Slack의 본문·상세·질문·명시적 검토 요청과 재시작 후 전달 기록을 확인하고 게시를 활성화한다.

현재 `BRIEFING_ENABLED=false`, `BRIEFING_PUBLISH_ENABLED=false`가 기본값이다.
이 기록은 앱 설치, 운영 배포, 실시간 5거래일 관찰 또는 자동 발송 완료를 의미하지 않는다.
