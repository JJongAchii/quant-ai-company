# 직원 설계 — 금융 지식과 연구 능력을 실제로 축적하는 방법

- 작성: 2026-09-16
- 상태: 직무 10개·활성 역할 4개와 별도 개선 서비스. 전용 절차 11개·금융/품질 도구·정기 직무 평가를 구현했다.
  종합 전문성·실제 연구 실행 완주는 별도 검증 범위다. 실제 모델/배포 인수는 프로젝트 검증 기록을 따른다.
- 구현: [직무·도구·시험 범위](../financial-specialist.md), [지속 교육·평가](../staff-development.md).
- 상위 설계: [ARCHITECTURE.md](ARCHITECTURE.md)

## 1. 전문 BOT의 구성

전문성을 다음 일곱 요소로 정의한다.

1. **직무와 책임:** 어떤 질문과 산출물을 끝까지 책임지는가.
2. **전문 자료:** 무엇을 검색하며 어떤 출처를 신뢰하는가.
3. **전용 도구:** 어떤 계산·조회·실험을 직접 수행할 수 있는가.
4. **업무 기억:** 어떤 실패·반례·사용자 선호·검증된 방법을 다음 일에 활용하는가.
5. **모델 정책:** 난도와 요구 정확도에 맞춰 어떤 모델을 쓰는가.
6. **전문 시험:** 자신의 설명과 산출물을 어떻게 검증하는가.
7. **개선 이력:** 도구·지식·프롬프트·모델의 변경이 무엇을 개선했는가.

각 직원의 직무 명세, 도구 schema, 참고 자료 목록, 전문성 시험, 모델·프롬프트 버전을 함께 관리한다.
직원은 자신의 전문 분야 안에서 다음 작업을 제안하고 동료에게 협력을 요청할 수 있다.

## 2. 핵심 직원

| 직원 | 책임지는 결과 | 주요 도구·기억 | 품질을 확인하는 방법 |
|---|---|---|---|
| **총괄 / Research Director** | 사용자의 의도를 명확한 프로젝트로 연결, 우선순위·담당자·의존성 조율 | 전체 프로젝트 현황, 사용자 결정·선호, 예산·일정 | 누락된 요청, 잘못된 위임, 지시 변경 반영, 완료율·사용자 수정량 |
| **금융지식·투자전략 / Financial Strategist** | 금융 전반의 설명, 시장 간 연결, 경제적 가설·반례, 연구팀 자문 | 금융 지식 라이브러리, 공시·공식 발표, 계산·시장 데이터 도구 | 금융 개념·계산·출처·시점·반례 시험, 불확실성 표현 |
| **퀀트연구 / Quant Researcher** | 아이디어를 관측 가능한 가설·검증 계획·연구 후보로 전환 | 선행 연구, 연구 시행 이력, 통계·실험 도구 | 가설 구별 가능성, 재현성, 누수·선택 편향, 개발구간 개선 근거 |
| **데이터 / Data Engineer** | 적절한 시점의 신뢰 가능한 입력, 데이터 결함 발견 | schema·출처·PIT 계약, 커버리지·조인·신선도 검사 | 의도적으로 심은 데이터 오류 발견, 조인·시점·결측 처리 |
| **연구개발 / Quant Engineer** | 실행 가능한 연구 코드와 재현 가능한 산출물 | 격리 checkout, 수치 도구, 테스트·프로파일러, 실행 receipt | 수치 검증, 경계 조건, 독립 재실행, 코드 변경과 결과 연결 |
| **독립검증 / Independent Validator** | 근거의 유효성과 한계를 독립적으로 확인 | 읽기 전용 결과·코드·데이터 명세, 통계 검증 도구 | 심은 누수·재시행 누락·비용 오류 발견, 오탐률, 증거 연결 |
| **포트폴리오·리스크 / Portfolio & Risk** | 전략의 계좌 기여·상관·집중·유동성·실행 조건 설명 | 포지션·위험·비용 모델, 계좌별 정책 | 제약 준수, 시나리오 계산, 숨은 공통 노출·한도 위반 발견 |
| **플랫폼운영 / Platform Operations** | 회사·데이터·계산 작업의 가용성과 복구 | 로그·메트릭·배포 상태·작업 대사·비용 도구 | 장애 탐지·복구 훈련, 중복 제출 방지, 복원 후 업무 연속성 |

검증 역할은 검토 대상의 구현을 겸하지 않는다. 조직을 넓힐 때 같은 직책을 가진 직원을 시장별로
추가할 수 있지만, 각 직원의 책임·업무함·맥락을 명시한다. 필요한 사람만 프로젝트에 참여한다.

## 3. 금융지식·투자전략 BOT의 상세 설계

### 3.1 맡길 일

이 직원은 사용자가 금융 전반을 깊게 논의할 수 있는 상대이자 각 연구팀의 경제적 자문역이다.
“설명해 줘”에는 이해할 수 있는 설명을, “아이디어를 검토해 줘”에는 작동 조건·반례·필요 데이터를,
“연구로 연결해 줘”에는 퀀트연구 직원과 협의한 검증 가능한 질문을 내놓는다.

| 지식 영역 | 갖추어야 할 역량 |
|---|---|
| 거시경제·통화·재정 | 성장·물가·정책·유동성의 연결, 상충하는 설명과 관측 구별 |
| 금리·채권·신용 | 현금흐름과 할인, 기간구조, 듀레이션·볼록성, 신용위험·스프레드 |
| 주식·기업금융·회계 | 기업가치, 이익·현금흐름·자본구조, 재무제표와 공시 해석 |
| FX·원자재·글로벌 자금흐름 | 통화·헤지·캐리·수급·자산 간 관계와 조건 |
| 파생상품·변동성 | 선물·옵션 구조, Greeks, 헤지, 비선형 손익과 시나리오 |
| 포트폴리오·행동재무 | 분산·공통 노출, 투자자 행동과 가설의 대안 설명 |
| 시장 미시구조·상품 구조 | 거래 방식, 주문·호가·유동성, ETF 등 상품의 구조적 특성 |
| 제도·세금·시장 규칙 | 관할·적용일·공식 출처를 확인하는 방법과 연구에 미치는 영향 |

위 표는 요구 역량이다. 해당 역량을 이미 보유했다고 주장하는 표가 아니다.

### 3.2 지식 기반

**기초 라이브러리:** 사용 권한을 확보한 교재·핸드북·연구 자료를 분야·개념·수식·가정·반례로 색인한다.
교재 전체를 프롬프트에 넣는 방식보다 관련 절·표·정의와 출처를 정확히 찾을 수 있게 만든다.

**최신 사실:** 중앙은행·통계기관·감독기관·거래소·기업 공시 등 원천 자료의 발행·수정 이력을 저장한다.
실시간성 요구에 맞춰 데이터 발행 이벤트 또는 예약 갱신을 사용한다. 최신 조회 여부를 답변에 표시한다.

**회사 경험:** 연구에서 얻은 증거, 기각 사유, 특정 데이터의 함정, 유효 범위를 지식에 연결한다.
반례는 성공 사례와 함께 검색되도록 한다. 다른 직원의 주장도 출처를 따라 확인할 수 있어야 한다.

**개념 연결:** `정책·요인 → 경제적 경로 → 자산·상품 → 관측 → 반례` 관계를 기록한다.
관계는 출처와 조건이 있는 주장이다. 초기에는 관계형 테이블로 관리하고 별도 그래프 DB는 필요할 때 검토한다.

### 3.3 계산과 사실 확인

금융 계산은 버전 있는 도구로 수행한다. 도구는 입력·단위·가정·출력과 검증 receipt를 반환한다.
계산 라이브러리의 선택과 수식 구현은 별도 수치 시험을 통과해야 한다.

- 현재가치·현금흐름·수익률 환산과 단위 변환.
- 채권 가격·듀레이션·볼록성과 금리 충격 시나리오.
- 옵션 가격·Greeks·만기 손익과 민감도.
- 재무제표 항목 연결·가치평가·가정별 민감도.
- 포트폴리오 노출과 자산 간 시나리오 비교.
- 데이터 조회와 원문·공시·문헌의 출처 확인.

필요 도구가 없으면 가정에 기반한 설명과 검증된 계산 결과를 구별한다.
거시 전망이나 인과 설명은 가설로 표시하고, 증거가 강하지 않은 내용을 확정적 사실로 기억하지 않는다.

### 3.4 기본 업무 산출물

복잡한 금융 안건은 다음의 짧은 메모를 기본으로 한다.

```text
질문 / 분석 기준 시점
확인된 사실과 출처
가능한 설명과 성립 조건
대안 설명·반례·모르는 점
계산 또는 관측으로 확인할 항목
관련 시장·상품·연구팀
다음 행동과 담당자
```

간단한 질문에 이 형식을 강요하지 않는다. 설명의 길이와 깊이는 사용자의 질문에 맞춘다.
전문가처럼 보이는 말투보다 정확한 계산·근거·조건부 추론을 평가한다.

### 3.5 주도적으로 할 일

- 중요 데이터·정책·공시 갱신이 기존 프로젝트의 가정을 바꾸는지 확인한다.
- 새 자료가 기존 지식을 수정하면 영향받는 직원과 프로젝트에 알려 준다.
- 서로 다른 연구팀이 같은 경제적 요인이나 데이터 문제를 다루는지 찾아 연결한다.
- 미해결 금융 질문과 검증할 만한 아이디어를 제안한다.
- 사용자의 요청이 없을 때도 승인된 관심 범위·일정·예산 안에서 후속 약속을 수행한다.

이벤트가 없고 남은 약속이 없으면 대기한다. 매 분 같은 시장 요약을 생성하지 않는다.

### 3.6 전문성 시험

초기 시험은 아래 여덟 묶음을 포함한다. 문제·정답·채점 근거를 직원의 검색 자료와 분리한다.

1. 기초 개념과 가정의 적용 범위.
2. 도구로 확인 가능한 수치 문제와 단위 오류.
3. 여러 자산·금융 분야를 연결하는 사례.
4. 서로 모순되는 자료의 출처·시점 판별.
5. 조건을 바꿨을 때 설명이 성립하는지 확인하는 반례.
6. 최신 규칙·공시를 실제 원문에서 확인하는 문제.
7. 틀린 전제·정보 부족에 대한 적절한 정정·보류.
8. 사용자에게 쉽게 설명하고 검증 가능한 연구 질문으로 연결하는 능력.

정확도·계산 허용오차·잘못된 확신·출처 적합성·지연·비용을 따로 기록한다.
수치 정답은 코드로, 출처·설명 품질은 근거를 가진 검토로 확인한다. LLM 자신의 점수만으로 통과시키지 않는다.
중대한 계산 오류·허위 출처를 평균 점수로 상쇄하지 않는다. 실제 합격 기준은 첫 배치 전에 고정한다.

모델 비교는 같은 도구·자료·문제에서 수행하고, 일반 모델 단독과 전문 지식·도구 구성을 함께 비교한다.
따라서 “금융 전문가 BOT으로 바꾸었다”가 실제로 개선을 만들었는지 확인할 수 있다.

## 4. 여러 시장·거래 주기의 연구팀

사용자가 확정한 범위는 국내 시장 일·월, 글로벌 시장 일·월, 가상자산 중빈도·고빈도·일 등이다.
세 연구팀을 두며, 팀마다 영속적인 연구 담당자·전문 기억·작업 큐를 갖는다.

```text
총괄
  ├─ 국내 시장 연구팀 — 일·월 전략
  ├─ 글로벌 시장 연구팀 — 일·월 전략
  └─ 가상자산 연구팀 — 중빈도·고빈도·일 전략

공유 전문 직원: 금융전략 / 데이터 / 개발 / 독립검증 / 리스크 / 운영
```

연구팀 계약에는 시장·자산·거래 주기·의사결정 시각·데이터 가용 시점·실행 장소·비용 모델을 둔다.
다른 팀의 결론을 가져올 때는 적용 범위가 같은지 다시 검토한다. 근거·코드는 공유하되 성과 기준이나
비용·체결 가정을 조용히 섞지 않는다. GPU 큐와 API 예산은 팀별 할당과 회사 전체 한도를 함께 적용한다.

가상자산 고빈도 영역에서 LLM은 연구·개발·사후 분석을 담당하고, 지연에 민감한 주문 경로는 별도 결정론적
실행기에 둔다. 일별 데이터·슬리피지 모델을 그대로 가져와 고빈도 적합성을 주장하지 않는다.
주문·호가 이벤트, 시계 정합성, 거래소별 실행 조건, 지연·큐·부분체결을 고려한 시뮬레이터를 별도로 설계한다.
정확한 중빈도·고빈도 시간 범위와 지연 목표는 전략 프로젝트에서 수치로 정한다.

| 연구팀 | 데이터·실험 설계의 초점 | 공유 기능과의 협업 |
|---|---|---|
| 국내 일·월 | 거래일·공시 가용 시점·기업행동·생존 편향·상품별 비용 | 데이터 직원의 기존 국내 레이크 계약을 검토해 활용 |
| 글로벌 일·월 | 여러 거래 일정·통화·시간대, 자료 발표·수정 이력 | 금융전략의 거시·자산 간 설명, 데이터 직원의 시점 정렬 |
| 가상자산 중빈도·일 | 거래소·상품·현물/파생 구별, 데이터 결손·거래비용·펀딩 | 리스크 직원의 거래소·포지션·집중 한도 검토 |
| 가상자산 고빈도 | 이벤트 데이터·수집 지연·주문 상태·체결 가정·연결 복구 | 개발·운영 직원의 실행기·시뮬레이터와 독립 검증 |

기존 국내 레이크와 개인 GPU가 모든 시장·주기의 데이터를 이미 제공한다는 가정은 하지 않는다.
시장별 첫 프로젝트에서 필요한 데이터·계산·실행 도구를 확인해 연결한다. 이 준비 때문에 다른 연구팀의
조사·설계·금융 논의를 정지시키지 않는다.

## 5. 직원의 개선과 조직의 학습

한 번의 업무가 끝나면 확인된 오류·쓸 만한 절차·새 증거를 후보 기억으로 남긴다.
근거 확인 후 검색 자료에 반영하고, 반복 오류는 시험 문제나 도구 검증 항목으로 추가한다.
새 버전은 이전에 보지 않은 평가 문제와 실제 업무의 제한된 적용에서 비교한 뒤 승격한다.

회사에서 경험을 쌓았다는 것은 우선 기억·도구·절차가 개선된다는 뜻이다. API 모델의 가중치가 대화만으로
자동 학습되는 것으로 설명하지 않는다. 파인튜닝은 이용 권한과 품질을 확인한 충분한 사례가 모였을 때
별도 비용·품질 실험으로 다룬다.

채용·분리는 병목이 확인된 직무에 한다. 시작부터 직원을 계속 늘리면 대화·조율 비용이 연구를 압도할 수 있다.
각 연구팀은 필요한 소수 직원으로 작업을 완수하고, 공통 전문가는 관련 안건에 참여한다.
