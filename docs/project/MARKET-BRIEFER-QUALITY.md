# Market Briefer 품질 개선 기록

후속 사용자 요청으로 담당 봇을 Analyst로 전환했다. 전문 분석 계약과 역량 점검은
[애널리스트 구현 기록](ANALYST-BRIEFING.md)이 현재 기준이다. 아래 v2 검사·예시는 당시 증거로 보존한다.

2026-09-22. 사용자의 최종 기준은 **정해진 시간에 첫 메시지를 읽으면 오늘의 시황과 중요한 변화를
이해할 수 있는 브리핑**이다. 수집 시장 데이터와 원문 보도를 함께 사용하고, 읽기 쉬운 편집과 검토를
구현했다. 자동 게시 기본값은 꺼져 있다. 이 문서는 [첫 구현 기록](MARKET-BRIEFER-VALIDATION.md)을 보완한다.

## 읽는 방식

본문은 핵심 최대 세 줄 → 주요 숫자 → 흐름을 만든 이야기 → 다음 확인할 것 순서다. 매일 항목 수를
채우지 않고 실제 중요한 내용을 고른다. 처음 읽는 사람이 이해하도록 짧은 문장과 구체적인 표현을 쓴다.
이슈를 고를 때 변화의 크기·영향 범위·지속성·다음 사건까지 남은 시간을 고려하고 직전 브리핑과 비교한다.

사실과 해석을 구분하되 다섯 가지 분석 소제목을 매번 반복하지 않는다. 결론에 영향을 주는 반대 근거는
본문에 담고, 세부 근거·정확한 관측 시각·추가 지표는 스레드에 둔다. 본문이 길어져도 다음 확인 사항을
위한 공간을 확보한다. 별도 관찰 항목이 없으면 핵심 이슈의 확인 조건을 사용한다. 저녁에는 아침에
제시한 관찰을 원래 문장 그대로 되짚는다.

[가독성 예시](evidence/briefing-quality-preview.md)는 실제 발송 코드로 렌더링한 합성 사례다.
본문 968자, 상세 한 건이며 숫자·방향·주요 원인·반대 근거·관찰 결과·다음 일정이 본문에 있다.
실제 시황, 실제 모델 출력, 실제 Slack 전달은 아니다. 재현 입력과 출력은
[JSON](evidence/briefing-quality-preview.json)에 보존했다.

## 시간과 데이터의 실제 제약

아침은 **07:30 KST**, 한국장 종합은 **20:00 KST**다. 실제 한국장 마감 + 50분보다 이르게 보내지 않는다.
한국판을 처음의 16:20에서 바꾼 이유는 수집 데이터를 확인한 결과다. KRX 데이터 계약의 당일 가용 조건은
18시 이후이며 실제 전일 객체의 게시 시각은 19:24였다. 19:20부터 5분 간격으로 갱신하고 19:40에 입력을
고정해 작성·검토 시간을 확보한다. 이 한 차례 관측이 매일의 갱신 시각을 보장하지 않는다.

[레이크 메타데이터 조사](evidence/briefing-quality-lake-survey.json),
[시리즈 조사](evidence/briefing-quality-series-survey.json),
[실제 소비자 실행](evidence/briefing-quality-data-probe.json)은 기존 인증을 사용한 실제 읽기 결과다.
연구 저장소·원천 수집기·레이크 데이터를 변경하지 않았다.

| 자료 | 실제 확인 | 브리핑에서 사용하는 방법 |
|---|---|---|
| KRX 지수 | 최신 거래일 09/21, 객체 게시 09/21 19:24 KST | 같은 판의 당일 자료가 있을 때만 코스피·코스닥 종가. 전 거래일·5/20거래일 비교는 코드 계산 |
| 미국 ETF | SPY·QQQ 등을 포함한 수정가격, 최신 09/17 | 날짜가 붙은 자산별 비교. S&P 500·나스닥 지수 종가로 대체하지 않음 |
| FRED | VIX·하이일드 스프레드는 있음. 요청한 S&P·나스닥·미 국채 2/10년 시리즈는 없음 | 존재하는 과거 관측만 날짜와 함께 제공. 현재 지수·금리는 확인된 보도 원문 필요 |
| ECOS | 기준금리·국고채 3년·달러/원 관측 | 발표 시각을 추정하지 않고 과거 배경자료로 구분 |
| 주식·투자자별 수급 대형 테이블 | 가격 약 323MB, 수급 약 646MB | 현재 소형 서버에서 전체 스캔하지 않음. 시장 폭·수급은 확인한 기사 근거가 있을 때만 포함 |

16:10 KST의 실제 소비자 검사는 작은 테이블 네 개를 모두 읽었고 접근 오류가 없었다. 배경 비교 16개를
만들었으나 오늘 저녁판의 당일 한국 지수는 아직 없으므로 현재 종가를 하나도 만들지 않았다.
한국 지수 2개와 ETF 9개의 시점 지연을 명시했다. 연결 성공을 당일 데이터 확보로 간주하지 않는다.

## 작성과 검토

고정 입력은 수집 숫자, 기존에 읽어 둔 등록 뉴스 원문, 부족한 부분의 추가 원문·제한된 검색, 공식 일정으로
구성한다. 동일 매체의 여러 피드를 독립 확인으로 세지 않는다. 다른 매체라도 같은 통신 기사를 옮긴 경우는
별도 검토에서 독립 근거로 인정하지 않도록 한다. 매체 수만으로 사실의 독립성이 증명되는 것은 아니다.

수집 데이터의 숫자는 모델이 바꾸지 못한다. 같은 지표·시점의 보도가 충돌하면 수집값을 유지하고 차이를
표시하거나, 수집값이 없으면 그 숫자를 제외한다. 오래된 가격을 오늘 값으로 쓰거나 충돌한 가격을 평균내지
않는다. 핵심 지수가 단일 매체 보도이면 본문에서 알린다.

작성과 별도 검토는 기존 구독 모델을 사용한다. 검토자는 숫자, 출처, 시점, 인과, 중요도/가독성, 반대 근거를
모두 명시적으로 평가한다. 비어 있는 검토를 통과로 간주하지 않고 `publish/reduce/withhold`로 구분한다.
일정·뉴스 접근 실패, 핵심 지수 결측, 시간 초과는 축약 사유로 남긴다. 예정 시각 + 10분까지 검토가 끝나지
않으면 검토하지 못한 초안 대신 확인 지연을 알리는 짧은 메시지를 확정한다.

숫자 읽기는 기존 lake-enabled worker의 별도 단기 프로세스에서 `qdata.api`만 호출한다. 읽기 전후 객체를
대조하고 행·객체 식별자·코드 버전을 보존한다. 객체당 4MiB·10만 행·12열, 총 45초와 출력 크기 제한이 있다.
DB·Slack·모델 비밀을 데이터 자식 프로세스에 전달하지 않고 모델 컨테이너에 레이크 자격 증명을 넣지 않는다.
모델 슬롯·서버·유료 API를 추가하지 않는다. PostgreSQL 확정 기록, Temporal 복구, 불명확한 외부 쓰기의
자동 재시도 금지는 첫 구현의 경계를 유지한다.

## 검증과 운영 인수

전체 회귀 **1,063개 통과·36개 건너뜀·실패 없음**, 최종 표시 문구 정리 후 관련 검사 **59개 통과**다.
린트·lock 검사·wheel 빌드도 통과했다. 최종 집계·변경 파일 해시는
[검증 영수증](evidence/briefing-quality-validation.json)에 기록한다.
전체 회귀는 [JUnit 기록](evidence/briefing-quality-tests.xml), 집중 검사는
[JUnit 기록](evidence/briefing-quality-targeted.xml)에 있다. 실제 로컬 PostgreSQL과 Temporal을 사용하며
실제 data worker의 소비자 연결과 workflow history replay도 검사했다. 시장 입력·모델·Slack 응답을
합성한 테스트와 실제 레이크 읽기 검사는 구분한다.

추가 검사는 고정 행의 등락 계산, 수집 숫자 변조 거절, 오래된 ETF의 대체 금지, 읽기 중 객체 변경,
마감 후 입력 제외, 대형 테이블 읽기 전 거절, 모델 프롬프트에서 원시 행 중복 제외, 출처 충돌, 같은 매체의
중복 확인 방지, 명시적 검토, 본문의 다음 확인 사항, 주말 조회, 데이터 고정 이후 변경 거절을 포함한다.

`briefing qualify`는 최근 완료된 한국 5거래일의 저장본을 재현하고 핵심 지수의 수집/복수출처 여부,
실제 Codex 작성·검토 영수증을 확인한다. 합성 자료·미확인 읽기 버전·결측·축약·충돌은 통과로 세지 않는다.
과거에 저장하지 않은 자료를 오늘 읽어 과거 수집으로 바꾸지 않는다. 검사는 읽기 전용이며 게시를 켜지 않는다.
빈 로컬 테스트 DB에서 실행한 [자격 검사 예시](evidence/briefing-quality-qualification.json)는 모든 발간 이력이
누락되어 통과하지 않는다. 실제 운영 이력이나 완료된 5거래일 관찰을 나타내는 보고서가 아니다.

현재 실제 Codex 실행, 전용 앱 연결 및 실제 Slack 전달, 운영 서버 배포, 5거래일 실시간 미리보기는
완료되지 않았다. 현재 접근 가능한 설정에는 회사 모델 runtime과 전용 Slack 앱·채널/소유자가 없다.
공개 BLS 일정의 접근 실패, 미국 지수 원자료 부재와 ETF 갱신 지연도 남아 있다. Linux 운영 환경의
장시간 부하와 두 모델 호출의 실제 편집 품질은 운영 미리보기에서 확인해야 한다. 로컬 자동 검사가
매일의 완전한 뉴스 커버리지나 사람의 내용 검토를 대체하지 않는다.

활성화 순서는 [운영 안내](../briefing.md)에 따른다. 별도 권한·앱을 확보한 뒤 게시를 끈 실제 미리보기와
5거래일 관찰, 실제 Slack 인수를 거쳐 게시 설정을 변경한다. 코드만 설치해 이 관찰을 통과한 것으로
간주하지 않는다.
