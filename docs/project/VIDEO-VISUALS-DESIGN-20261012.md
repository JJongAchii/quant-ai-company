## 원칙

1. 정확성이 먼저다. 그림은 이해를 돕는 장식이고 사실을 주장하지 않는다. 숫자·사실 검사는 지금 그대로 둔다.
2. 형식(순서·코너)은 고정한다. 매일 바뀌는 것은 그림, 도입부 문장, 썸네일이다.
3. 사실적 표현의 경계
   - 일반 사물·장소(반도체, 유조선, 항구, 데이터센터 등): 사실적인 3D 편집 일러스트 허용(시험 샘플 수준).
   - 실존 인물, 특정 사건(사고·군사·시위), 실존 건물·로고를 실제처럼 합성하는 것은 계속 금지. 시청자가 실제 사진으로
     오해할 수 있고, 유튜브의 "변경·합성 콘텐츠" 표시 대상이 된다.
   - 특정 기업·장소를 보여줄 때는 라이선스가 확인된 실제 사진만 쓴다.
4. 항상 만든다. 그림 생성·사진 검색이 실패하면 기존 라이브러리 그림으로 대체하고 제작을 멈추지 않는다.

## 설계

### 1) 장면별 그림 지시 (Claude, 대본 단계)

대본(`video_episode_v1`)에 `visuals`를 더한다. 이미지 자리가 있는 장면(photo·headline·bars 카드)과 도입부·썸네일
대표 이미지 1장에 대해 Claude가 다음 중 하나를 고른다.

- `illustration`: 그림 지시문(주제, 구도, 꼭 피할 것). 스타일 문구는 서버가 고정으로 덧붙인다.
- `photo`: 위키미디어 검색어와 반드시 보여야 할 대상.
- `library`: 기존 라이브러리 ID(지금 방식).

규칙: 회차당 생성 3~5장(대표 1 + 핵심 장면 2~4), 같은 그림을 7일 안에 다시 쓰지 않는다.

### 2) 그림 생성 (Codex 구독, 서버)

- Codex 실행기에 이미지 전용 실행 경로를 둔다. 이미지 생성만 켜고 셸·파일 수정·웹·MCP는 끈다. 생성된 파일은
  실행기가 `CODEX_HOME/generated_images/`에서 직접 회수하고 해시를 영수증에 남긴다. 같은 요청 ID로 두 번 생성하지 않는다.
- 브리핑 Codex 호출과 겹치지 않는다. 영상 작업은 브리핑 발송 뒤에 시작하고, 실행기의 한 번에 하나 규칙을 따른다.
- 음성 합성과 동시에 진행한다(1장 약 2분, 회차당 약 6~10분). 렌더 입력에 회차 전용 이미지를 함께 올린다
  (Fargate 렌더 입력 묶음에 추가).
- 구독 이미지 한도에 걸리거나 실패하면 그 자리는 라이브러리 그림으로 대체하고 지적으로 남긴다.

### 3) 실제 사진 (위키미디어 공용)

1. 검색 → 라이선스 필터(CC0·퍼블릭 도메인·CC BY만, 1600px 이상, 제한 표시 없음).
2. 후보 3~5장을 Claude가 이미지로 직접 보고 판정: 장면 내용과 맞는가, 식별 가능한 사람이 있는가, 사고·군사·행사
   사진인가, 화면에 쓰기 좋은 구도인가.
3. 통과한 사진만 쓰고 "자료사진 · 저작자 · 라이선스" 칩과 설명란 출처를 자동으로 넣는다(기존 기능).
4. 통과한 사진은 라이브러리에 태그와 함께 쌓아 재사용한다.

### 4) 썸네일·도입부

- 썸네일: 대표 이미지(사진 또는 생성 그림)를 배경으로, 그날 핵심 숫자 하나와 짧은 질문(4~6단어)을 크게 얹는다.
- 도입부(cold_open, 첫 8~10초): 같은 대표 이미지를 배경으로 그날 핵심 숫자 카드 3개를 띄운다.
- Claude 화면 검수가 썸네일과 도입부 프레임도 본다(이미 검수 대상). 이미지가 내용과 안 맞으면 그 장면 그림만 다시 만든다.

### 5) 검수와 수정 루프

지금의 화면 검수(`video_visual_review_v1`)가 생성 이미지가 들어간 프레임을 보고 지적한다. 화면 수정(`video_screen_fix_v1`)에
"그림 교체" 항목을 더해 그 장면의 그림 지시를 고쳐 다시 생성한다(장면당 1회). 그래도 안 되면 라이브러리 그림으로 바꾸고
전달한다.
