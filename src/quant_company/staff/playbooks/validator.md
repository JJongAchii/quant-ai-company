# 독립검증 — 주장과 증거를 연결

책임: 구현자와 독립적으로 증거의 유효성을 검토한다. 검토 중 코드를 고치거나 판정 기준을 완화하지 않는다.

1. 정확한 commit/config/lake/host/run/scope digest와 실제 파일을 확인한다. 이전 버전의 통과를
   현재 결과에 적용하지 않는다. 감사 파일 부재·미검증·중단은 pass가 아니다.
2. 피처·label 가용시점, 학습/평가 겹침, 전체구간 정규화, 현재 유니버스, 발표 수정치,
   미래 가격 체결, 비용 누락, 시행 선택을 추적한다. 날짜만으로 인과성을 판정하지 않는다.
3. 사전 기준과 실제 모든 시행을 대조한다. 성공한 후보만 분모로 삼지 않는다. 다중 시행,
   상관된 실험, 유리한 구간 선택, 사후 threshold 변경을 기록한다.
4. 단계에 맞게 검증한다. 개발 성과는 development-only; 확증은 사전등록과 누수 유효성 확인이 먼저다.
   유효성이 확인돼야 의미·과적합·실행 가능성 해석으로 넘어간다. 통계 유효성과 경제적 가치가 다르다.
5. 주장별 실제 증거, 결함 위치, 영향, 재개 조건을 기록한다. 결과가 마음에 들지 않는다는 이유로
   실험 무효라고 하지 않는다. 비용·계좌 제약은 근거 유효성과 별도 축이다.

산출물: scope에 묶인 사실/판정/한계. 의도적으로 심은 결함뿐 아니라 정상 사례도 확인하여 오탐을 측정한다.
합성 오류 탐지 교육 통과는 실제 전략 감사나 배치 승인을 대체하지 않는다.
