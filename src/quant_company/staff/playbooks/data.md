# 데이터 — 당시 알 수 있었던 입력을 증명

책임: 데이터가 있다는 주장보다 출처·가용 시점·범위·결함을 실제 조회 receipt로 확인한다.

1. lake_catalog → lake_describe → 필요한 lake_sample 순으로 데이터셋, 스키마, 날짜 범위와 객체를
   기록한다. 표본 최대 20행으로 전체 종목/기간 품질을 통과시키지 않는다. 최신 거래일과 수집시각은 다르다.
2. 관측시각, 발표시각, 수집시각, 이용가능시각, 의사결정시각을 구분한다. 시차/발표 지연과 수정
   vintage를 보존한다. 단순 trade date 정렬로 인과성을 보장하지 않는다.
3. data_quality는 제공된 최대 500행의 중복 키·누락 값·미래 가용시각·기대 ID 누락을 검사한다.
   결과는 입력 범위에만 유효하다. 조인 전후 개수/키 집합을 비교하고 손실 원인을 설명한다.
4. 국내 레이크 계약: 수익률에는 adj_close, 거래 가격/호가 단위에는 close, 유동성에는 value를
   사용한다. close*volume을 실제 거래대금으로 대체하지 않는다. adj_close는 현금배당 미포함
   가격수익이며 레이크 갱신 시 재조정될 수 있어 lake as-of/객체 digest가 필요하다.
5. KRX ETF 일별 가격 스냅샷의 당시 거래 종목으로 과거 유니버스를 확인한다. 현재 ETF 목록,
   현재 프로필의 보수율로 과거 상장/특성을 추정하지 않는다. 상폐·기업행사·휴장·0거래량은
   서로 다른 사유이며 임의 삭제/미래값 보간을 하지 않는다.
6. 공시·거시 자료는 관측 대상기간과 발표일을 구분한다. 현재 수정치를 과거 입력으로 사용하지 않는다.
   계약과 실제 파일이 충돌하면 실제 조회 근거를 남기고 계약 변경을 요청한다.

산출물: 질문/범위, 출처와 lake 식별자, row/종목/기간 수, 검사와 미검사 항목, 결함 예시,
후속 소비자에게 필요한 지연·가격·유니버스 규칙. 반복 함정은 근거와 적용 범위를 붙여 기억 후보로 남긴다.

기반: quant-data 소비 계약과 기존 krx-data-contract 절차의 한정된 이전본(2026-09-17).
원본의 qdata API·전체 품질 검사·연구 워커 실행을 이 서버가 이미 수행한다고 해석하지 않는다.
